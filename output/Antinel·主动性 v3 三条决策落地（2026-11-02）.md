## 二、为什么（每一条的依据）

### ① gap：它报的是作息，不是异常

实测对比（同一份真账本，174,305 条记录）：

| 阈值 | 报几条 | 内容 |
|---|---|---|
| 30 分钟（旧默认） | **5 条** | `00:50–01:50`、`01:52–02:53`、`02:56–03:57`、`03:58–04:59`、`05:04–06:10` |
| 90 分钟（v2 默认） | **0 条** | — |

那 5 条是**这个人在睡觉**。90 分钟不是「调对了」，是刚好把睡眠挡住——哪天熬夜到凌晨，
同一段就会重新变成「断层」。**阈值在拟合作息，不是判据。**

而「某个钩子挂了」这件事，`absent` 用更准的量具抓（type 的**日级出现频次**，不是小时级间隙）。
所以：**gap 报作息，absent 报故障。** 留着 gap 只是让报告多一个会说谎的量具。

同时，12 条金标准里 gap 占 3 条，**3/3 全是噪声**。

### ② 静默：一个数管八种线索，而这八种方向相反

`SILENT_AFTER = 3` 的问题不是「3 这个数拍得对不对」，是**它管的东西不该由同一个数管**：

| 类型 | 说的是 | 该怎么说 | 旧行为 |
|---|---|---|---|
| `absent`／`anchor`／`verdict`／`baseline` | 「有个东西坏了」 | **天天说，直到好了** | 说 3 次就闭嘴 ❌ |
| `rule_pair`／`first_seen`／`repeat`／`gap` | 「有件事发生了」 | **说过一次就够，除非内容变了** | 说 3 次才闭嘴（前两次是噪音） |

「某个钩子挂了」说三遍就沉默，等于替你决定「你已经知道了」——而账本**没有**「人真的读过了」的信号，
这个假设没有依据。反过来，「某个组合首次出现」说三遍也不增加信息，只增加噪音。

这是铁律 35（计数单位要分开）的正向应用。

**未知 kind 按故障类处理**（宁可多说，不可漏说）。这是有代价的选择：新检测器如果没登记，
会天天吵。所以它在 `is_fault()` 里是显式分支，不是默认值。

### ③ `--ack`：旧语义不是「别再说了」，是「把眼睛闭上」

旧代码（`clue_ledger.py` 的 `annotate`）：

```python
if e.get("acked_day"):
    out.append((c, k, ACKED, e))   # 永久静默，不看内容
    continue
```

于是：你对「AN-016 → AN-010 这个组合首次出现」按一次 `--ack`，**它以后变成每天 40 次，你也永远不会再听到**。

新语义：记下按下那一刻的**内容指纹**，变了就重开并标明「你确认过的那件事变了」。
这才是人按那个按钮时真正想说的。

## 三、指纹怎么算，以及为什么这样算

```python
def clue_fingerprint(clue) -> str:
    items = sorted(clue.items)          # 集合
    body = "|".join(items) + "\x1f" + _mag_bucket(clue.magnitude)
    return sha1(body)[:12]
```

三个刻意的排除：

| 排除 | 理由 |
|---|---|
| **不含 `subject`** | v2 刚把 `AN-010` 改成 `写到项目目录之外（AN-010）`。含 subject 的话，那次**纯文案改动**会让所有已确认的线索同时重开——用户看到「它突然把旧事全翻出来」，真实原因是我们改了措辞。这是铁律 27（量具自指）的形状。 |
| **不含 `day`** | 事件类的 day 不是身份（`clue_key` 的注释已说明）。 |
| **不含精确规模，只含量级桶** | 用精确值的话，「4 次 → 5 次」也算变了，同一条线索天天重开——指纹退化成「每天都是新的」，和没有一样。 |

量级桶的边界是**数量级**，不是调参：`1 / 2-3 / 4-10 / 11-30 / 31-100 / 100+`。
本文件已经因为「拍出来的数」吃过两次亏（`SILENT_AFTER`／`COOL_DAYS`），不拍第三个。

`magnitude` 由**检测器声明**，不由下游从 subject 里抠数字——抠数字等于把「文案」当「数据」。

## 四、撞出一个新缺陷：同一份报告对同一个 0 给出两种相反的归因

**这是本轮最意外的收获，而且它一直躺在那里。**

`onepager.py` 里有两处解释「0 条」的文案：

| 触发条件 | 文案 | 说的是 |
|---|---|---|
| `n_need == 0 and bundle.evidence` | 「这一层的判据还没接上」 | 判据缺失 |
| 没有证据（走 `else` 分支） | 「两条检查都跑成了，都没有发现变化。这是「查了，没有」，不是「没查」」 | 一切正常 |

**两句话不可能同时为真。** C 线只读账本、不读规则库 ⇒「挡下／提醒」两档**无论有没有证据**都产不出来。
所以「0 条」在任何情况下都不是「查了没有危险」。

怎么发现的：e2e 的 `e1` 臂原来靠 gap 产出 5 条证据，走的是第一条分支；
我把夹具改成「真正 0 条证据」之后它立刻红——**它守的那个字符串只在一条分支之外出现**。

修法：两句归因**共用一个来源**（`E.need_zero_note()`），并且都带限定语：

> 账本自洽检查跑成了，没有发现变化（这是「查了，没有」，不是「没查」）。
> 但这只是「账本自洽」这一层：「需要你看一眼」为 0，是因为本报告只读账本、不读规则库……

e2e 的 `e1` 臂同时加了一条反向断言：**不许出现「都没有发现变化」**。
