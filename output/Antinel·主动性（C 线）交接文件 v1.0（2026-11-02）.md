## 1. 边界：C 线是什么，不是什么

### 1.1 主动性的定义（三要件，缺一不算）

一条输出要被称为「主动」，必须同时满足：

1. **没有显式请求** —— 用户没问，系统自己发起；
2. **指向未被注意的东西** —— 不是把用户已知的事再说一遍；
3. **系统自己发起** —— 不是用户点了某个按钮之后的响应。

**不等于**：自主性（能自己改目标）／响应快（延迟低）／预判性（猜用户想要什么）。
这三样常被混进来，混进来之后「主动性」就变成了一个什么都能装的筐。

出处：`output/Antinel·主动性：定义与维度完备性（务虚稿 v1.1，2026-11-01）.md`（941 行，含 3 张图）。

### 1.2 唯一正当领域

把「系统知不知道」× 「用户知不知道」做成 2×2，**只有一格**值得主动推送：

```
                     用户知道自己需要   用户不知道自己需要
系统知道        │  ① 响应即可      │  ② ★ 主动性唯一正当领域
系统不知道      │  ③ 一起去查      │  ④ 都不知道，别装懂
```

- ① 是响应式产品的地盘，抢它没有增量；
- ③ 是探索，可以问，但不许「主动宣布」；
- ④ 主动说就是编；
- **②** 才是「用户不知道自己需要、而系统已经知道」—— 唯一该主动开口的地方。

### 1.3 主业是推送，不是报告

这是最容易做歪的地方。C 线**交付物是一页纸报告**，但**主业是推送决策**：

- 报告是「用户主动来看」时看到的东西（响应式出口）；
- 主动性是「系统决定要不要打扰用户」时做的决定（推送出口）。

两者的判据完全不同：报告要求**完整**，推送要求**克制**。
`clue_ledger.py` 存在的理由就是后者：同一条线索连说 3 次 → 静默 7 天 → 期满回来说 1 次。
**静默是功能，不是缺陷。**

> ★ 产品里的「巡检」是**用户触发的体检**，不是主动性。别把两者混为一谈。

### 1.4 五条硬边界（违反即返工）

| # | 边界 | 为什么 |
|---|---|---|

### 2.5 代码指纹

- 源文件清单的唯一真源是 `codeid.py` 的 `SOURCES`，现在是 **13 个**（本轮补了 `verdict_leg.py`、`clue_ledger.py`）；

### 3.2 三个最容易做错的地方

**① `HERE` 拼路径前先看一眼它到底是什么。**
`output/lineC/*.py` 里 `HERE` 已经是 `lineC`。写成 `os.path.join(HERE, "lineC")` 会多一层，于是「源文件全部缺失」——**而它看起来像「文件真的没了」**。这个错在 `redteam.py`／`selfproof.py`／`codeid.py` 各犯过一次。三个文件现在都用同一句兜底：

```python
LINE_C = HERE if os.path.basename(HERE) == "lineC" else os.path.join(HERE, "lineC")
```

**② `evidence.collect()` 走子进程，不 import。**
`auditor`／`watchman` 已过 30 臂负控，改它们（哪怕只抽一个函数）都要全量重跑。更重要的是：**子进程天然给出「不可判」与「零」的分界**——它们崩了，`undecidable` 里会记一条，而不是安静地返回空列表。

**③ 强度档的中文词只有一处声明。**
`evidence.WORD` 从产品侧 `inbox_model.py` 的 `STATE_LABEL` **派生**（AST 解析，不 import、不 exec）。三档 `log_only`／`no_response`／`checked` 产品侧没有对应态，是 C 线自有的，**必须显式登记且不许说成产品态**。

## 5. 三层分母：43 / 29 / 17（最重要的口径）

### 5.1 三个数各是什么

| 数 | 名字 | 怎么数的 | 能回答什么 |
|---|---|---|---|
| **43** | 裁决记录（按 decision 值） | `decision ∈ {block, deny}` 的行数 | 账本里有多少条「动作没执行」的记录 |
| **29** | 落桶记录 | 43 减去 14 条产品侧判为**非事件**的 | 有多少条真的进了报告的分档 |
| **17** | **真实动作数** | 按（会话＋时刻＋工具＋命令前 300 字）去重 | 用户实际被挡了多少次 |

**43 → 29 的 14 条差额**：`pre_tool_use_summary` 这类记录，产品侧 `notify_policy.NON_EVENT_TYPES` 判为「结构上不是事件」（与逐条 `pre_tool_use` 覆盖同一批调用，同时通知会提醒两次）。**这是「不适用」，不是「静音」**——两者必须分开记。

**29 → 17 的 12 条差额**：**一次工具调用被两个钩子各记一遍**。实测同会话、同秒、同工具、同命令，`pre_tool_use` 记 `block`、`command_deletion_permission` 记 `deny`；而产品侧 `hooks/notify_policy.py:92-102` 明写：

```python
"deny": GATE,   # 与 block 同义（历史记录里仍会出现，故保留键）
```

⇒ 它们是同一次动作。**29 条记录 / 17 次动作，两个数都真，都不能丢**（铁律 35：拦截时归并、记账时分开；铁律 39：原始条数一条不丢）。

### 5.2 为什么不能合成一个数

- 合成「29」⇒ 一次动作说成两次，**把「挡住了」说成「挡住了两次」**（对外强度虚高，铁律 21）；
- 合成「17」⇒ 记账口径丢失，无法逐行回指到具体哪条记录；
- 合成「43」⇒ 把「不适用」算成「有事件」（F40：一个数承担两个分母）。

所以 `Cluster` 同时带 `n_records` 与 `n_actions`，`claim()` 两个都印且**各自带单位**：

```
AN-009 挡下 9 次（账本 18 条记录，同一次动作被多个钩子各记一遍）（严重度 critical）
```

记录数等于动作数时**不许**画蛇添足提「账本 N 条」（自检 4b 守着这一条）。

### 5.3 17 不能主张什么

- 不能主张「17 次拦截」——「拦截」在 `glossary.RETIRED_WORDS` 里已判死（与「出事／失守／注意」同批），用错名即对外强度虚高；
- 不能主张「17 个不同的问题」——6 簇才是问题数，且**簇数不守恒**（换一种聚合键，簇数会变；条数守恒）；
- 不能主张「这些都是真发现」——账本里混着本项目自己造的夹具（`evil.example.com` 就在 2026-10-31 的「首次出现域名」里，与百度、几个政府网站并列）。账本没有「这是夹具」字段，**无法区分**。

## 6. 四种 0 与 `need_zero_note` 机制

### 6.1 「需要你看一眼 0 条」至少有四种来源

| # | 来源 | 含义 | 该怎么说 |
|---|---|---|---|
| ① | **查了，没有** | 有腿读了，读到的就是 0 | 结论。可以说 |
| ② | **没跑成** | 腿崩了／超时 | 盲区。不许说成「没有」 |
| ③ | **没腿读** | 这一档今天压根没有腿去读 | 结构性缺口。**最容易说成「今天没有」** |
| ④ | **读了没装进来** | 腿读到了、但契约挡下了 | 要修的 bug |

页面上只有一个「0」。所以归因**必须是机制**，不能交给渲染层自由发挥（三份报告会说三种话，且都会说成最好听的那种）。

### 6.2 机制怎么落地

```python
# evidence.py
NEED_TIERS = (K_HELD, K_ALERT, K_NO_RESPONSE)   # 「需要你看一眼」＝这三档之和，唯一声明处

@dataclass
class LegReport:
    name: str
    ran: bool                      # False ⇒ 它没读，不是「读了没有」
    produces: Tuple[str, ...]      # 这条腿**自己声明**能产出哪几档
    denominator: str = ""          # 报数不带分母等于没报
    note: str = ""

def need_zero_note(bundle) -> str: ...   # 渲染层只许调这里
```

**`produces` 必须由腿自己声明，不许消费方推断。** 第一版想「这条腿当然能产 held 和 no_response」，而它实际只读 `block/deny` ⇒ **推断出来的答案是「三档都有腿」，真答案是「只有两档有腿」**。差别不在数字，在于页面上那个 0 会被读成「今天没有提醒」。

`verdict_leg.py` 的声明：

```python
PRODUCES = (K_HELD, K_NO_RESPONSE)   # `alert` 不在里面，是事实不是遗漏
```

### 6.3 三种失败模式（都已写成负控）

1. **写死的归因会过期**：旧版 `need_zero_note` 写死一句「挡下/提醒结构上产不出来」。第三只腿接上后，那句话变成**过期 24 小时的自我安慰**——它还在说「产不出来」，而实际已经产出了。
   ⇒ 要验的不是「有没有这句话」，而是「**换一种腿状态，话会不会跟着变**」（自检 ⑧ 的负控）。
2. **无脑说「读到 0 条」会撒谎**：函数在别处被调用时，bundle 里可能有非零的档（实跑时「挡下」有 9 条）。⇒ 必须逐档判 `not by.get(t)`。
3. **不给 bundle 时不许退回旧文案**：说不出归因就说「说不出」，**不许**给一个听起来像结论的句子。

## 9. 踩过的坑 → 铁律对照（这一节最值钱）

### 9.1 一次动作被两个钩子各记一遍（本轮最重）

**现象**：一页纸上出现两条「AN-009 挡下 9 次」，行号只差 2。看起来像两件事。

**根因**：聚合键里放了 `decision`。而 `block` 与 `deny` 是**同义**（产品侧回退表明写），同一次调用被两个钩子各记一遍 ⇒ 被拆成两簇。

**修法**：聚合键去掉 `decision`；新增 `n_actions` 按（会话+时刻+工具+命令前 300 字）去重；`claim()` 同时印「次」与「条」。

**教训**：**「一次动作说成两次」比「漏掉一次」更难发现**，因为两个数都真、页面也自洽。只有把「记录」与「动作」当两个口径分开记，差额才会浮出来。

### 9.2 命令字段被两个钩子截断成不同长度

**现象**：按 `command` 全长去重得 20 次动作，按前 300 字得 17 次。

**根因**：两个钩子对 `input.command` 的截断长度不同（实测一条 300 字、一条 500 字，**短的是长的前缀**）⇒ 同一次动作的两条记录字符串不等。

**修法**：取 `command[:300]`。实测 0/120/200/300 字都给 17，键稳定。

**教训**：**去重键要选在「两个写者一定一致」的截断点上**。全串看似更精确，实际更脆。

### 9.3 分母被污染不会报错

**现象**：`glob("*.jsonl")` 把 `lock_events.jsonl`（5781 条锁事件）算成日文件 ⇒ 印出「日文件 36 个（2026-09-25 .. lock_event）」。

**修法**：改用与 `watchman.py:48`／`auditor.py:63` 同一条正则 `^(\d{4}-\d{2}-\d{2})\.jsonl$`。真实 35 个。

**教训**：**分母错的时候页面不会红，它只会把 35 说成 36，并把 `lock_event` 当成一个日期印出来。** 铁律 22：分布太整齐先怀疑量具。

### 9.4 默认值不许替人决定口径

**现象**：`--day` 留空 ⇒ 扫全期 2033 条 → 120 簇，而一页纸首屏写「这次」。

**修法**：默认＝`latest_day()`；全期须显式 `--all`。

**教训**：这是 **F40 的第三种形态**——不是两个分母印在一起，而是**一个词的指代范围被悄悄放大**，读者无从对照。「这次」被默认值换成了「历来」，而页面上没有任何一处会显示这件事。

### 9.5 `_stable_id()` 只收 3 个位置参数，第一版传了 4 个

**现象**：第三只腿一接上就 `TypeError`。

**修法**：改为 `_stable_id("VDT", "%s|%s" % (...), ())`，并顺手把身份从 `claim`（含会变的 `n_records`）改为**簇的聚合键**。

**教训**：**崩溃级 bug 反而是幸运的**——它当场报错。真正危险的是那些「看起来稳定」的：例如读一个**已经不存在**的字段，恒取空串，永远不报错，只在有人把键加回来时静默改变（本轮修的就是这个）。

### 9.6 过期的断言比没有断言更糟

**现象**：`need_zero_note` 改版后，`onepager` 自检还在断言旧文案「结构上产不出来」⇒ 红。

**修法**：断言改成**性质**（这个 0 必须落进四种归因之一），并加一条负控（没有腿的 Bundle 不许说「查了，没有」）。

**教训**：自检里写死文案，等于把「文案已更新」判成红，逼人把旧话改回去。**断言要断言性质，不要断言字面。**

### 9.7 新模块默认不受保护（本轮发现的结构性缺口）

- `verdict_leg.py` 落地后**不在** `selfproof.CHECKS` 里 ⇒ 闸门仍然全绿，而它自检红了没人知道；
- `verdict_leg.py`／`clue_ledger.py` **不在** `codeid.SOURCES` 里 ⇒ 换了分档规则，组指纹不变，归档报告对不上账。

**教训**：清单式真源的固有风险是**漏登记不报错**。只能靠纪律：**新增模块必须同时登记三处**——`CHECKS`（闸门）、`SOURCES`（指纹）、`AGENTS.md` 的共享文件表（如适用）。

### 9.8 判据写错方向，会长期保护一个缺陷（本轮最该记的一课）

**现象**：`_p_evid_negctl.py` 的 `nc16` 臂红：「产出了 5 条『挡下』」。

**原文**：这条臂断言「真账本跑出来的证据里，**一条『挡下』都不许有**」，理由是「C 线读的是账本、不是规则 ⇒ 它没有任何资格产出挡下」。

**问题**：那句话在**只有两条腿**时是真的。但它被写成了一条**行为判据**，于是第三只腿接上、真的从账本里读出 `rule_id` 之后，这条臂立刻报红——**而红的方向是「不许有结论」**。

**修法**：改成断言「每条『挡下』必须带规则号 + 出处必须是 `verdict_leg/<规则号>` + 反向对照：无规则号的簇必须落『已发现无法处置』」。

**教训**：它守的其实不是「没有挡下」，而是「**挡下必须有规则号**」——那才是 `Evidence.__post_init__` 的硬约束。把纪律写成「不许产出」，等于替那条腿的自我阉割背书，**而且写得很有道理**。
> ★ 所以：看到一条红，先问「它守的是纪律，还是守的是昨天的现状」。守现状的判据会随时间变成进步的阻力。

### 9.9 两条路径做同一件事，忘掉的那条不会报错

**现象**：端到端负控 `e7` 红——折叠样本里出现 `**`。

**根因**：`auditor`／`watchman` 的盲区都走 `blind_of()`，那里做了 `plain()`（去 Markdown 星号）；第三只腿的盲区是**现成的字符串列表**，`collect()` 里直接 `+=` 就把它跳过了 ⇒ `verdict_leg` 里那些「本腿**一条不读**」的星号原样进了 HTML。

**修法**：①在 `collect()` 对第三只腿的 blind／undecidable 补 `plain()`（防御）；②按 `plain()` 注释的原话——**让上游散文别写 `**`**——把 `verdict_leg` 里的星号删掉（治本）。

**教训**：这是 R4（同一件事一处实现）的典型失守。**忘了的那条不会报错，它只会少洗一次**；而「少洗一次」在页面上是 `本腿**一条不读**` 这种小瑕疵，很容易被当成排版问题放过。

### 9.9b 整句盲区被印成两遍

**现象**：报告「这份报告看不见什么」一节里，同一句话在一行内出现两次。

**根因**：渲染层写 `title, _, rest = b.partition(" —— ")` 再 `_e(rest or title)`。审计器／巡检的盲区都是「标题 —— 详情」格式，所以 `rest` 非空；第三只腿的盲区是**整句话**，`rest` 为空 ⇒ 回退成 `title`，于是同一句话印两遍。

**修法**：无分隔符时用单列整行（`.row .full{flex:1 1 auto}`），并加自检：整句盲区必须只出现一次。

**教训**：这是「零与不可判同貌」的**排版版**——**重复让「一条」看起来像「两条」，而多出来的那条谁也核不了**（它不存在）。凡是从「一种输入形态」扩到「两种输入形态」，都要回头看渲染层有没有假设过形态。

### 9.10 量具 vs 被测对象（铁律 22 的新实例）

v4 文档曾把 C-2 超时归因为「账本变重」——被实测否掉：账本 177k→184k 条仅 +4%，而同一份账本 `账本端到端 5 臂` 从 143s 涨到 464s（差 3.2 倍）。真因是**并发占用机器**。

**教训**：看到耗时上涨先怀疑量具与环境，不是被测对象。且**并列两条不构成矛盾检查，只有归因段会被单独引用 ⇒ 归因段错了必须改**。

### 12.3 一句话留给下一位

> C 线最贵的错不是算错数，是**让两个不同的东西长得一样**：
