## 6 三个最严重的缺口（必须先修）

### 6.1 `eid` 不稳定 —— 这是 bug，不是设计取舍

```python
eid=f"AUD-{i + 1:02d}"   # i 是数组下标
```

后果：昨天报告 `AUD-03` 是「A3 日清单」，今天若 A1/A2 都 PASS 不进证据，`AUD-03` 就变成别的。
**读者拿两份报告对照，会以为「同一件事变了」，其实是编号换了对象。**
这正是本仓最忌的「同值不同义」——同一个字符串在两个时刻指两个东西。

**修法**：`eid = sha256(claim + 首个 cite 的 (day,lineno))[:8]`，加人类可读前缀（`AUD-`／`WCH-`）。

### 6.2 `_CLUE_META` 与 watchman 的 kind 列表两处实现

`watchman.py` 里 8 处 `kind="xxx"`，`evidence.py` 里 `_CLUE_META` 又列了一遍。
加第 9 个 kind 时，`_CLUE_META` 不会自动跟上 ⇒ 新线索会落到「未知类型」分支，盲区声明缺失。
**这是 R4 与九维一的直接违反。**

**修法**：从 watchman 的 JSON 输出里读 `coverage` 的键集合，与 `_CLUE_META` 求差集，差集非空 ⇒ 报红。

### 6.3 `read_at` 是时变产物

品质第 2 条原样复现：报告里写「读数时刻 2026-11-01 02:24」，任何判据逐字比对它，跨分钟就伪红。

**修法**：判据侧经 `note_text()` 归一（只比到分钟，或只比「是不是今天」）；并在报告里显式说「本时刻是读取那一刻，不是生成那一刻」。
