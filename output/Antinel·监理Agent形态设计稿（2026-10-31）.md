# Antinel · 监理 Agent 形态设计稿

**日期**：2026-10-31
**性质**：设计推演。**不触碰产品代码**，不改 `rules/default.json`。
**起因**：创始人两问——①监理本身能不能做成 Agent，有哪些形式、各适配什么场景；②做成 Agent 是否必须内置 LLM，现阶段要不要做。

---

## §0 结论先行

| # | 问题 | 答 |
|---|---|---|
| 1 | 监理能不能做成 Agent？ | **能，但只能做一半。** 裁量只能落在「去哪看」（观测侧），不能落在「算不算数」（判定侧） |
| 2 | 必须内置 LLM 吗？ | **不必。** Agent 的判据是「目标驱动的观察—决策—行动循环」，不是「有没有模型」。决策器有五档，前两档零模型 |
| 3 | 现阶段要做吗？ | **做 A，不做 B。** A＝主动去看（零模型，体验跃迁）；B＝看得懂（要模型，三条硬约束全撞） |
| 4 | LLM 现在该用在哪？ | **研发侧，不是产品侧。** 用大模型提规则候选、进 CI 人审；不用大模型判规则 |

---

## §1 裁量边界：一句话说清

> **Agent 决定看什么，不决定算不算数。**

**为什么判定侧不能让**：判定一旦交给模型，账本就变成「模型说的」。两个后果同时发生——

1. **自述不可信。** Anthropic 2025-04-03 实测：奖励作弊场景 >99% 在作弊、<2% 承认。我们靠「自述不可信」立论，不能自己变成新的自述者。
2. **不可复跑。** 同一记录、同一模型、两次结论可能不同。账本可信第一层（L0 内部一致性）靠确定性重算，模型一进来就塌。

**边界的操作性定义**：
- 裁量用在「采样」→ 错了只是**漏**（L1 缺口），可以接受。
- 裁量用在「判定」→ 错了是**错判**（L0 污染），不可接受。

## §2 观测侧：五种形态

### 2.1 巡检 Agent（Watchman）

| 项 | 内容 |
|---|---|
| 干什么 | 定期翻账本，找**单条规则看不出来**的跨时间、跨会话模式 |
| 典型线索 | 同一文件 7 天内改 14 次、每次只改一行；某天开始命令里首次出现外发请求；凌晨 00:00–06:00 有操作；记录出现 >30 分钟断层 |
| 裁量 | 采样窗口、线索排序 |
| 产出 | **线索清单**，每条必须带账本记录 ID 范围 |
| 适配 | **个人开发者（最需要，没人帮他看）**；团队（周报素材） |
| 红线 | 只能说「这里对不上，去看」，不能说「这是违规」 |

**原型现状**（`output/lineC/watchman.py`，2026-10-31 23:11 实测）：八个检测器已落地 ——
`anchor`（日锚）／`absent`（预期缺席）／`verdict`（裁决口径八档）／`baseline`（同期基线偏离）／
`repeat`（第二次才算数）／`first_seen`（首次出现）／`gap`（日内断层）／`rule_pair`（同会话新组合）。
负控 **30/30**。两条口径已机制化进报告，不再靠人记：

- **两套裁决字段并存**：`decision` 与 `action` 是两套字段。`post_tool_use` 没有 `decision`，
  裁决记在 `action=record` 里 ⇒ 只按 `decision` 分桶会把执行侧整类漏掉。
- **日锚是 L0 不是 L2**：`day_manifest.json` 的 size／last_hash 只抓「改完没重算」，
  锚与账本同一个进程写 ⇒ 整链重写仍报自洽。措辞里不许出现「防篡改」。

### 2.2 取证 Agent（Examiner）

| 项 | 内容 |
|---|---|
| 干什么 | 用户带模糊诉求来（「我上周好像泄露了什么」），拉时间窗记录、按文件/域名/命令聚类 |
| 关键 | **标出缺口**——哪段时间没有记录。没有记录本身就是线索（扫描器崩溃的表现不是报错，是那条记录不存在） |
| 产出 | 证据包：时间线 ＋ 记录 ID ＋ 缺口说明 |
| 适配 | 事故复盘、甲方追责、诉讼举证、合规检查 |
| 红线 | 不能推断「是谁干的」，只能陈述「记录显示什么」 |

### 2.3 对账 Agent（Auditor）—— **商业模式落地件**

| 项 | 内容 |
|---|---|
| 干什么 | 拿到外部账本（合作方/甲方/监管给的），验链是否连续、每日摘要是否对得上、时间戳是否单调、总量是否与声明一致 |
| 裁量 | **几乎为零，纯计算** ⇒ 五种形态里最安全的一种 |
| 产出 | 「内部自洽 / 不自洽」＋ 断点位置 |
| 适配 | **BP 第七章「引用免费，认证收费，与结论无关」的那个「认证程序」** |
| 红线 | 只报 L0（内部一致性），不报「可不可信」——L2 外部锚今天还没有 |

### 2.4 拟稿 Agent（Draftsman）

| 项 | 内容 |
|---|---|
| 干什么 | 读真实账本，提出「空着的槽位里可能有这几条规则」，附证据样本 |
| 产出 | 候选规则草案 → 进 CI → 人审 → 才进 `rules/default.json` |
| 适配 | **内部研发，不对外** |
| 红线 | **永远不能直接落库。** 这是「生成方不能验自己」的镜像：拟稿的是它，判定的就不能还是它 |

### 2.5 红队 Agent（Adversary）

| 项 | 内容 |
|---|---|
| 干什么 | 主动尝试绕过自己的规则（改文件名、拆命令、编码、走代理），记录哪些能绕 |
| 产出 | 绕过清单，进 CI |
| 适配 | 内部测试 |
| 红线 | 不对外；绕过手法本身不能公开（否则是攻击说明书） |

## §3 判定侧：四种不做

| 形态 | 为什么不能 |
|---|---|
| **判决 Agent** | 不可复跑 ⇒ L0 塌。「我们凭什么信一个模型的判定」这个问题我们自己答不上来 |
| **处置 Agent** | 监理不施工。一动手就是裁判兼运动员，判断可信度归零（BP §六） |
| **代决策 Agent** | 三条路必须用户自己选。替用户拍板，就不再独立（BP §二） |
| **汇总 Agent** | 跨组织看所有人的账 = 从「一个组织请的监理」变成「监管者」。同时违反「数据不出这台机器」 |

---

## §4 决策器五档：不是「要不要 LLM」的二选一

| 档 | 决策器 | 裁量 | 可复跑 | 运行时成本 | 守备档能跑 |
|---|---|---|---|---|---|
| **0** | 固定规则 ＋ 定时任务 | 无 | 是 | 0 | 能 |
| **1** | **统计归纳**（基线偏离／首次出现／罕见组合） | 极低 | 是 | 0 | 能 |
| **2** | 本地小模型（1–3B，量化） | 中 | 弱 | 0（一次性包体积） | 能 |
| **3** | 云端 API 大模型 | 高 | 否 | 每次 token | 不能 |
| **4** | 外部 Agent 调我们（MCP server） | 无（我们只答） | 是 | 0 | 能 |

**规律：决策器越弱，裁量越小，可复跑性越强。** 这不是能力取舍，是**证据强度**的取舍。

## §5 把「内置 LLM」这个需求拆成三件事

创始人说的「大幅提升体验」，背后其实是三种不同需求，混在一起了：

| | 需求 | 要不要模型 | 说明 |
|---|---|---|---|
| **A** | **主动去看**（不用等我点） | **不要** | 定时任务 ＋ 统计基线就够 |
| **B** | **看得懂**（这段命令在干嘛） | 要 | 语义理解，绕不过模型 |
| **C** | **说人话**（把线索讲清楚） | 要，但小模型够 | 表达层，不影响判定 |

**A 是体验提升的大头，成本几乎为零。B、C 是锦上添花，各有硬代价。**

## §6 现阶段做什么：按「今天能不能做」排序

### 6.1 现在做（零模型）

1. **巡检：档 1 的统计归纳。** 在已有单日报告（`inbox_report.py` 的 `daily_report` / `render_text` / `render_markdown`）之上加一层**跨日归纳**：
   - 基线偏离：过去 30 天日均 N 条，昨天 M 条
   - 首次出现：37 天里从未出现过的命令/域名/路径
   - 罕见组合：两条规则从未同时触发过，昨天同时触发
   - 时间断层：连续记录间隔 > 阈值
   **这四条都不需要模型，但线索质量最高。**
2. **对账：纯计算。** 只读账本与外部账本，不碰判定路径。
3. **报告摘要：结构化模板，不用模型。** 数字全部由账本算出。

### 6.2 不做（现阶段）

- **内置大模型做判定**：违反自己的立论（生成方不能验自己）。
- **调云端 API 做默认路径**：破「数据不出这台机器」，且免费版成本失控。

### 6.3 用 LLM，但只用在研发侧

**拟稿 Agent**：用大模型读账本、提规则候选、进 CI 人审。
- 成本：开发者自己出 token
- 风险：零（产物必须过 CI）
- 收益：82 槽位里空着的那些，靠人想太慢

**这是「用 LLM 加速造工具」，不是「用 LLM 当工具」。**

### 6.4 如果一定要内置模型，只放两处

1. **表达层**（C）：把结构化线索翻译成人话。1–3B 量化模型够用。
2. **必须可关、可换、离线。** 关掉之后产品功能不减，只是话说得生硬。

## §7 三条工程约束（比形态本身更重要）

### 7.1 巡检必须能在守备档跑（0 token）

免费版的门槛是「跑一条安装命令就能得到它」（BP §八）。内置 1 GB 模型会把这个门槛毁掉。
⇒ **巡检只能是本地规则引擎 ＋ 统计，不做语义理解。** 这不是缺陷，是免费的代价。

### 7.2 Agent 读账本 ＝ Agent 吃被污染的数据

账本里有被监理方写进去的内容，命令字符串里可以嵌提示词。巡检 Agent 一旦把原文当自然语言读，就能被引导去看不重要的事。
⇒ **输入必须结构化**：记录 ID、类型、时间、哈希。原文要么不给，要么显式标成不可信输入。

### 7.3 监理 Agent 自己必须被监理

它能读账本、能跑命令，它自己就是新的攻击面。
⇒ 82 槽位里二阶那 23 个，之前是设计，现在终于有真实对象了。

## §8 商业含义

- **巡检可以收费，但只能按「巡检程序」收固定费，不能按「巡出多少问题」收。** ISO/IEC 17020：费用不得依赖检测结果。
- 与 BP 第七章「引用免费，认证收费，与结论无关」是同一个结构。
- **对账 Agent 是这条商业模式的落地件**：它是「能不能被第三方复跑」这句话的具体实现。

---

## §9 一个反直觉的判断

> **体验的最大提升不来自「更聪明」，来自「有回应」。**

现在的缺口不是 Antinel 不够懂，是它**跨时间不说话**：日报有（`inbox_report.py`），但「这周和上周比怎么样」「这个东西以前见过没有」没有。

而这件事用确定性代码就能做，而且做得比模型更可靠——**数字不会编**。

加一个模型让它「更懂」，用户还是看不到东西。**这是「用模型解决一个不需要模型的问题」的典型陷阱。**
