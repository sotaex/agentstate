fix(gate): 判据子进程走了带 user site 的通道 —— 红在通道，不在被测物

## 症状

同一棵树、同一批判据，只在启动方式上不同，结论就相反：

    裸 sys.executable   → regression 2 红（D-42 / D-45）
    -I -X utf8          → 45 条判据 PASS 45 / FAIL 0

D-42 报「`resolve_rules_file` 不存在」，D-45 报「带现算哈希的清单却判红」。
两条都不是代码坏了，是**判据 import 到了另一个对象**。

## 成因

套件是按 `[sys.executable, <套件绝对路径>]` 起的，于是 `sys.path[0]` 是套件
所在的 `ci/`，**仓根不在搜索路径上**。判据里裸 `import host_shield` 只能顺着
sys.path 往上找，命中 user site 里那份 0.28.0 的旧 `host_shield.py`。
量具拿到旧对象，量的当然不是这棵树。

## 为什么选 `-E -s` 而不是生产钩子那套 `-I -S`

- 生产钩子的旗标只有一处真源（`scripts/install.py::hook_command()`，`-I -S`），
  钩子不依赖第三方包。判据套件不同，要用 system site-packages，加 `-S` 会崩。
- `-I` = `-E -s -P`，那个 **`-P` 是副作用**：它把 `sys.path[0]` 也摘掉了。
  实测用 `-I` 时 0431 的两条负控双双失效，红项原文
  `ModuleNotFoundError("No module named 'tmpreg'")`。
  **负控失效比红更糟** —— 判据无法证明自己会红，等于没有判据。
- 只取「排除 user site」这一件事：`-s`。`-E` 顺带排掉 PYTHONPATH（本机那份指向
  宿主的 `cli/vendor/shim` 垫片），让判据站在同一个干净基线上。

## 敌对通道不靠这里守

`-s` 让「user site 有旧同名模块」这个情形在闸门里消失了，但那本身是**产品**
要扛的事（旧模块劫持）。它由 0514 的 HSI 族用带 user site 的通道显式测降级留痕。
两条腿分工，缺一不可：这里量「干净环境下判据看见什么」，HSI 量「被劫持时产品
有没有说出来」。只做前者，等于把要抓的东西藏起来。

## 现状核对（2026-11-03 00:10）

那份旧 `host_shield.py` 已被重命名为 `host_shield.py.away-20261102`，
user site 里其余 0.28.0 残留（`antinel.py` / `audit_chain.py` / `antinel_mcp.py`
等）仍在。**但这条旗标不因此可以撤**：重命名是手工动作，换台机器、重装一次
0.28.0 它就回来了。旗标是把同一件事变成结构性的。

## 连带修复：控制台编码

同一处还钉了 stdout/stderr 的编码。原来只设 `line_buffering`，编码仍随 locale
⇒ 本机控制台是 GBK（936），打印 ✅（U+2705）抛 `UnicodeEncodeError`，进程走不到
「未知 `--only` 键返回 2」那一行 ⇒ D-41 报「期望 rc=2 得 rc=1」，输出尾是一段
traceback。两级回退：先试「编码＋行缓冲」，流不支持再退回只设行缓冲。

这一条同时说明**产品在普通 Windows 控制台上真的会崩**（含管道/重定向，那时
stdout 不是 tty，Python 按 locale 编码），不是判据太严。
