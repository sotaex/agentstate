## 2 复核时新发现两条（B 没写，不是 B 写错——它没扫这一侧）

### BD-6（严重 · 死判据）唯一读 `last_hash` 的验证器，那条判据恒假

B-3 的结论写「`last_hash` 写了但**没有任何代码读它**」。**一半对**：`tools/verify_chain.py` 确实没读；
但 `challenge/verify.py:63`（对外那份「公开挑战件」，零依赖、售给别人离线复算用的）**读了**，只是条件恒假：

```python
if m.get("last_hash") and prev_full and not prev_full.startswith("") \
        and m["last_hash"] != prev_full:
```

`"".startswith("")` 是 `True` ⇒ 第三个合取项恒为 `False` ⇒ 整条判据永不成立 ⇒ `TAIL-EDITED` 永远不会被报出来。

**四腿读数**（`output/lineA/bd6_dead_condition.py`，样本 `2026-10-08`：1,754 条 / 592,953 字节）：

| 腿 | 期望 | 实际 | rc |
|---|---|---|---|
| A 原版 + 故意写错的锚 | TAMPERED | **CLEAN** | **0** |
| B 原版 + 正确锚 | CLEAN | CLEAN | 0 |
| C 修版 + 故意写错的锚 | TAMPERED | **TAMPERED**（明细含 `TAIL-EDITED`） | **2** |
| D 修版 + 正确锚 | CLEAN | CLEAN | 0 |

修法是把那个合取项换掉（变异差 33 字节，替身命中恰好 1 次，脚本已断言）。
**但先别急着改**——理由见 §3：单独改它，只是给两个验证器造出第三种口径。

### BD-7（中 · 静默降级）末条超过 4096 字节时，日锚整套更新被吞掉

`audit_chain.py:567 touch_day_manifest()` 只回读末 **4096** 字节，然后对那一行做 `json.loads`。
若末条比这更长，解析必然失败 ⇒ 被 `except Exception: pass` 吞掉 ⇒ **整次锚更新静默跳过**（不是只丢 hash）。

| 量 | 值 | 时刻 |
|---|---|---|
| 全账本超 4096 字节的记录 | **3 条**（10-15 一条 16,662 字节；10-23 两条 8,780／…） | 04:08 |
| 末日记录超 4096 的日 | **0**（所以今天没炸） | 04:08 |

⇒ 现在**潜伏**。它一旦发生，表现是「锚停在上一状态」，与 BD-3 的「漏调锚」在磁盘上长得一模一样，
而两者的修法不同。**这类缺陷不会被任何"看锚在不在"的判据发现**——锚在，只是旧的。

## 3 BD-2 的「二选一」现在应该是「三件事一起做」

先把数摆出来（`output/lineA/bd2_anchor_feasibility.py`，04:07:24）：

| 量 | 读数 |
|---|---|
| 有锚且非空的日 | 32 / 34（缺 `09-25`、`10-05`，即 BD-3 的两个实例） |
| 锚里的 `last_hash` 仍能在当日文件里找到 | **32 / 32** |
| 锚 `last_hash` == 当前末条 `hash` | **32 / 32** |
| 锚定字节落后实际字节 | min 0 / 中位 0 / max 0，累计 **0 字节** |

**两个含义：**
1. **「把 `last_hash` 接进校验」今天不会误报**——32 天全部命中，且锚正好压在末条上。这条腿是干净的。
2. **但只接 `last_hash` 不够，甚至可能帮倒忙**：锚可以**静默停更**（BD-7）、可以是**opt-in 漏调**（BD-3）、
   两个验证器各有一套口径（BD-6）。接进去之后，攻击者不必去改 hash，只要让锚停止刷新就行——
   **一条会停更的锚，比一条明说"只抗截断"的锚更危险，因为它看起来在工作。**

所以我的建议是 **选「接进去」，但作为一件事的三个面一次做完**：

| 面 | 做什么 | 为什么不能分开 |
|---|---|---|
| ① 单一实现 | 「锚 ↔ 尾」的比对只写一次，`tools/verify_chain.py` 与 `challenge/verify.py` 都调它 | 两个调用方各写一遍＝第一顽症的标准形态 |
| ② 锚由唯一写入口刷新 | `touch_day_manifest()` 变成写账本的副作用（BD-3），不再靠 11 处调用方记得调 | 否则接进去的牙咬的是「调用方记性」 |
| ③ 刷新失败要留痕 | `except: pass` 改成记一条可查事件；末条读不全（BD-7）要能自己发现并重读 | ②失效时唯一能被看见的方式 |

**验收口径（三条，缺一不验收）：**
- 用 B-3 的 L-3／L-4 两腿当正控：改版后 L-4 必须 `rc=2` 且报 `TAIL-EDITED`，L-3 仍 `rc=0`；
- 用今天的真账本跑一遍：34 天里**误报必须为 0**（当前基数 32/32 全对）；
- 把锚故意改成陈旧（模拟停更）：必须报出来，而不是静默通过。
