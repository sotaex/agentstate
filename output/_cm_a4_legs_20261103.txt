## 每组守的是什么

- **EXIT_CODE（守 Q1-01 构建失败）**：两条正负控之外，关键在第 3 条 ——
  **非构建命令的非零退出必须整段返回 None**。`ls /nonexistent` 也非零退出，
  若把它算进「构建失败」，这条判据就变成天天红的噪声源，几次之后必然被人关掉。
  另加一条：记录里缺 `exit_code` 时不许当成非零（缺字段是缺事实，不是失败）。

- **ARTIFACT_PATH（守 Q1-05 声称产物消失）**：语料**真的在盘上造一个文件**
  再问，不靠 mock 路径 —— 这条探针只做 `os.path.exists`，造假的输入测不到它
  真实的判断。造在 `_TMP.tmpdir` 里（本仓有过 tempfile 残骸事故，560 多个
  8 字符随机名躺在 git status 里）。第三条：`Bash` / `Read` 记录里的
  `file_path` **不算「声称产物」** —— 命令行里出现的路径是猜的，不是声称。

- **CMD_TEXT（守 A1-01 / A1-05 / K1-02）**：三类锚点**现取现报**，从
  `rules/default.json` 的 `category` + `name` 里取，不写死任何规则号 ——
  手抄一份 ID 名单就是第二套口径，规则表一改判据就不跟（铁律 8）。核心那条：
  **只命中 secret 时 dangerous 必须为 False，反之亦然**。三类「危险」的定义
  不同，混用会让「读到一份凭证」被报成「删了东西」。再加一条：规则表读不到
  时必须整段 None，否则「不知道什么是危险」会被读成「没有危险」。

- **LEDGER_ACTIONS（守 I1-01 决策无留痕）**：`unpaired`（有 pre 无 post，动作
  可能还在跑）与 `unpaired_post`（有 post 无 pre，动作做完了决策没留）**必须
  是两个字段**。合并它们会让 I1-01 与 I1-02 对同一事实给出相反结论 ——
  实测过：I1-01 判命中 354，同一批数据 I1-02 判清白 2.6%。另加空 digest
  不算配对依据、空集必须 None。
