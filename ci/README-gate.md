# 回归闸门（L7）使用说明

> **一句话**：每次改完代码、提交前，跑 `python ci/regression_gate.py`。
> 全绿 ⇒ 提交；变红 ⇒ 你刚把某个已修好的缺陷弄回去了。

## 为什么要有它（解决「越修越多」）

「越修越多」有三条结构性原因，这个闸门针对**前两条**：

| 原因 | 闸门怎么管 |
|---|---|
| ① 判据与被测对象分离，且判据自己没被验过 | 闸门的**每条判据都配负控**（`--selfcheck`），负控证明它不是假守卫 |
| ② 只验「本次修的」，不验「被影响的」 | 闸门锁的是**历史已修缺陷**，每改一次全跑一遍 |
| ③ 问题只进不出，无收口 | （闸门不管这条，那条靠封版/台账） |

**关键数字**：套件要 **~24 分钟**（大量冷启动子进程）⇒ **太慢就不会天天跑 ⇒ 等于没有**。
本闸门 **~8 秒**，快到你没有理由跳过它。

## 三种跑法

```bash
# 1. 跑闸门（日常）
python ci/regression_gate.py

# 2. 跑负控（改了闸门本身 / 定期自检）
python ci/regression_gate.py --selfcheck

# 3. 机器可读（接 CI）
python ci/regression_gate.py --json
```

**退出码**：`0` = 全绿；`1` = 有判据变红（**这是拦截信号**）；`2` = 找不到包。

## 判据清单（7 条）

| # | 判据 | 锁的是什么 |
|---|---|---|
| 1 | **SELF** 闸门运行在真表上 | 防闸门**自己**被静默降级 ⇒ 后面 6 条全部不可信 |
| 2 | A1 DST-10 的 block 不被降级为 alert | 解释器分支的判据必须够宽 |
| 3 | A1 判据单一真源（两函数不分叉） | `_interp_mention_residue` 是唯一真源 |
| 4 | A2 加载与比对同源（**行为级**） | 真跑 install ＋ 篡改 ⇒ `SELF-TAMPERED` **必报** |
| 5 | D-3 纯文本提及仍放行 | 防「修 A1 把 D-3 弄回去」（假阳性） |
| 6 | DST-01 真表 21 条未损坏 | 对照项：确认规则表本体没被动 |
| 7 | 兜底集事实未变（17 条、无 DST-10） | 防有人误以为兜底集含 DST-10 |

## ★★ 第 1 条判据最重要：防「闸门自己被骗」

`_load_rules_integrity` 会在 `(os.getcwd(), dirname(os.getcwd()))` 找
`.psl/manifest.json`。产物仓的**上级** `D:\psl\poc\.psl\manifest.json`
是 **09-18 陈旧件**，会让闸门**静默降级到 17 条兜底集（无 DST-10）**：

- DST-10 类判据 → **假红**（真表里才有 DST-10）
- DST-01 类判据 → **假绿**（兜底集里也有 DST-01）

**两个方向都会骗人。** ⇒ 闸门用 `neutral_cwd()` 把 cwd 换到中性目录，
并且**第一条就断言"我跑在真表上"**。它红，后面全部结果作废。

## pre-commit 钩子（第二半）

**光有闸门 ≠ 闸门会被跑。** 钩子把「跑闸门」变成提交的前置条件。

**部署**（新克隆的仓要手动做一次）：
```bash
cp ci/git-hooks/pre-commit .git/hooks/pre-commit
chmod +x .git/hooks/pre-commit
```

**已被实测验证**：
- 绿时放行（提交成功）
- 红时拦截（注入 A1 回退缺陷后，提交被拦下并打印 `[FAIL]` 行）

**绕过**：`git commit --no-verify` —— 但请写明理由，它是知情选择，不是溜过去。

## 改闸门本身的纪律

改了 `regression_gate.py` 之后，**必须跑 `--selfcheck`**：

```
负控 = 把每个缺陷注入回去，断言闸门必须变红
```

**负控自己也会骗人**，所以它有两条自保：
- 注入点**找不到时报 SKIP 并算失败**（不许静默通过）
- 断言「变红了」**且「红的是预期那条判据」**（防止张三的病让李四的药变红）

**实测记录**（首次建立时负控抓出的三个真问题）：

1. **A2 初版是假守卫**：判据写成了「在源码里 grep `rules_file`」——把
   `_rules_path = _cand` 改回 `RULES_PATH`，字符串还在，判据照样绿。
   ⇒ 重写为**行为级**（真跑 install ＋ 篡改 ＋ 断言必报）。
   **这是「文本级 ≠ 值级校验」的活标本。**
2. **A1 注入 2 是空操作**：改成 `pass` 后代码仍落到同一个 `return None`。
   ⇒ 改为 `return seg`（真降级），注入才生效。
3. **闸门初版没隔离 cwd** ⇒ 见上文第 1 条判据。

## 与套件的关系

| | 回归闸门 | 套件 `verification_tests.py` |
|---|---|---|
| 耗时 | **~8 秒** | ~24 分钟 |
| 判据数 | 7 | 313 |
| 用途 | **每次改动后立刻跑** | 发版前全量验一遍 |
| 覆盖 | 只锁已修缺陷 | 全量功能 |

**不是替代关系**：闸门是**快筛**，套件是**全检**。发版前两个都要。
