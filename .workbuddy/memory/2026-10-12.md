## ⑩ 兑现 D-25 的「出路」+ 一次我自己造成的破坏与防线（2026-10-12 傍晚）

### 10.1 发现 D-25 是个「红而无出路」的判据（维九违例）
D-25 docstring 写了「追平工具：`_tools_034/_resign_manifest.py --roll`」——**这个 `--roll` 当时并不存在**。
判据红了却给不出修法 ＝ 文档与代码不同锚。⇒ 实现 `--roll`：
死条目**结构化对齐**（同目录 + 同扩展名 + 该扩展名在目录内恰好一个、且它自己还不在清单里），
三条全是集合运算、不是字面匹配豁免；猜不出唯一解 ⇒ **STUCK 并 exit 1，不猜**。
实测闭环：注入死条目 ⇒ D-25 精确红 ⇒ `--roll` 精确对齐 ⇒ `--manifest` 回绿。

### 10.2 ★ 我误跑破坏了 manifest（诚实登记，这是本轮最重的一条）
跑 `_resign_manifest.py`（**不带 --roll**，只想看干净状态）⇒ 它把
`hooks/pre_tool_use.py` 判成「需重签」并写回 ⇒ `--manifest` 立刻
`[SUPERSEDED] 1 of 124 ... changed: hooks/pre_tool_use.py`（**由绿变红**）。

**根因（既有缺陷，量具自身）**：构建器 `_manifest_hash_of` 对
`host_shield.VERSION_BEARING_CHAIN_FILES`（实测只 `hooks/pre_tool_use.py` 一件）
是**先把版本行的引号内值归一化掉再算**（版本行不进完整性哈希，否则每次升版都让自检红）；
而 `_resign_manifest.py` 用**裸 sha256**。两个口径不一致 ⇒ 后果**双向**：
  · 假红：把没变的文件判成「需重签」
  · 破坏：照错值写回 ⇒ `--manifest` 由绿变红
**处置**：`git show :psl/manifest.json` 恢复 staged 版（追平+host_shield 重签那版，
hooks 口径正确）⇒ 三项复验全绿。**没有污染任何产品代码**（`git diff` 对
hooks/pre_tool_use.py 为空，磁盘哈希与清单一致——破坏只在 manifest 一个文件里）。

### 10.3 修工具 + 加量具自检（维七，由真实破坏逼出来）
- `sha256()` 改为**直接 import host_shield 拿归一化函数**（判据不许二次实现），
  与构建器逐字同口径。
- **量具自检**：写回之前，对每个口径特殊件验「本工具算出的值 == manifest 已记录值」
  （干净状态下理应相等）。不一致 ⇒ **拒绝写回**（修工具，别修清单）。
  ⇒ 这正是维七「量具先自检」缺的那一环：原有自检只注入**产品**缺陷，
  **从不验量具自己的口径**——所以量具坏了没有任何东西会叫。
- **反向对照（量具自身）**：故意把 manifest 的 hooks 哈希改成裸口径错值
  ⇒ 工具报「量具自检失败…拒绝写回」且 manifest 未被改动 ✓
- 修后实测：干净状态「124 未变 / 0 需重签 / 0 不存在」（hooks 误报消失）；
  `--roll` 闭环仍然精确。

### 10.4 一条操作教训（我自己的）
还原命令写成 `diff -q A B && echo ok && cp A B` —— `diff` 发现两文件不同返回 1，
把后面的 `cp` **短路**了 ⇒ 还原没执行，manifest 留在被破坏状态直到我下一轮手动还原。
**纪律**：破坏性测试的还原必须是**独立一步**（`;` 分隔或单独一条命令），
不许挂在校验命令的 `&&` 链尾——校验失败时恰恰最需要还原。
