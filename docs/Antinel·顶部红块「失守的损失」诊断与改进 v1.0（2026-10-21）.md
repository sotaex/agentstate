> 「**截图中红色部分看着让人紧张，但是又没法操作；我认为有问题**……再看看红色部分

## 1. 现场（原样抄录，不改一个字）

> **失守的损失：以下 1 项（此刻实况，非计数）：**
> · 有 4 个受监管落点，此刻没人巡检（监理在会一直盯着它们、有写入就报）；其中 4 个相对上次记录有变动

而**同一屏**顶部写着：

> **值守中　研发中**
> 正在用还没发布的版本守着，能拦的照拦；另有 18 次已处理。

下面收件箱写着：

> **当前读取到的记录里，没有要你处理的事。**

⇒ **一屏三个说法**：值守中 / 没人巡检 / 没有要你处理的事。

## 2. 实测自证：那句「此刻没人巡检」是**假的**

现场直取（`host_shield.guard_posture()`，2026-10-21 10:30 实跑）：

```
state      = dev | 研发中
why        = 正在用还没发布的版本守着，能拦的照拦
can_fix    = False | fix = None
sentinel   = 20580        self_check_ok = False
dev_why    = 登记版本 0.50.5 ＜ 代码版本 0.53.2 ⇒ 这一版还没发出去
consequences = [landing_unwatched :: 有 4 个受监管落点，此刻没人巡检…]
```

再核「哨兵到底在不在」：

| 项 | 实测值 | 判定 |
|---|---|---|
| 哨兵进程 | pid **20580** 在 | 在岗 |
| 心跳时刻 | `2026-10-21T10:28:11+08:00` | 491 秒前 |
| 心跳周期 `HEARTBEAT_SECONDS` | 600 秒 | 正常节奏内 |
| 判死阈值 `_STALE_AFTER` | 1800 秒（3×周期） | **远未到** |

⇒ **哨兵在岗、心跳新鲜、正在放哨。** 那句「此刻没人巡检」与事实相反。

**这条要按 T-01（会说谎的数字）的变种处理：会说谎的**状态**。**
它比数字说谎更危险 —— 用户看到红块的第一反应是"出事了"，而事实是"一切在岗"。

## 3. 根因：一条调用链，错在**一行**

```
manifest 停在 0.50.5（未重签）  →  self_check() = False
        ↓
_code_untrusted = True  且  alive and fresh  →  进 dev 分支（host_shield.py:3569）
        ↓
dev 分支为了「不硬编码空列表」，调用了 **缺岗损失计算器**
        _cons = _outage_consequences(st, pkg_root)      ← host_shield.py:3601
        ↓
_outage_consequences 的 ④ 号只问「有没有受监管落点」，
**从不问「有没有人在看」**                              ← host_shield.py:3450-3477
        ↓
只要有落点 ⇒ 无条件产出「此刻没人巡检」
```

**对照证据（同一函数、另一处调用是对的）**：
`host_shield.py:3678` 的 `cons = _outage_consequences(st, pkg_root)` 位于**缺岗分支内**
（`if not alive` / `else 没动静了` 之后）—— 那里算「缺岗损失」名副其实。
**全仓只有 dev 分支这一处，在哨兵活着的时候调用它。** 这就是全部病因。

**为什么会写成这样（历史原因，不是随手）**：
`host_shield.py:3572-3577` 的注释写着 —— 0.36.4 发现原实现 `"consequences": []`
是**硬编码的空**，与"量过了、确实没有后果"长得一样，会藏起状况 ⇒ 改成"照走
`_outage_consequences()`"。
**修的方向对（不许硬编码空），选的工具错（拿缺岗计算器去算非缺岗场景）。**
正确的做法是：算**另一个问题**（此刻正在盯什么），而不是借一个前提不成立的函数。

## 5. 改进方案

### 5.1 先修事实（必须，与文案无关）

**把「扫描落点」与「判定缺岗损失」拆成两个函数**（§22 闸五：一个事实一个实现）：

```python
def _watched_landings(pkg_root=None):
    """此刻监理盯着的目录 + 其中有多少自基线后有写入。纯事实，不含判断。"""
    # 原 ④ 号里的 _scan() 整段搬到这里，返回 (落点列表, 有写入的个数, 基线时刻)

def _outage_consequences(state, pkg_root=None):
    ...
    # ④ 只在**真缺岗**时才走（本函数名已经假定了 outage，实现必须自己守住）
    ...
```

- **dev 分支**（`host_shield.py:3601`）：改调 `_watched_landings()`，产出**正面陈述**，
  不再调用缺岗计算器；`consequences` 保持 `[]`（此时它**是真的**：没有缺岗，
  就没有缺岗损失），另给一个新字段 `watch_note`。
- **缺岗分支**（`:3678`）：照旧用 `_outage_consequences()`，语义本就正确。

> ★ 为什么这样不违反 0.36.4 的初衷：「不许硬编码空」要防的是**把没量过的说成没有**。
> 这里 `consequences: []` 是**量过之后**的结论（哨兵在岗 ⇒ 不存在缺岗损失），
> 并且另有一份**算出来的** `watch_note` 说明"此刻正在盯什么"——信息没有被藏起来。

### 5.2 文案（全部换成大白话，一句一事）

| 现在 | 改成 |
|---|---|
| 失守的损失：以下 1 项（此刻实况，非计数） | **（dev 态不再出现这块）**；真缺岗时改为「**这段时间漏掉了什么**」 |
| 有 4 个受监管落点，此刻没人巡检 | 真缺岗：「有 4 个目录平时由监理盯着，这段时间没人看」 |
| （监理在会一直盯着它们、有写入就报） | 「有人动过这些目录，监理本来会立刻报」 |
| 其中 4 个相对上次记录有变动 | 「其中 4 个自 10:12 之后有写入」**（必须给基准时刻）** |
| （无路径） | 列前 3 条路径 ＋ 「还有 1 个」 |

**dev 态的新表述（推荐）**——放在顶部条下方，**中性色，不是红底**：

> 监理正在盯着 **4 个目录**，其中有 **4 个**自上次记录后有写入（这是它们在工作，不是告警）。
> 不需要你做什么：这一版发出去之后，这里会自动消失。

### 5.3 视觉

- **红底只留给"真缺岗且有损失"**（`POSTURE_DOWN`）。dev 态用中性／浅色块。
- 若同一屏已有「没有要你处理的事」，红块**不许**再出现 —— 两者互斥
  （一条说"有损失"，一条说"没事"，必须只能留一条）。

### 5.4 可操作性

| 情形 | 用户要做什么 | 页面给什么 |
|---|---|---|
| dev 态（当前） | **什么都不用做** | 一句话说明 + "发版后自动消失" |
| 真缺岗 | 点「马上修复」重新拉起监理 | 已有按钮（`fix="revive"`），保留 |
| 真缺岗且修复失败 | 按提示重装 | `fix_hint` 指向具体命令，**不指向"它们"** |

## 6. 判据缺口（这是为什么会漏到今天）

现有两条判据都没管这一格：

- `0353 P12`（缺岗看得见受监管落点）：只在**缺岗**场景验"后果被列出来"。
- `0353 N-P12`（没有后果 ⇒ 不许出现那一块）：验的是"没有后果时不许有噪音"。

**两条都假设「consequences 非空 ⇒ 一定在缺岗」。dev 分支打破了这个前提，而没人守。**

**建议新增 `X11`／`N-X11`**：

- `X11`：构造 `alive=True, fresh=True, is_dev=True` ⇒ 渲染产物里**不许出现**
  「没人巡检」「失守」字样；且必须出现"正在盯着 N 个目录"这类**正面**陈述。
- `N-X11`：把 dev 分支改回调用 `_outage_consequences()` ⇒ `X11` 必须红。
  （这就是今天这一版的真实形态，负控天然成立。）
- 附带一条：`X11b` —— 同一页**不许同时**出现「没有要你处理的事」与「失守的损失」。

## 7. 与「已知问题总账」的关系

本件是那份总账里 **P1「体验层」**的一个具体实例，但它暴露的是一条更普适的机制：

> **「前提不成立的函数被复用」** —— 函数名写明了前提（`_outage_…` 假定缺岗），
> 调用方却在前提不成立的地方用它，而函数内部**不校验前提**。
> 这类错误不会让任何判据变红（因为每条判据都在自己假设的场景里测），
> 只会在真实页面上被**人**看见。

建议把这一条补进 `ci/defect_types.py` 的 T-10（静默降级）或新立一类：
**「前提未校验的函数复用」**。
