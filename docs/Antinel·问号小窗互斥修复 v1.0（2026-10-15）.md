# Antinel · 问号小窗互斥修复 v1.0（2026-10-15）

## 0. 一句话结论

创始人判定「点开下一个问号小窗时，上一个自动关闭」为产品缺陷。机制层修法＝给术语芯片加 **WHATWG HTML 原生互斥手风琴**属性 `name="term"`（一处发射点，全站生效，零 JS），并新增判据 **U-19 ＋ 负控 N-U19** 钉死，防死灰复燃。

## 1. 现象与判定

- 现象（创始人 2026-10-15 截图＋实测）：值守台页面多个术语「？」小窗**同时展开并互相叠压**；点开下一个，上一个不关。
- 创始人原话：「截图这个是缺陷。能不能做到——点开下一个问号的小窗时，上一个自动关闭？……如能解决，要从机制层解决。」
- 服务端 HTML 实测：四视图 `<details>` 带 `open` 的为 **0 个** ⇒ 展开全部来自用户点击，**不是**浏览器状态残留、**不是** JS 强开。

## 2. 根因链（机制层，全部有代码行号）

1. **发射点唯一**：`glossary.py:394` `chip()` 是全部术语芯片的唯一出口（`<details class="term[ mk]" data-t="KEY">`）。全仓检索确认无第二处手写 `class="term`。
2. **弹层是视口定位**：`inbox_server.py:195` `.term>.tdef{position:fixed;...}`（0.50.3 截图复发后改的），JS `fit()`（:365-381）把展开体按锚点摆到视口坐标 ⇒ **同时 open 两个就叠两个窗**。
3. **原生 `<details>` 从未互斥**：HTML 里 `<details>` 天然允许多开，没有任何「同名自动互斥」语义。
4. **考古（本轮最关键发现）**：`inbox_server.py:162` 的 0.36.1 CSS 注释**早就宣称**「点开别的词条会收起上一个，因为同名 details 在同一父节点下互斥——这也是选原生控件的原因」。**这在 HTML 里从未成立**——是把愿望写成了事实，机制从未存在过。用户今天看到的多开叠压，就是这句注释欠下的债。

## 3. 方案：为什么是 `name="term"`（机制层，不是补丁）

- **标准机制**：WHATWG HTML 的 `<details name>` —— 同 `name` 值即同组（**不要求相邻**，散在全页也算同组），开一个、浏览器**原生保证**关掉组里其余 open 的。正是「互斥手风琴」。
- **支持面（联网核实 caniuse／MDN／Chrome 官方文档，2026-10-15）**：Chrome/Edge **120+**（2023-12-05/07）、Firefox 130+（2024-09）、Safari 17.2+；Edge 120–157 全支持，全球覆盖 92.49%。本机 Edge 远新于 120。
- **渐进增强**：旧引擎不认 `name` ⇒ 退回现状（多开），**不会坏**。
- **零 JS、零状态**：不加一行脚本、不引入自管状态；现有 `fitOpen()`/`toggle` 监听只对 `open` 的芯片做定位，被互斥关掉的那枚触发 `open=false`，监听自然跳过——**无需改 JS**。
- **范围边界（刻意不做）**：只锁术语芯片。`details.where`（账本「存在哪个文件里」等行内补充）、`details.item`／`rem`（记录行、归因面板）是**行内展开**，多开无害、互斥反而碍事——**不进组**。`.gloss`（`GL.line`）当前无落点（Q-25 撤块后休眠），不动。

**为什么锚点必须同步**：U-04 ③ 断言的是逐字子串 `data-t="KEY"><summary>…`（data-t 后紧跟 `>`）。`name` 无论放标签内哪个位置都必然撞一处锚点（类名后插会撞 734/772/775 的正则前缀，data-t 后插会撞 749 的逐字子串）——按纪律**同步锚点、不降强度**：head／`<summary>？</summary>`／`<div class="tdef"><b>` 仍逐字在场，少一样照样红。其余锚点实测兼容：0490:734/772/775（正则在 data-t 值即停）、0490:2047（U-16，`[^>]*` 吞属性）、0353:2199（`data-t="K"` 无邻接要求）、`page_caliber.py:62`（`_TERM_BLOCK` 带 `[^>]*`）。

## 5. 判据设计（U-19 ＋ N-U19）

- **U-19（正判据）**：四视图（inbox/report/health/ledger）逐页渲染，用**唯一尺子** `_u19_offenders()` 检查每个 `<details class="term…">` 都带 `name="term"`；任一缺 name ⇒ 红。另设兜底：四视图合计 0 枚芯片 ⇒ 红（发射器整体失效不静默）。单视图 0 枚**不**红（词条落点分布是 U-04／P13 的职责，不重复设防）。
- **N-U19（负控，两步法）**：变异落在**发射器**——import 后 monkeypatch `GL.chip`，剥掉输出的 ` name="term"`，经 `_mut_render` 渲染（C-01 两步法：能 import＋最小渲染不抛，量具故障与产品红分账）⇒ U-19 必须红；`finally` **还原共享模块**，不给后续判据留脏状态。夹具自证：真实现本身必须全带 name，否则判「负控无分辨力」。
- **登记**：加在既有套件 0490（术语芯片族 U-04 邻位），不新增套件 ⇒ A2 常驻 29 不变、A1 五判据头不涉（仅新套件需要）。
