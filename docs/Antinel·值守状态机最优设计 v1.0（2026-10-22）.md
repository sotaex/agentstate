## 0. 结论先行

**六态应当退役为一个「能力谱」（品牌叙事），运行态改为「模式层 ＋ 三轴 ＋ 派生灯」。**

| | 现行 | 本方案 |
|---|---|---|
| 运行灯值 | `R0 / L2 / L1 / L0`（生产可达 3 个） | **灰 / 绿 / 黄 / 红**（4 个，全部可达） |
| 对外状态词 | 6 个（其中 `拦截`、`缺粮` 已不可达） | **7 个**（全部可达，全部对应一个动作） |
| 词的挂载点 | 挂在**灯**上（一个词装多件事） | 挂在**成因**上（一个词一件事） |
| 灯的决定方式 | 赋值（分支判断，散在两处） | **纯函数**（四轴派生，可穷举验） |
| 可区分处境 | 12 个处境 → 3 组（7 个挤在绿灯上） | 19 格 → 7 组，每组一个动作 |
| 「失守」的用法 | 3 件事共用（没人守/漏了/认不出） | **只用于 1 件事**（没人守 ∧ 有损失） |

一句话：**旧模型用一个维度（灯）承载四个正交事实，四个事实打四次架；新模型把
四个事实分开，灯只回答一个问题——要不要现在停手。**

## 1. 诊断：现行六态到底是什么

### 1.1 逐态解剖

| 键 | 自述职能 | 实际承载的处境 | 判据锚 |
|---|---|---|---|
| `R0` | 红·讣告：防线没生效 | ① 不在岗 ∧ 有损失 ② 守门代码对不上 ③ 疑似投毒 ④ 开机不自启 ⑤ 加锁失败 ⑥ 自检失败 | `_posture_direct`、`TITLE_OF_TOPIC` |
| `L2` | 明黄：有操作被拦下 | 已被挡下的危险操作 | `tool_call_blocked` → 0.51.0 起 info 桶不抬灯 ⇒ **生产点不亮** |
| `L1` | 浅黄：知情即可 | ① 不在岗 ∧ 无损失 ② 探不到状态 ③ 读不到心跳 ④ 未关闭的提醒 ⑤ 自研迭代 | `base_state` 三个分支 + `_event_lamp_level` |
| `Ls` | 橙：预算告警 | 粮将尽 | 0.51.0 起移出主灯，改徽标 |
| `L0` | 绿：值守中 | ① 在岗 ∧ 干净 ② 有拦截活动 ③ 未启用（灰变体） ④ 研发中 | `base_state` |
| `dev` | 蓝：研发迭代 | 代码比登记的新 | 0.51.0 起移出主灯，改徽标 |

**三处结构性事实（不是我读出来的，是源码自己写着的）：**

1. `current_state()` 的 docstring 把 `L1` 标注为「**兼有**」—— 一个档同时接收
   「此刻」与「账」两种来源。这是维度混装的自我承认。
2. `POSTURE_LABEL` 里 `warn` 的标签是「失守」与 `down` **完全相同**，而两者的
   证据强度差一整个量级（一个是"确定没人守"，一个是"我认不出"）。源码注释
   解释了这个选择（标签必须与灯同词），但**它同时暴露了根因：词挂在灯上，
   所以标签被迫跟着灯走。**
3. `light_explain()` 走 `base_state()`（只看姿态），而灯走 `current_state()`
   （姿态＋事件）—— **同一事实两条路径**，违反闸五同源。

### 1.2 实测：12 个「动作不同」的处境，只有 3 组在视觉上分得开

实测方法：构造 12 个处境喂给 `current_state()` ＋ `light_explain()`
（`now` 固定，`items` 用真实 `Alert` 形状）：

| 处境 | 该做的动作 | 灯 | 首屏那句话 |
|---|---|---|---|
| 在岗·干净 | 无 | L0 绿 | 监理在岗，没发现问题 |
| **在岗·1 小时前有未修复缺口** | **修缺口** | **L0 绿** | **监理在岗，没发现问题** |
| **在岗·3 天前有未修复缺口** | **修缺口** | **L0 绿** | **监理在岗，没发现问题** |
| 在岗·已自愈记录 | 无（知情） | L0 绿 | 监理在岗，没发现问题 |
| 在岗·有拦截活动 | 无（知情） | L0 绿 | 监理在岗，没发现问题 |
| 在岗·未关闭的提醒 | 处理提醒 | L1 黄 | **监理在岗，没发现问题** |
| 不在岗·有损失 | 拉起＋查损 | R0 红 | 监理不在岗，现在没人替你挡着 |
| 在岗·守门代码对不上 | 核对重装 | R0 红 | 守门用的代码跟出厂记录对不上… |
| 不在岗·无监管对象 | 拉起 | L1 黄 | 监理暂停了一会儿，好在…没放过任何东西 |
| 探不到状态 | 确认 | L1 黄 | 看不到监理的状态… |
| 未启用 | 装配 | L0 绿（应灰） | 还没开启，现在不会拦，也不会记账 |
| 研发中 | 无 | L0 绿 | 正在用还没发布的版本守着… |

**三处硬缺陷（探针固化为 F1/F2/F3，改前必红）：**

- **F1 未修复的缺口不进灯。** 一条 R0 级、1 小时前发生、**至今没修**的缺口，
  灯是绿的，句子里写着"没发现问题"。根因：`_event_lamp_level()` 把 R0 一律
  排除在抬灯之外（0.39.0「失守不回溯」），实现却用**时间窗**（`within_hours`）
  去判断"过去"，而那条铁律的本意是「**已恢复** ≠ 现在失守」——
  **"已恢复"是状态（`recovered` / `state ∈ CLOSED_STATES`），不是时间。**
- **F2 事件抬灯时那句话不变。** 灯黄、话说"没发现问题"，同屏两个通道打架。
  用户看到黄灯只会判断"这灯坏了"。
- **F3 未启用与值守中同色。** 都是 `--l0`，只差三个字。新装第一屏恰好是 `off`
  —— 承诺还没兑现，被画成"一切正常"。

### 1.3 结论：词表不缺，缺的是**维度**

六态不是"多了"或"少了"，是**把四个正交事实挤进了一个维度**：

| 正交事实 | 只有两个/三个取值 | 被挤在哪 |
|---|---|---|
| 有没有人在守 | 在 / 即将失去 / 不在 | `L0` / `Ls` / `R0`+`L1` |
| 守得住吗（可不可信） | 能证明 / 证明不了 | `L0` / `R0`(warn) |
| 有损失吗（未修复缺口） | 有 / 无 / 说不清 | `R0` / `L0` / `L1` |
| 装了吗（模式） | 未装 / 演练 / 执勤 | `L0`灰 / `dev` / 其余 |

**四个事实，灯只有三个可达值。** 这不是设计选择，是编码容量不足。

## 2. 第一性原理：状态机只有三个客户问题

一个 24 小时在场的监理，用户看它的灯时只可能问三件事：

| 问题 | 谁来回答 | 形态 |
|---|---|---|
| Q1 我现在有风险吗？ | **灯**（粗，4 值） | 颜色 |
| Q2 如果有，损失是什么？ | **清单**（细，可展开） | 条目 |
| Q3 我该做什么？ | **动作**（一条，可点/可照做） | 动词 |

任何第四问（"多严重？""为什么？""以前有过吗？"）都是**二级信息**，不该占灯。

由此得出一条判据：**灯的语义就是"要不要现在停下手里的活"**。它不是一个
严重度刻度，是一个**开关**。开关只有四个位置：不适用 / 不用 / 稍后 / 现在。

> 这四个位置在模态上是穷尽的（不适用 · 否 · 将来 · 现在）。所以"四色"不是
> 我们选了四这个数，是**时态只有这四种**。任何第五种想挤进来，都会落进这四类
> 之一——那就说明它不是新颜色，是新成因。

## 3. 编码论：为什么 3 个灯值必然不够

**定理（不严谨但够用）**：要让用户"看一眼就知道该做什么"，视觉可区分格数
必须 ≥ 动作等价类数。

- 现行：动作类 7 个（无 / 知情 / 修缺口 / 装配 / 拉起 / 确认 / 核对重装），
  视觉可区分 **3** 个（红/黄/绿）。⇒ **必然有动作被压平**，实测压平的是
  最危险的那一组（"有缺口需修" 与 "干净" 同为绿）。
- 新模型：动作类 7 个，成因 **7** 个（与动作一一对应），灯 4 个 +
  成因词 7 个 ⇒ 视觉可区分 **7** 个（词是视觉的一部分，见 I6）。

**关键**：颜色不必等于成因数。颜色管"什么时候做"，成因词管"做什么"。
两者合起来才构成"视觉可区分"。旧设计的错误是**用一个维度同时管这两件事**。

## 4. 新模型

### 4.1 模式层（不是运行态）

模式回答的是「**这个结论代不代表生产担保**」，不是"此刻怎么样"。

| 模式 | 含义 | 灯 |
|---|---|---|
| `unarmed` | 没装（默认全关，产品第一原则） | **不亮**（灰）—— 没装配就没有担保可给，任何颜色都是编的 |
| `drill` | 演练（自研迭代 / 非生产构建） | 亮，但带「演练」标；颜色照算，明确告知不代表生产 |
| `armed` | 执勤 | 亮，生产语义 |

> **灰色不是一种灯色，是灯没通电。** 这个隐喻解决 F3：`off` 需要一个颜色，
> 是因为把它当成了灯的一个取值；正确做法是它根本不在灯上。

### 4.2 三轴（仅 armed / drill 下有效）

| 轴 | 取值 | 含义 | 数据来源（**全在账本四字段里，不需要新埋点**） |
|---|---|---|---|
| **值勤** `duty` | `on` / `at-risk` / `off` | 在岗 / 在岗但即将失去（粮将尽、心跳将断）/ 不在岗 | 进程＋心跳＋自启＋`granary` |
| **可信** `trust` | `sound` / `unsure` | 我能证明我在守 / 我证明不了 | 版本比对＋自检＋链完整性 |
| **后果** `harm` | `none` / `some` / `unknown` | 无未修复缺口 / 有（可列清单）/ 统计不出来 | `breached` 中 `recovered=False ∧ 未关闭` 的记录 |

**两个刻意的设计决定：**

1. **`harm` 的判据改成「是否已恢复」，不再是时间窗。**
   `recovered` / `state ∈ CLOSED_STATES` 才是"过去时"。一条三天前发生、
   至今没修的缺口，此刻依然成立 —— 它必须红。这既修了 F1，也不违反
   0.39.0 铁律（铁律管的是"已恢复不许冒充此刻"，本模型严格遵守）。
2. **`trust` 与 `duty` 正交。** 在岗但不可信（代码对不上）与不在岗是两件事：
   前者"我可能守不住"，后者"没人守"。旧模型把它们合在 `R0` 一个词下，
   动作却完全不同（核对重装 vs 拉起）。

### 4.3 灯 = 纯函数（顺序即优先级）

```
灯(mode, duty, trust, harm) =
    grey    if mode == unarmed            # 灯没通电
    red     if harm in (some, unknown)    # 有后果 / 后果说不清（按最坏算）
    red     if trust == unsure            # 证明不了自己在守
    yellow  if duty in (at-risk, off)     # 值勤受损，且无损失
    green   otherwise
```

纯函数带来的三个直接好处：I1（恰好一个主态）**自动成立**；可穷举验完备；
可以给"灯的取值"配一条只断言函数性质的判据（不依赖具体文案）。

### 4.4 完备性证明（54 格，可复跑）

`3 模式 × 3 值勤 × 2 可信 × 3 后果 ＝ 54 格`。探针实测结果：

| 灯 | 54 格内出现 | 其中逻辑可达 |
|---|---|---|
| 灰 | 18 | 1（未装配时三轴无观测值，18 格折叠为 1 个视觉态） |
| 绿 | 2 | 2 |
| 黄 | 4 | 4 |
| 红 | 30 | 12 |

19 个逻辑可达格 → 7 个成因 → 4 个灯。探针断言全绿（I1–I6、无空灯、无装饰色、
动作不共用、「失守」只在 `absent` 一格）。

> **18 格折叠不是"不完备"**：未装配时没有任何探针在跑，三轴根本没有观测值，
> 强行给它们填值是另一种编造。完备性的要求是"每一格都有**定义好的**归属"，
> 不是"每一格都必须出现"。
>
> 反过来，**代码仍须能兜住这 54 格全部**（集合外显式降级、绝不打绿）——
> 所以探针数的是"54 格全有归属"，而不是"19 格"。

## 5. 成因与动作：一个词一件事

| 灯 | 成因 | 状态词 | 动作 | 一句话（示例，过 STE100） |
|---|---|---|---|---|
| 灰 | `unarmed` | 未启用 | 装配 | 监理还没开启。开启后才会拦、才会记账。 |
| 绿 | `ok` | 值守中 | 无 | 监理在岗。 |
| 黄 | `paused` | 暂停中 | 拉起 | 监理停了一会儿，这段时间没有东西经过。 |
| 黄 | `draining` | 快没粮了 | 补粮 | 粮还够用 3 天。用完监理会停。 |
| 红 | `breach` | **有缺口** | 按清单修 | 有 2 处缺口没修。最早一处是 3 天前。 |
| 红 | `blind` | **看不清** | 核对／重装 | 我证明不了自己在守。 |
| 红 | `absent` | **失守** | 拉起＋查损 | 监理不在岗。这段时间放过 2 件。 |

**合并的唯一标准是「动作是否相同」，不是「处境是否相同」。**

这条标准是整份设计的方法论核心。旧设计按"处境"分，于是把 7 个动作不同的
处境压成 3 组；新设计按"动作"分，于是 `breach` 收了 4 格、`blind` 收了 3 格
—— 它们各自的动作完全一样，**不需要区分**。

> 设计过程中的自证：我第一版按处境细分，造出了 `blind`（不可信）与
> `unknown-harm`（后果统计不出来）两个成因。探针立刻报「`blind` 逻辑可达 0 格」
> —— 因为**不可信的定义就是"统计不出后果"**，两个词指一件事。
> 当场删掉 `unknown-harm`。这就是"死词"的机器自证，不是靠人读出来。

## 6. 「失守」的归位：从伞形词降为精确成因

创始人 2026-10-06 裁定：「**失守必须说得出损失**」。这条裁定当年只落到了
"缺岗"这一条路径上，`warn`（认不出）是它留下的漏洞 —— 说不出任何损失，却与
`down` 同灯同词。

本模型把这条裁定**推广为结构性约束**：

| 处境 | 旧词 | 新词 | 说得出的损失 |
|---|---|---|---|
| 不在岗 ∧ 有损失 | 失守 | **失守** | 有（可列清单） |
| 在岗 ∧ 有损失（漏了） | 失守 | **有缺口** | 有（可列清单） |
| 证明不了在守 | 失守 | **看不清** | 说不出 —— 所以不叫失守 |
| 不在岗 ∧ 无损失 | 注意 | **暂停中** | 无 |
| 粮将尽 | 缺粮 | **快没粮了** | 无（是预告） |

⇒ 「失守」从**3 件事共用**降为**1 件事专用**。这才是"失守太重"的根治：
不是给它换个轻词，是不再让它给三件事当名字。

> 这也回答了上一轮那个建议为什么不该采纳：「缺位／离岗」不是「失守」的轻化版，
> 而是它的**上位概念**（同时覆盖红灯与黄灯）。换过去会让"监理不在岗"有两种
> 叫法，而读者分不出哪种更严重 —— 正是 2026-10-06 那条裁定要消灭的形状。

## 7. 与品牌的关系：五态 → 能力谱（不是废弃）

品牌五态（值守 / 注意 / 拦截 / 缺粮 / 失守）讲的是「**监理的五种作为**」，
是能力叙事；运行灯讲的是「**此刻什么情况**」。这是两个对象，过去被绑成一张
词表，于是：

- `L2 拦截` 在生产点不亮 —— **因为它本来就不是灯**：拦住了就是没损失。
  它是"我干了活"的记账，不是"你要停手"的信号。0.51.0 的"info 不抬灯"
  不是妥协，是这个结构的必然结论。
- `Ls 缺粮` 移出主灯 —— 同理：它是"即将失去值勤"，本模型给了它明确位置
  （`duty = at-risk`，黄灯，动作补粮）。
- `dev 研发中` 移出主灯 —— 它是**模式**，不是态。

**⇒ 三态退出的原因各不相同，但方向一致：它们都不是"此刻的风险"。**

| 旧五态 | 在新模型中的位置 |
|---|---|
| 值守 | 灯绿 · `ok` |
| 注意 | 拆开：`paused`（黄）／`blind`（红）／活动计数（绿，不抬灯） |
| 拦截 | **活动层**：不抬灯，进"期间摘要"与计数 |
| 缺粮 | 轴一 `at-risk` ⇒ 黄 · `draining` |
| 失守 | 红 · `absent`（严格限定） |

品牌叙事照旧可以说"监理做五件事"，但那五件事是**能力**，不是灯值枚举。
这与 0.51.0 已经开始的通道分工是同一条路线，本件只是把它推到底。

## 8. 对外呈现：一屏三问

```
┌─────────────────────────────────────────────┐
│  ● 有缺口        有 2 处没修。最早一处是 3 天前。 │  ← 灯 + 一句话（Q1/Q2 概览）
│                            [看这 2 处 →]     │  ← 动作（Q3）
└─────────────────────────────────────────────┘
```

三条硬规矩（吸收 0.53.5 已定的两条，加一条）：

1. **标签说过的不再说第二遍**（标签"值守中"⇒ 正文不许写"正常/在岗"）。
2. **红/黄态不许有玩笑**；主语只许监理；一句最多一个括号、一个数字。
3. **灯与话必须同源**（修 F2）：那句话由**成因**生成，不由姿态生成。
   姿态只是成因的输入之一 —— 同一条路径，不许再有第二条。

## 9. 时间片：`scope` 是视图，不是态

0.39.0 裁定"失守不回溯"方向正确（避免假红灯），代价是真的：用户睡 8 小时，
期间出过一次 R0 并自愈，早上看到绿灯，除非主动点开收件箱否则不知道。

**本模型的解法：时间不进灯，进视图。**

| scope | 灯怎么算 | 出现位置 |
|---|---|---|
| `now`（默认） | 只看未修复/未恢复 | 主灯 |
| `since-last-look` | 同样公式，但 `harm` 换成"期间内发生过的（含已自愈）" | **独立的期间行**，不抬灯 |

理由：**"过去发生过"不影响"此刻要不要停手"**。硬把它塞进灯，就会回到
0.39.0 之前那个"哨兵好好的、灯显示失守"的假红灯。

期间行的文案示例：「你上次看过以后出过 1 次失守，已经恢复。要看吗？」
—— 口径与账本 `day_counts()` 同源，不另造计数。

## 10. 多维压力测试

| 维度 | 考验 | 本方案的回答 |
|---|---|---|
| **信息论** | 灯能不能编码所有需要区分的情况 | 灯只编码"何时做"（4 值，模态穷尽）；"做什么"由成因词承担。可区分 7 组 ≥ 动作类 7 |
| **认知** | 用户看到灯要做几次判断 | 1 次（颜色）＋ 0 次（词已给动作）＋ 可选 1 次（看清单） |
| **安全** | 不确定时是否 fail-closed | `harm=unknown` 与 `trust=unsure` 都判红。**没有一条路径允许"不知道"落到绿** |
| **审计** | 每个结论能不能复算 | 三轴分别来自 进程/心跳/自启、版本比对/自检/链、账本 `breached` 中未恢复项。**不需要新埋点** |
| **同源** | 同一事实是否唯一实现 | 灯是纯函数，成因是它的唯一分支；文案由成因生成（修 F2 的根因） |
| **演化** | 新增一种情况要改几处 | 只加一个成因（词＋动作），**不改灯**。旧设计每加一种都要问"算不算失守" |
| **兼容** | 现有六态键、判据锚怎么办 | 六态键**整体保留**为成因键/能力键（`R0`/`L1`/`Ls`/`L0`/`dev` 仍在两张表里）⇒ 0372 `S09 键不可撤` 不动 |
| **多宿主/多项目** | 一个灯管几个项目 | 灯是**全局**的（监理只有一个进程，要么在守要么不在）；**缺口清单分项目/分宿主**。灯管子，单子分行 |
| **首次使用** | 新装第一屏 | 灰"未启用"＋一句"还没叫我来"。灰不是警告，是默认全关这一产品原则的正常呈现 |
| **离线** | 探不到怎么办 | `trust=unsure` ⇒ 红"看不清"。**不折叠成绿**（探不到 ≠ 没问题），也不冒充"有人守" |
| **合规** | 对外词是否会夸大 | 失守严格限定为"没人守+有损失"，是保守用法；不给无损失的缺岗扣"失守"帽子 |
| **可译性** | 词能不能出中文本地化 | 有缺口/看不清/暂停中/快没粮了 都比"注意/失守"好译（附带好处，非理由） |

## 11. 判据与负控设计

每条不变量都要有**可执行判据**，且每条都要有"删掉它就红"的负控（本仓纪律）。

| 不变量 | 判据形态 | 负控（必须判红） |
|---|---|---|
| I1 恰好一个主态 | 断言 `lamp()` 是纯函数：同输入两次调用等值；返回值 ∈ 4 值集 | 注入返回两个值的假实现 |
| I2 完备 | 遍历 54 格，断言每格有 (灯,成因,词,动作) 且非空 | 从成因表删一个键 ⇒ 必红 |
| I3 无空灯 / 无装饰色 | 断言 4 个灯值各至少 1 个逻辑可达格 | 把 `grey` 的成因删掉 ⇒ 必红 |
| I4 动作分派 | 断言 `ACTION_OF` 是**单射**（一个动作只服务一个成因） | 两个成因共用一个动作 ⇒ 必红 |
| I5 看不清不折叠 | 断言 `trust=unsure` 在 armed 下必红 | 让 unsure 落到绿 ⇒ 必红 |
| I6 颜色与文字同权 | **逐渲染点**断言：灯色变量与状态词同时匹配 | 复现 F3（off 用 `--l0`）⇒ 必红 |
| 词归位 | 断言「失守」只出现在 `absent` 一格 | 给 `blind` 用「失守」⇒ 必红 |

**I6 的特别说明**：本仓已经栽过四次"四个渲染点只锁一处，另一处天然全绿"
（favicon／托盘／漂浮哨标／桌面快捷方式）。I6 必须**逐渲染点各一条断言**，
不接受"抽一个代表点验过就行"。这与 0380 的 S04/S08/S09/S15 是互补关系，
不取代它们。

**判据落地时机**：探针现在**不是**判据（它自带参考实现，是设计验证）。
落地时按闸五同源，断言改为 `import` 产品函数，探针退役。

## 12. 迁移路径（六步，每步独立可验收）

| 步 | 做什么 | 验收（可实测） | 停下会留下什么 |
|---|---|---|---|
| **一** | 把模式层从灯里剥出来：`off`→不亮（灰）、`dev`→「演练」标 | 实渲 `_bar(posture={'state':'off'})`，灯点变量≠`--l0` 且词「未启用」 | 无半成品（只是颜色与标记） |
| **二** | 落四轴数据模型 `situation()`；旧 `current_state()` 改为它的派生（兼容层） | 对拍：旧 API 输出与派生结果逐格一致（19 格） | 无（兼容层保旧接口） |
| **三** | 红灯成因分化：失守 / 有缺口 / 看不清，各配动作 | 三种成因在页面上文案与动作不同；F1 转绿（未修复缺口必红） | 无（颜色已对，只是词更准） |
| **四** | 文案与话同源：那句话改由成因生成 | F2 转绿（灯黄时话不许说"没问题"） | 无 |
| **五** | 期间行（`since-last-look`） | 构造"期间发生并自愈"的记录 ⇒ 主灯仍绿，期间行出现该条 | 无（是新增一行） |
| **六** | 判据迁移：探针断言进 `ci/`，改 import 产品真源，配负控 | 七条负控全部判红 | 无 |

**顺序是依赖关系**：步一是步二的可视前提（先让灰独立出来，才有"模式层"这个
概念可落）；步三依赖步二的成因字段；步四依赖步三（要先有成因才能由它生成文案）。

**每一步都跑全部十套判据 + 活体回读**（闸四），不是只跑步一涉及的那套。

## 13. 代价、边界、不做的事

### 13.1 代价（诚实列）

| 代价 | 量级 | 是否可避免 |
|---|---|---|
| `L1` 一脚分成三份（`paused`/`blind`/活动计数） | 涉及 0372 S04/S08、0380 S15 的锚 | 不可 —— 它本来就是"兼有"，分裂是修正 |
| 品牌五态词表从"灯值枚举"改为"能力清单" | 文档、网站 8 页的叙事措辞 | 不可 —— 但**品牌资产（mp4/ico）不用重做**，颜色值可复用：红/黄/绿沿用 `--r0/--l1/--l0`，灰新增 |
| 用户认知迁移 | 无（**产品还没发布**） | 这是唯一的最佳时机 |

### 13.2 边界（明确不解决）

- **不追求"世界完备"**：`blind` 就是"看不清"的名字。消灭它等于把失败说成成功。
- **不给"没开"加警告色**：默认全关是产品第一原则，灰是正确呈现，不是缺陷。
- **不把活动量抬成灯**：拦住了 = 没损失。抬灯等于把成功报成失败（0.51.0 已证）。
- **不新增第五色**：模态已穷尽（不适用/否/将来/现在）。更急的情况用红色内部的
  动效与文字分层，不靠加色。

|---|---|---|
| P1 | 四色隐喻是否接受（灰=没通电） | 接受。它同时解决 F3 与"未启用算不算故障" |

## 14. 自我证伪：什么条件下本方案应当被推翻

一份不写证伪条件的设计不是设计，是立场。以下任一条成立，我会推翻自己：

1. **若"两个成因动作相同"的情况超过 3 组** ⇒ 说明动作类数远小于成因数，
   7 个成因是过度细分，应回到按动作合并（探针会报 I4 失射）。
2. **若 54 格里逻辑可达格超过 30 个** ⇒ 说明轴之间有隐藏耦合（比如 `trust`
   其实不是独立轴，而是 `duty` 的函数），应减一轴而不是加词。
3. **若用户实测中，用户看到"有缺口/看不清/失守"仍然分不出该做什么** ⇒
   说明成因词没有起到"回答 Q3"的作用，应把动作直接写进状态词
   （"有 2 处要修"），而不是保留名词。
4. **若红/黄/绿的色觉无障碍测试不通过** ⇒ 颜色不能作为唯一区分，I6 必须升级为
   "颜色 + 字形 + 位置"三重编码。

其中第 3 条是我最担心的：`有缺口`／`看不清`／`失守` 都是**名词性**的，
它们比"注意/失守"精确，但**仍然要用户自己想动作**。若要更彻底，状态词应直接
是动词短语（「要修 2 处」「我认不出」「没人守」）。这是本方案唯一可能还要
再往前走一步的地方 —— 我把它列为**待验证**，不冒充已定。

## 15. 一句话

> 六态没错，**错在让一个词干三件事**。
> 四个正交事实分开之后，灯只剩一个问题要回答：要不要现在停手。
> 而这个问题的答案只有四种 —— 不适用、不用、稍后、现在。
