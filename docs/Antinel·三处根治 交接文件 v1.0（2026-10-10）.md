## 1. 项目与背景

### 1.1 这是什么

Antinel 是 PSL 项目下属的**宿主守护与审计工具**：挂在 AI 编码工具的钩子上，对每一次文件写入与命令执行做判定（放行／提醒／拦截／拒绝），并把判定写进一条**只追加、可验真**的审计链。

它自己身上长出来的东西，正在被考虑成一个独立品类：**自带自收敛与自检机制**（多套闸门、数百条断言、基线比对、崩溃与缺失记账）。所以**它的可信度就是产品本身**——一个会假红、会漏判、会自己失效的 Antinel，卖不出去。

### 1.2 三域与路径（别弄混）

| 域 | 路径 | 装什么 | 接手者能不能写 |
|---|---|---|---|
| 代码仓（生产仓） | `D:\psl\poc\antinel-security` | 源码、规则表、闸门、审计库 | **能**（唯一可写区） |

## 5. 根治的机制定义：防复发十道机制

> 这是本次交办的核心：**「杜绝被迭代掉的部分死灰复燃、旧病复发」。**
>
> 先说清楚一件事：**复发不是运气不好，是机制缺位的结果。** 本项目已经实证过的复发形态至少有七次同型（判断描述而非判断事实）、四次连带破坏（修好一处弄坏另一处）、一次失效不可见（节流失效 46.9%（68 / 145），看起来跟正常一样）。靠「下次注意」拦不住它们——只有把它们变成**会红的断言**才拦得住。

### 5.1 元机制：不许新增「基于描述匹配」的豁免通道

| 项 | 内容 |
|---|---|
| 死法 | 一个判定如果靠「这段文本像不像某个名单里的东西」来下结论，那么名单会永远增长，且每加一条就多一条被绕过的路。**这是本项目复发七次的那一个形状** |
| 机制对策 | 判据必须建立在**事实**上：先结构化（这一段到底是什么）、再取目标（真正被操作的是谁）、最后才问许可（能不能动它）。描述与字面只允许用于**展示与解释**，不允许用于**下结论** |
| 已立的硬纪律 | 赋值建起来的变量表，只许用于「看得更清楚」，**不许用于匹配豁免名单**——否则等于把豁免名单的选择权交还给调用方 |
| 落地位置 | 命令判定侧（0.44.0 与 0.46.0） |
| 会红的对照 | 有人往豁免判定里加一条基于字面／子串匹配的通道 ⇒ 闸门必须红。负控做法：故意写一条「把变量展开值拿去匹配豁免」的代码，判据必须红 |

### 5.2 维一：入口唯一性（防绕过型复发）

| 项 | 内容 |
|---|---|
| 死法 | 修好了甲入口，但乙入口是照抄旧写法长出来的；或者老路径根本没被收编。修一处，漏三处 |
| 现状实证 | 唯一按字段更新入口**只有 3 处调用点**，而整份写回有 **6 处**——这 6 处正是绕过者 |
| 机制对策 | 同一语义**只能有一个写入口**；底层写函数只允许被唯一入口调用；新代码想写必须先过它。入口之外出现的直接调用，一律视为缺陷 |
| 落地位置 | 甲层（0.45.0） |
| 会红的对照 | 静态扫描：凡直接调用底层写函数且不在显式白名单内 ⇒ 红。负控：把 6 处里的任一处恢复成整份写回 ⇒ 必须红 |

### 5.3 维二：反向对照（防回退型复发）

| 项 | 内容 |
|---|---|
| 死法 | 后续重构把修复代码删掉了，因为**没有任何东西会因为它消失而变红**。这是最常见的一种死灰复燃 |
| 机制对策 | 每条修复必须配一个**「撤销即红」的反向对照**；并且**必须真的跑过一次、亲眼见过它红**——没见过红的对照是假守卫 |
| 现有基础 | `ci\regression_gate.py` 已有 `--selfcheck`，设计文档明确写了它针对「越修越多」的前两条结构原因（判据没被验过、只验本次修的不验被影响的） |
| 落地位置 | 每一步都要，无例外 |
| 会红的对照 | 把修复**逐字**换回旧写法 ⇒ 对应负控必须红；不红 ⇒ 该负控作废，重写 |

### 5.4 维三：断言打在行为上（防文本锚失效）

| 项 | 内容 |
|---|---|
| 死法 | 断言打在字符串、子串或行号上。代码一改名或一挪位，断言要么静默失效，要么误杀干净产物 |
| 现状实证 | 0.42.1 一次真跑抓到自己**两个假红**，两处都是子串判据（一个是把归档顶层目录项当成「非本版成员」误杀，一个是探针没接正常退出导致成功也被判失败）；v3.0 审核上一版 24 处行号引用，其中 1 处已语义漂移 |
| 机制对策 | 断言打在**函数名／导出符号／可观测行为**上，不打在字面与行号；文档引用用函数名锚并写核验日；**禁止**用语法树的文本转储做子串比对 |
| 落地位置 | 所有新增闸门与判据 |
| 会红的对照 | 给被测对象改名但不动行为 ⇒ 判据必须仍然绿；改坏行为但不动名字 ⇒ 判据必须红 |

### 5.5 维四：既有保护清单（防连带破坏）

| 项 | 内容 |
|---|---|
| 死法 | 修好一处，弄坏另一处。本项目已实证**四次**，最新一次是「读不到就拒写」这道保护，让另一道保护（节流）**静默**失效 |
| 机制对策 | 维护一张**既有保护清单**；每次改动前逐条问「这次会让哪条既有保证变松」；改动必须配「没弄坏别的」的对照。特别要盯**静默**二字：变松不可怕，变松且不出声才可怕 |
| 落地位置 | 每一步的改前检查 |
| 会红的对照 | 保护清单里每一条都有一个仍在绿的判据；改动后全跑，任何一条由绿转红即未通过 |

### 5.6 维五：保护自报（防失效不可见）

| 项 | 内容 |
|---|---|
| 死法 | 保护还在，代码没被改，但它已经不生效了，**而且看起来跟正常一模一样**。只能靠事后的数据统计发现 |
| 现状实证 | 节流失效：短于节流窗的占 46.9%（68 / 145），而落在边界的只有 1.4%（2 / 145）——**不是抖动，是失效**；且状态文件里「上次复活尝试」停在 17.28 小时前，同一时段却拉起了 13 次 |
| 机制对策 | **凡限额类、节流类、保护类机制，必须内建「我今天生效了吗」的自报**：记生效次数与最近一次生效时刻，可被查询。保护不能只在被绕过时才留下痕迹，它必须能证明自己活着 |
| 落地位置 | 甲层与乙层（0.45.0），以及告警预算（0.47.0） |
| 会红的对照 | 人为让保护跳过一次 ⇒ 自报必须显示「未生效」；显示不出来 ⇒ 缺陷 |

### 5.7 维六：运行态生效确认（防「代码落盘即算完」）

| 项 | 内容 |
|---|---|
| 死法 | 代码改了、测试绿了、包也出了，但**跑着的还是旧代码的进程**。于是「已修」是假的，且看起来一切正常 |
| 现状实证 | 0.43.0 未提交、未出包；本机存在常驻进程。历史上出现过两个哨兵进程停留在旧代码上的情况 |
| 机制对策 | 发布验收必须包含**运行态生效确认**：实际加载的模块版本与磁盘版本一致，或明确记录「旧进程仍在、需重启且已重启」。**文件写完不等于修完** |
| 落地位置 | 每一步的收尾，尤其是 0.45.0（动的是常驻组件） |
| 会红的对照 | 故意留一个跑旧代码的进程 ⇒ 验收必须红，而不是报「已修」 |

### 5.8 维七：量具先自检（防量具假红假绿）

| 项 | 内容 |
|---|---|
| 死法 | 量具自己错了：**零覆盖的路径必然是坏的**——一个从未成功执行过的闸门，第一次真跑就坏，且它的红不代表产物有问题 |
| 现状实证 | 0.42.1 的发布验收脚本**从未成功执行过一次**，第一次真跑就坏两处，两处都是假红；本轮文档质检首版 83 项红里，70 项是量具自身缺陷而非文档问题 |
| 机制对策 | 量具必须带**阴性、阳性、阳性二**三类自检样本；新增闸门必须记录「首次真跑」的时间与结果；量具的**显示口径**也要被检（本项目踩过：状态串带后缀时用等号比对，把「正常（活数）」当成了失败） |
| 落地位置 | 所有新增闸门 |
| 会红的对照 | `--selfcheck` 必须同时能给出 0 项（阴性）与大于 0 项（阳性）两种结果；只能给出一种 ⇒ 量具不合格 |

### 5.9 维八：数据版本与迁移（防升级即复发）

| 项 | 内容 |
|---|---|
| 死法 | 加了字段或改了结构，旧数据读不到 ⇒ 走「当空」分支 ⇒ 新保护全程缺席，而且没人知道 |
| 现状实证 | 状态文件要新增版本号字段；另有一处已实证的同类陷阱：产物仓上级存在一个**陈旧清单件**，会让闸门**静默降级**到 17 条兜底集——**假红与假绿两个方向都会骗人** |
| 机制对策 | 读到不认识的版本**必须出声**并走显式分支，禁止「读不到就当空」；兼容路径必须有测试；陈旧件必须能被识别（比对时间戳与版本）并拒绝使用 |
| 落地位置 | 甲层（0.45.0） |
| 会红的对照 | 喂一个旧版本状态文件 ⇒ 必须走显式迁移或报警，静默当作新状态 ⇒ 红 |

### 5.10 维九：文档与代码同锚（防文档漂移）

| 项 | 内容 |
|---|---|
| 死法 | 文档说甲，代码做乙；下一个人照文档动手，从头错到尾 |
| 现状实证 | v3.0 审核发现上一版 24 处引用里 1 处语义漂移；另有跨版本同名小节承载不同内容的歧义 |
| 机制对策 | 文档引用一律用**函数名或结构锚**加核验日，行号只作辅助；数字一律写成「分子 ／ 分母」，不同口径并列时各标来源；有可重跑的核验脚本 |
| 落地位置 | 每次改动同步 |
| 会红的对照 | 跑核验脚本，不符项大于 0 ⇒ 文档已过期，先修文档再动手 |

## 6. 每次改动必须同时交付的四件套

**缺任何一件，都不算改完，不许进入下一步。** 这是「根治」在本项目里的可执行定义。

| 件 | 是什么 | 判据 |
|---|---|---|
| 一 | **正判据** | 改完之后应该由红转绿的那一条；要写明它锁的是哪个已修缺陷 |
| 二 | **反向对照** | 撤销修复即变红；且**必须实测见过它红**（没见过红的是假守卫） |
| 三 | **连带对照** | 保护清单里被影响的每一条仍然绿；改前先问「这次会让哪条保证变松」 |
| 四 | **可观测** | 新增或改动的保护，能回答「我今天生效了吗」；答不出来的，不许上线 |

两条附加要求

- **并发部分不许用协程模拟**，必须起真进程去抢。本项目 46.9%（68 / 145）的短间隔就是现成实绩，这类缺陷用模拟并发测不出来。
- **闸门要快到没有理由跳过**。现有回归闸门约 8 秒，而完整套件要约 24 分钟——**太慢的闸门等于没有闸门**，新增判据不得把日常闸门拖过几十秒量级。

## 7. 分维度机制清单

> 用户要求「各个相关维度的机制层面点都要考虑到」。本节按**系统维度**而不是按任务展开——因为复发经常发生在你这次没盯的那个维度上。每一维都给四件事：现状机制、本次要补的机制点、为什么这才叫根治、如果不做会怎么复发。

### 7.1 命令判定维度

| 项 | 内容 |
|---|---|
| 现状机制 | 命令扫描认危险标志；只读辨析逐段判定；命中即降级或放行并留痕 |
| 本次要补 | ① 首词函数的前缀剥离正则尾部由「必须有空白」扩展为「空白**或到行尾**」，并**引号感知**；② 纯赋值段剥完前缀后无剩余命令 ⇒ 视为中性跳过，不参与否决 |
| 为什么这才叫根治 | 不是给名单加一条例外，而是**换掉判据的来源**：从「这段文本像不像只读」换成「这一段的结构是什么」 |
| 不做会怎么复发 | 每遇到一种新写法就加一条例外，名单永续增长；且任何一种新写法都可能再次连坐整条命令 |
| 已验证 | 5 正例、7 反向对照，0 失败（v3.0 取数时点） |

### 7.2 状态与并发维度

| 项 | 内容 |
|---|---|
| 现状机制 | 严格读取状态（读不到就拒写）；按字段更新入口已有；哨兵主循环启动时读一次状态进内存 |
| 本次要补 | 甲：6 处整份写回收编进唯一入口，**返回值不再允许被忽略**，并加版本号字段做乐观锁；乙：接线既有锁，把「检查」与「记账」合成一个临界区；丙：名片带进程号与启动时刻双因子判活，陈旧名片改名让开，敏感字段用临时文件加原子替换再读回比对 |
| 为什么这才叫根治 | 定性已改：主因**不是**同一瞬间抢（同秒簇只有 1.2%（2 / 160）），而是**秒到分钟级错开的覆盖或静默拒写**（五到六十秒档占 23.4%（34 / 145））。只加锁不对症——**先收编入口，再谈锁** |
| 不做会怎么复发 | 加再多的锁，只要还有一处整份写回拿着旧蓝图往回塞，症状就会回来，而且更难查 |
| 未分离 | 候选一（拒写）与候选二（覆盖）到底哪个导致节流失效，**本轮没分开**，需一次连机观测（读状态文件修改时间序列 ＋ 在拒写分支加留痕） |

### 7.3 删除许可维度

| 项 | 内容 |
|---|---|
| 现状机制 | 只有一份兜底名单做判据 |
| 本次要补 | 两票裁决：第一票问「用户自己声明过这是产物吗」（版本工具忽略查询，**必须带忽略索引参数**）；第二票问「它真能再来一份吗」（向上查找各生态的构建描述文件）。两者做**并且**运算 |
| 为什么这才叫根治 | 从「看名字像不像产物」换成「用户声明 ＋ 可再生事实」；兜底名单**降级**为最后退路，于是它的长度不再是攻击面的增长点 |
| 不做会怎么复发 | 名单继续增长；且「清理构建目录」这类最日常的动作会持续误拦 |
| 三处强化 | ① 用忽略规则的反向语义，不用追踪清单（追踪清单覆盖不到刚写完还没提交的新代码）；② **忽略声明优先于已追踪**（本仓 61 个文件是现成反例）；③ 与「可再生」做并且运算，不是或者运算 |

### 7.4 判定顺序与退出口维度

| 项 | 内容 |
|---|---|
| 现状机制 | 缺显式顺序与「取不到信号时怎么走」的出口 |
| 本次要补 | 显式五步：结构化 → 目标提取 → 是否删除类 → 删除许可两票 → 兜底名单；四个退出口（分不出段／取不到字面目标／版本信号不可用／兜底也无信号） |
| 为什么这才叫根治 | 每一个「不知道」都有**显式且留痕**的去处。静默是复发的温床：**任何一条静默分支，将来都会被当成正常路径** |
| 不做会怎么复发 | 取不到信号时会悄悄走默认拦或默认放，且没人知道走了哪条；下次排查从零开始 |

### 7.5 告警与呈现维度

| 项 | 内容 |
|---|---|
| 现状机制 | 所有提醒同级别、同通道、同盏灯 |
| 本次要补 | ① 给单条规则设滚动窗口预算，超预算**合并成一条汇总且保留原始条数**，窗口结束补记，**不静默丢弃**；② 篡改类分通道（自研迭代导致 ／ 疑似投毒导致），界面不共用一盏灯；③ 界面不许出现无分母的告警数 |
| 为什么这才叫根治 | 治理对象是**配额与分级**，不是规则增减。真信号被稀释成二十分之一（疑似真投毒仅 7.5%（12 / 160））是结构问题，加多少规则都改不了 |
| 不做会怎么复发 | 疲劳持续，于是有人会想到「把那条规则放宽」——**那正是旧病复发的入口**：一放宽，误拦与漏判一起回来 |

### 7.6 数据与口径维度

| 项 | 内容 |
|---|---|
| 现状机制 | 审计库只追加；多种事件混在同一库里 |
| 本次要补 | **实验数据与生产数据必须可分**；跨目录求时间序列一律作废，改**同文件**口径；所有百分比写成「分子 ／ 分母」；总量类数字必须标**取数时点** |
| 为什么这才叫根治 | 本轮第一版统计就踩了这个坑：安全区上锁类记录里混有大量自家硬化套件的临时目录路径，跨目录求间隔得到**虚高**的短间隔，差点把结论带偏 |
| 不做会怎么复发 | 下次有人拿混池数据做统计，会得出一个看起来也很合理的错误结论——**这是最难发现的一类复发，因为数字都真** |

### 7.7 构建与发布维度

| 项 | 内容 |
|---|---|
| 现状机制 | 有构建器、有发布验收脚本、有旧版件自动挪归档的机制 |
| 本次要补 | ① 清掉 61 个误入索引的构建产物；② **必须回答「它们当初为什么能进来」**——答案是忽略规则对已追踪文件无效，所以清理动作必须配一条常驻闸门断言：「构建目录不得出现在索引里」；③ 发布验收含运行态生效确认 |
| 为什么这才叫根治 | 只清一次是打扫，加一条断言才是机制。**打扫完不加断言，下次一次强制添加就全回来了** |
| 不做会怎么复发 | 见上；并且这个维度的复发极隐蔽，因为「清理过了」这件事本身会让人放松警惕 |

### 7.8 闸门与量具维度

| 项 | 内容 |
|---|---|
| 现状机制 | 回归闸门 7 条判据，约 8 秒，带负控自检与提交前钩子；另有十余个版本族闸门件 |
| 本次要补 | 新增判据一律遵循本件 §6 四件套；新增闸门必须记录首次真跑；量具显示口径纳入自检；**不得把日常闸门拖慢** |
| 为什么这才叫根治 | 闸门本身也是代码，也会被改错、也会假绿。设计文档已写明最关键的一条：**第一条判据是「我跑在真表上」**——闸门被骗，后面全部结果作废 |
| 不做会怎么复发 | 闸门假绿比没有闸门更危险，因为它提供虚假的安全感 |

### 7.9 文档与版本维度

| 项 | 内容 |
|---|---|
| 现状机制 | 禁止同名覆盖；改条款出下一版；方案文档有退役声明 |
| 本次要补 | 引用用函数名锚加核验日；数字带分母与时点；有可重跑核验脚本；**方案的每一节在下一版都要有落点**（本轮已做承接对账表） |
| 为什么这才叫根治 | 文档漂移不会让测试变红，所以它是**唯一一类没有任何自动防线**的复发。只能用「可重跑核验」补 |
| 不做会怎么复发 | 下一个人照旧版动手，把已修的东西改回去，还以为自己在照章办事 |

### 7.10 权限与边界维度

| 项 | 内容 |
|---|---|
| 现状机制 | 路径白名单；写入与删除各有判定规则；零删除纪律 |
| 本次要补 | 无新增机制，**但本维度是前九个维度的约束条件**：写入被拦时换落点或请授权，不改宽权限；清理走改名让开；外部路径先定位工作树根，工作树外走退出口，**不许把返回 128 当成「未被忽略」继续判** |
| 为什么这才叫根治 | 一个靠放宽自己权限才跑通的修复，**本身就是一个新缺陷**，而且它绕过的正是产品要守的东西 |
| 不做会怎么复发 | 一次「临时放开」会变成常态，且没有判据会红 |
