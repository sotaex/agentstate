## 6. 严防 happy path：39 条（**本版首次全量列出，1–36 从退役版复原**）

### 6.1 造样本与判据构造（1–8，v1.0）

1. **正控样本来自真实攻击形态，不从 pattern 反推**——反推＝循环论证（AN-025 实证）。
2. **删掉被测代码再跑一次**：判据必须能被「把要守的东西删掉」打红。打不红＝死判据。
3. **期望值不从实现现状抄**：把缺陷钉成判据，判据天天绿，缺陷永远在。
4. **负控必须存在且与正控同源**：只测「干净不误报」不叫测过规则（零覆盖规则的通病）。
5. **空态单列**：「0 条记录」不许等于通过。分母为零时，100 分和「没有问题」是同一种假话。
6. **退出码逐个断言**：不许只看 stdout 里有话就算过（退出码不过管道，`| tail` 会吃掉 rc，已两次假绿）。
7. **故障要真注入**：磁盘满用配额或 mock 真造，不许写「假设失败」的注释代替。
8. **每条降级路径都要有判据证明它走过**：`sidecar`/`dropped` 生产路径 0 处，就是这条失守的实证。

### 6.2 测行为的方式（9–12，v1.1）

9. **【血泪】测行为走产品 CLI，不走库函数**。用库函数必须与 CLI 结果对账；
   签名、返回值元组长度、路径口径三者任何一处错，都会得出反向结论。
10. **被测环境必须与生产同构**。判据跑在被 Antinel 守护的机器上会被自己干扰（锁文件实证）；
    需要隔离 HOME / 清空 PYTHONPATH / 独立 venv，并在判据里**打印被测根**以自证。
11. **新增面必须同批加判据**。修一处、不加一条判据 ⇒ 该修复会在下个版本静默退化（0.55.2/0.55.3 两处修复零判据）。
12. **判据不许把「缺陷形态」只写在注释里**。`scan` 的 `lstrip` 缺陷写在注释里、判据只命中 1 次；
    缺陷形态要有可执行断言（负控：把 `lstrip` 装回去必须红）。

### 6.3 覆盖声明与同源性（13–18，v1.2）

13. **【头号】手工跑通 ≠ 有判据守**。任何一次成功的探查，必须问「结果沉淀成断言了吗」；
    没沉淀的只能记「已探查未守」，不许进完成度分子。
14. **覆盖声明分两级**：「点名」与「真断言」分开写。点名只证明有人提过，不证明有人守。
15. **判据不许抄真源**。规则/命令/版本/文案一律 import 或读文件；负控是把真源改坏，判据必须红。
16. **升级路径必须真装两遍**：先装旧版造数据，再升级，读回来。只读代码不算测过。
17. **对外页面要真跑**。README 承诺的每个数字都从产物里数出来，不从文档抄。
18. **「成功」出口配一个「假成功」负控**。凡返回 ok/True/成功的地方，都要造一个
    「返回成功但事情没发生」的场景，确认它不是绿的。

### 6.4 探针与形状（19–22，v1.3）

19. **探针必须声明排除集**（仓内有 9 类不入 git 的代码副本）。全仓遍历前先写清排除清单并打印。
20. **同名函数先对形状再动手**。参数语义与返回形状不一致时，
    第一件事是确认「我调的是哪个」，不是「结果对不对」。
21. **判据不许只验返回值**。凡是「写」的判据都要回读盘（`exists` + 内容比对），否则守的是函数自己说的话。
22. **可达之后要问「然后呢」**。落盘成功不等于可用：有没有读它的入口、谁消费它、界面能不能看见。

### 6.5 多腿与档位（23–25，v1.4）

23. **多腿判据要逐腿单独跑**。前面那条红了，后面的负控根本不会执行——没验证过的自证等于没有。
24. **夹具要声明平台有效性**。`chmod` 造「不可写」在 Windows 与 root-Linux 下结论相反；
    夹具必须先自证「场景真的造成了」。
25. **「应当态」判据先定档位再写**。红着进正式档 = 阻塞出包；要么进 `negctl`，要么与修复同批。

### 6.6 负控入口与断言宽度（26–31，v1.5）

26. **负控必须走与正控相同的入口**。合成一段坏源码喂给扫描器，只证明扫描器能识别，
    **没证明遍历逻辑正确**——D-40 的三条负控全绿，而遍历只扫了 7/13。
    正解：在**目标目录里**塞一个坏写法，判据必须红。
27. **判据的断言要覆盖它宣称守的全部形态**。「零 `bool()` 包裹」不等于「无静默塌缩」——
    还有 `[0]` 丢字段与直接丢弃两种。
28. **扫描器要过语法形态矩阵**。至少覆盖：属性调用、`from-import` 直调、`if not`、`if`、
    短路、三元、`assert`、别名再调。
29. **扫描面要写进完成判据，并给两种口径**。同一件事 grep 口径与 AST 口径可以差 4 处。
30. **版本迭代做内容合并，不只做扣分点追加**。每次升版先核对旧版独有章节是否还在。
31. **测试计划不替产品定语义**。发现与判定是计划的职责；改成什么行为、要不要改，属产品决策。

### 6.7 合并与计数（32–36，v1.6）

32. **合并要核对旧版独有章节，且必须逐节核对，不能凭印象**。
33. **不许新编编号体系**。新维度接在既有字母序列后面（v1.7 用 AO–AQ），否则追溯链断、且与批次编号撞名。
34. **汇总数一律脚本数**。
35. **丢一个维度和漏一个判据一样严重**（本轮弄丢的「拦/放决策」是产品价值本身）。
36. **声称「已复原／已合并」前，跑一次差集脚本**。没跑就不许这么说。

### 6.8 v1.7 新增（37–39）

37. **「累计条数」必须等于「正文条目数」**。A40 实证：连续七版都写「已累计 N 条」，
    而每版正文只有自己新增的那几条——**没有任何一版数过对数**。
    做法：计数脚本按 `^\d+\. ` 提取，与声称值比对，差一条就不许交付。
38. **探针不得自带一套与判据分叉的模型**。要报判据的覆盖，就 **import 判据的遍历函数**
    （A43：`_probe_v15_surface.py` 自建模型 ⇒ 报出已过期的 7/16）。
    同一事实两处实现，是本项目第一顽症的第一形态。
39. **口径必须随实现一起更新**。判据改一次行为，计划里对应的数（覆盖几条、几个文件、几套件）
    同批重数（A42：D-40 补了 hooks 腿，计划还写 7/13）。
