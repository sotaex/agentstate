# Antinel·0.53.0 监理拉不起来：迭代考古与三道士闸 v1.0（2026-10-18）

> **这份文档是什么**：创始人 2026-10-18 晚说「拉起来监理我看看，我真怕你」，
> 随后批准修两处并追问「这两处是不是迭代过程中新引进的？如果是，如何从机制层面
> 根本解决」。本文记录：① 实测事实；② 两处各自的引入时间（有提交号）；
> ③ 为什么它们能活这么久——**判据在三处替它们背书**；④ 落了哪三道士闸；
> ⑤ 为什么这三道是病族级而非点位级；⑥ 还剩什么没解决（如实登记）。

---

## 一、事实（全部实测，不是推理）

| 观测 | 结果 | 怎么测的 |
|---|---|---|
| 日志说「已重拉」 | `console.log` 里连打 **7 次** | `tail console.log` |
| 8790 是否在听 | **一次都没有** | `netstat -ano \| findstr LISTENING` |
| 日志说「已就位 720x640 @(2240,1264)」 | 枚举窗口 **命中 0 个** | `inbox_window.enum_windows` |
| `spawn_console` 本身能不能起服务 | **能**，0.6–0.8 秒端口就起来 | python.exe 作父、pythonw.exe 作父，各测一遍 |
| `DETACHED_PROCESS` 能不能逃出进程树 | **不能** | 三个 pid（58516／76644／61112）父退后逐一消失 |
| 桌面快捷方式参数 | **完好**（`-I -S "...inbox_cli.py" window`，cwd 正确） | 直接读 `.lnk` 字节，UTF-16 偏移 1117／1145 |

结论一句话：**服务起得来，窗口开得出来，但两者都活不过那条命令**；而两处代码都报了成功。

## 二、迭代考古：两处各是什么时候进来的

| 缺陷 | 引入时间 | 提交 | 性质 |
|---|---|---|---|
| **B 假绿**：`ensure_console` 用 `rec2 or rec` 兜底，没起来也返回旧记录 | **2026-10-13** | `15603a0` B1 值守台常驻 | **首版就带的**，不是后来改坏 |
| **A 不确保 daemon**：`cmd_window` 只 ensure 服务、开窗前不问 daemon 在不在 | **2026-10-15** | `8469eec`（含 `open_console_via_daemon`） | **补丁引进的** |

### 缺陷 A 是一条「只修一半」的补丁

2026-10-14 创始人实测「起得来、活不久」，结论写进了代码注释：窗口必须由
**活得比它久的进程**起，于是 10-15 补了 `open_console_via_daemon`。

这条补丁解决的是「**窗口由谁开**」。它没有解决「**daemon 在不在**」——
而两者缺一不可：daemon 不在时，`open_console_via_daemon` 必然返回 none，
`cmd_window` 按设计降级直起，窗口挂在短命 CLI 名下，秒死。

所以：**修复本身是直的，但它把系统带进了新的失衡** —— 有了正确的路，
没人保证这条路的入口条件成立。

## 三、为什么它能活 5 天：判据在三处替它背书

这一节是本文的重点。缺陷本身不稀奇，稀奇的是**四条相关判据当时全绿**。

| 判据 | 它实际断言了什么 | 它为什么替缺陷背书 |
|---|---|---|
| **W17-a 臂②** | 「daemon 失败 ⇒ 降级直起且返回 0」 | 把**已知会死窗口**的路**定义成合格**。名字叫「不卡用户」，实际是批准坏路径 |
| **W17-b** | 用 mock 把 daemon 出口替换掉 | 「daemon 到不了」这个真实条件被 mock 抹掉，判据在自己的假设里自洽 |
| **0490 W04-b** | 「进程已死 ⇒ `ensure_console` 去重拉了」 | 只看**去重拉没有**，不看**拉起来没有**。假 spawner 会真绑端口，于是永远拉得起来 |
| **W17-d** | 「有桌面却没服务 ⇒ 判红」 | 把**用户没启动**误判成**链路断了**；反过来，服务不在时它红的是环境态，不是代码 |

三种病，各自成立、合起来致命：

1. **合格定义错**（W17-a 臂②）—— 最坏的一种。缺判据只是没看见，错判据是**签字放行**。
2. **夹具抹掉真实条件**（W17-b）—— mock 掉了「daemon 不在」，等于假设问题不存在。
3. **只问过程不问结果**（0490 W04-b）—— 「重拉了没有」是过程，「起来了没有」是结果。

再加一条系统性的：**没有任何判据问「入口链路是否完整」**。W17 系列全部在
`open_console_via_daemon` 这个**函数**上做文章，没人从 `cmd_window` 这个**入口**
往下走完整条链（daemon → 服务 → 窗口 → 用户看见）。

## 四、改了什么（三处产品 ＋ 六条判据）

### 产品

| 位置 | 改动 |
|---|---|
| `inbox_server.ensure_console` | 成功**只由回读决定**：`console_status` 说不在就返回 `None`，不再拿旧记录充数 |
| `inbox_server.ensure_daemon`（新） | 判活 → 拉起 → **等回读确认**；返回 `(alive, pid, started, why)` |
| `inbox_server.spawn_daemon`（新） | 与 `spawn_console` 同一形状（`DETACHED_PROCESS\|CREATE_NO_WINDOW`），**不弹黑窗** |
| `inbox_cli.cmd_window` | 开窗前**先 ensure daemon**；daemon 起不来必须**出声说「活不过本命令」**；服务没起来时如实报原因（不再说「拿不到记录」） |

### 判据（`ci/inbox_guards_0517.py`）

| 判据 | 守什么 |
|---|---|
| **W17-a**（重写） | 臂① 开窗前必须调 `ensure_daemon` **一次**；臂② 委托失败可降级；**臂③ daemon 起不来 ⇒ 必须在 stderr 说「活不过本命令」**，静默降级判红 |
| **W17-e** | 喂什么都不做的 spawner ⇒ `ensure_console` **必须返回 None** |
| **N-W17-e** | 把 `rec2 or rec` 塞进同尺变体 ⇒ **必须判红** |
| **W17-f** | 喂什么都不做的 spawner ⇒ `ensure_daemon` **必须 alive=False** 且给原因 |
| **N-W17-f** | 合成「spawn 即成功」⇒ **必须判红** |
| **W17-d**（修正） | 区分「用户没启动」（SKIP）与「daemon 在、服务没起」（真断链，红） |

### 实机验证（不是 mock）

## 五、为什么这三道是根治，而不是补丁

判据守的**不是这两个函数**，是三个病族：

| 病族 | 士闸 | 以后任何地方犯同型 |
|---|---|---|
| **假绿**：报成功由分支决定，不由事实决定 | W17-e／W17-f ＋ 各自负控 | 任何 `ensure_*` 都可套同一把尺子（当前清单：`ensure_console`／`ensure_daemon`／`ensure_background`） |
| **静默降级**：降级到已知会坏的路径还不说 | W17-a 臂③ | 任何「失败就退一步」的分支都会被迫说清退到哪、坏在哪 |
| **环境态混入代码门禁** | W17-d 修正 | 判据不许把「用户没启动」当成「代码错了」；反之真断链仍判红 |

三条的负控都是「把旧形状塞回去必须判红」——**先证它会红，再信它绿**。

**这不是 happy path 的理由**：happy path 是「针对这个 bug 加一句 if」。
这里改的是**合格的定义**：以前「降级直起」算合格，现在「降级直起且说清后果」才算；
以前「重拉了」算成功，现在「回读在听」才算。

## 六、还没解决的（如实登记，不假装收口）

1. **常驻在本环境无法自证。** 本探针所在进程结束即整树回收（三个 pid 实测），
   所以我只能证「次序与归位」，不能证「明天早上它还在」。真正的常驻由
   创始人双击桌面图标那次自证——那一次走的是 explorer 宿主，不在这个进程树里。
2. **S57（设计要求→判据映射）有一个结构性盲区。** 它只守「设计文件里写过的章」。
   本次两条要求——2026-10-14 的四路实证（窗口必须由长命进程起）、
   2026-10-17 的「桌面启动不许弹黑窗」——**都没有落进设计文件的任何一章**。
   没有章节，就没有条款号，S57 天然看不见。
   修法（未落）：**每条事故结论必须落进设计文件的一章**，否则它无处可守。
   这条比再加十条判据更重要——它管的是「要求有没有安放的位置」。
3. **`daemon` 子命令没有 `--root`**（只有 `serve` 有）。判据用临时中枢时，
   `ensure_daemon` 的判活走的是注入 spawner，不碰真目录；但真做多实例隔离时会撞。
4. **窗口落位仍是右下角且不抢前台。** 全屏应用盖住时用户「看不见已经开了」。
   临时置前靠 `AttachThreadInput`（只 `SetForegroundWindow` 会被静默拒绝）。

## 七、版本与边界

- 版本保持 **0.53.0**：运行态行为有变（开窗前起 daemon），但该版从未出厂
  （PyPI 仍 0.35.1、无 tag、dist 里从未分发），故并入同一版，不出 0.53.1。

  `DETACHED_PROCESS|CREATE_NO_WINDOW`；0353 的黑窗判据是**全仓扫描**（不是列点位），
  新增的 Popen 自动被它管住——实测 78 绿 / 0 红。
- 本轮的证物：`_p_spawn_probe.py`／`_p_spawn_diag.py`／`_p_win_shot.py`／
  `_p_win_focus.py`／`_p_live_proof.py`（一次性，交付前一并归档）。
