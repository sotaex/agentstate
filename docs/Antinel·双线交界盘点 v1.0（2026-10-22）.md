## 4. 交给另一条线的三条（都会让下一轮踩坑）

### 4.1 `host_shield.self_check()` 返回**元组**，不是列表

```
>>> host_shield.self_check()
(True, [])
```

docstring 原文：「返回 (ok, problems)。manifest 缺失 → (True, [])」。

- 《DAG 施工顺序与前置闸门 v1.0》§4 闸门③写的是「`self_check()` 的 `problems==[]`」——
  作为简写可读，但**照字面写判据会拿到元组 `(True, [])`，永远不等于 `[]` ⇒ 恒红**。
  正确写法：`ok, problems = self_check()` 后断言 `ok and problems == []`。
- 更要紧的副作用：**manifest 缺失时它返 `(True, [])`（fail-open）**。
  所以闸门③的第三查（`version` 仍是 `0.50.5`）不能省——只有它能兜住「清单没了」这种情况。
  原文说「三查缺一不可」，实测支持这条：第二查单独绿**不能**证明清单在场。
- 顺带一个同名陷阱：`state_registry.selfcheck()` 返**列表**（0a 验收输出 `[]`），
  与 `host_shield.self_check()` 只差一个下划线、形状不同。将来一定有判据会写混。

### 4.2 `state_registry.py` 进 manifest **没有现成工具**

实测 `_tools_034/_resign_manifest.py --adopt-dev` 的补登名单来自
`host_shield._DEV_GUARDED_CHAIN_FILES`，实测值 ＝ `('ci/freeze_zones.json',)` **一项**。

那个分支的设计意图写得很清楚：「这些件构建器永远不会收（`ci/` 不进 wheel）⇒ 不补就永远红」。
`state_registry.py` 是**根目录产品件、构建器会收**，所以 `--adopt-dev` **补不了它**
（跑一次会打印 `ADOPT-SKIP` 或什么都不做）。

三条出路，按纪律排序：

1. **手工加一行再重签**：在 `psl/manifest.json` 的 `files` 里加
   `"state_registry.py": "sha256:<值>"`，再跑 `_resign_manifest.py` 走主循环复核。
   缺点：哈希值是手算的，属「绕过构建器口径」，要在提交信息里写明。
2. **等出包**：`scripts/build_package.py` 会把它算进 manifest（第 131 行「本构建器写 manifest」）。
   缺点：挡在「本轮不出包」上。
3. **先让它红**：闸门③的第二查会因 tamper 变红，与「problems==[]」的门槛冲突。

⇒ 闸门③在「不出包」前提下**只有第 1 条路**，且属于手工绕行，必须记录。
