# 值守台遗留问题清单与建议方案

> 2026-10-13 · 依据 0.48.5 六批次交付（a9bff3b…c0b1cb4）与 §6.1/§6.2 运行态验收的**实测证据**列出，不做推测性扩项。
> 分级：**A = 真缺陷候选**（有实测复现路径）；**B = 产品债**（影响可用性，非缺陷）；**C = 流程/量具债**（本次实证踩到）。

---

## A1 · 姿态心跳按仓库 `.psl/audit` 链作用域化 —— 仓库搬家/复制即「假失守」

**证据（本轮两次复现）**：改动前代码放进 git worktree（`D:/_ant_accept/before`，无 `.psl/audit`）渲染，同一时刻、同一 CWD，页面显示「**失守**：心跳断档 38 分钟」；把真实仓库的审计链复制进 worktree 后，同一服务立刻恢复「**拦截**」。诊断句自己都说「**哨兵进程在**，但心跳断档」——进程活着，仅因心跳链不可达就被判 `down`(R0)。

**危害**：用户备份/换盘/重命名 `antinel-security` 目录，或从 wheel 安装运行（site-packages 里没有审计链）⇒ 值守台亮红灯报失守。这与本项目立项原词直接冲突——「如果真失守不会带来明显不利后果，那就跟假失守没啥区别」；反之假失守也一样有害。

**建议方案**：`guard_posture` 分层判读——
1. 哨兵进程不在 ⇒ `down`（真失守，现状不动）；
2. 哨兵进程在、但 audit 链**不可发现** ⇒ 新态 `unknown`（L1 盲区「查不到心跳」），原因句明说「心跳链不可达（仓库被移动/打包运行？）」，**绝不渲染成 R0**；
3. 两者皆可达、age 超阈 ⇒ 维持现状 down。

**配套判据**（进 0372）：`_posture_cases` 新增 `blind` 现场（在岗 + `hb=(None,None)` + `up=None`），断言姿态 `unknown` 且文案不点红；新判据 **S19/N-S19**（登记四字段含 `sentinel_audit_dir`、注册目录优先、legacy 显式两分支带 `heartbeat_source`）；负控三种变异（抹注册字段 / 陈旧链冒充盲区 / 不在岗冒充盲区）全被抓到；撤销实测（内存级改回旧行为）S19 实测见红。

**修复状态（2026-10-13）**：✅ 已修并入库。落地比建议多走一步治本——不只做"分层渲染"，而是**消灭二义性本身**：哨兵启动经 `_register_sentinel_start()`（state 唯一写入口）自注册 `sentinel_audit_dir`，心跳目录解析收敛到 `_sentinel_heartbeat_chain()` 一个实现（注册值优先，legacy 显式两分支）。判据落 0372（S19/N-S19，20 绿），连带 0360/0353/0362/0380/0470/0490 与交付闸门 30 套全绿。顺带把 0363 R07 改成探针注入（原来裸跑真实机器状态，哨兵被会话回收后恒红——判据在看机器天气）。

## A2 · 托盘与 Web 状态词不一致（§6.2.4 验收项实测不通过）

**证据**：同一枢纽、同一时刻，`inbox_tray.sync_from_items` 后 state=**R0**（tip「有过失守 · 哨兵在岗」），Web 头部显示「**拦截**」。托盘走旧合并读（历史 R0 抬灯），Web 自 0.39.0 起走 `current_state`（历史 R0 一律不抬灯）——同一事实两套口径，正是本仓铁律禁止的形状。§6.2.4「两个界面不许各说各话」目前不过。

**建议方案**：托盘 `sync_from_items`／`shield_state` 改调唯一实现 `M.light_explain()`（与头部同一次调用产出 label/reason），tip 由同一函数拼；`inbox_tray.SHIELD_SUFFIX` 维持。**判据 W-03**（进 0490）：同一夹具同时渲染页面与托盘 state.json，断言两边状态词逐字相同；负控＝把托盘改回合并读即红。

**修复状态（2026-10-13）**：✅ 已修并入库。产品（`inbox_tray.py`）：① 新增 `probe_posture()`（托盘侧唯一探针，`shield_state` 与 `sync_from_items` 共用，不再各探一次）；② `sync_from_items` 的事件态/状态词改取 `M.light_explain()`（`state`＝`ex["state"]`、`label`＝`ex["label"]`），tip 首段即页面那个词，粮的读数与页面同根（都调无参 `granary_now()`——连根不一致会再漂出 Ls 只在一边亮）；③ `write_state` 增 `label` 字段（缺省从 state 现算），`refresh_state` 增 `posture` 可注入（判据不许看机器天气，0363 R07 教训）。判据 W-03/N-W03 落 0490（28 绿）：两现场（账内 R0 不抬灯 ⇒ 值守中；账内 L2 抬灯 ⇒ 拦截）逐字比对页面标题与托盘 label/tip，负控＝把托盘换回旧合并读（`_OldM` 代理），实测红且咬在「账内 R0」现场。连带修：P5 两条（`inbox_guards.py`）改显式注入姿态并随 0.39.0 口径改期望；0353 `n_tray_refresh_is_not_a_noop` 期望改 `light_explain`；**另修两处陈旧判据**——P3「空态渲染」仍断言 `<video`（批次4 戊1 已换 logo.svg ⇒ 恒假，而旧 P 套不在交付闸门清单里所以没人看见）、P12「有事状态可点开看明细」负控（收件箱筛选条本就恒有 `f=action` 标签页 ⇒ 负控必然无效；改为深度平衡剥掉 `<div class="filters">` 后再断言）。旧 P 套现 137 绿 / 0 红、负控活力 137/137。

## B1 · 值守台无常驻入口（服务随会话生死）

**证据**：本次服务是我在代理会话里拉的前台进程；会话结束即停。`~/.antinel/host_shield.json` 里有 `_task_installed_last: true`，说明计划任务装过，但当前本机 8790 无监听（上一轮清场时确认过）。

**建议方案**：核实 `antinel inbox daemon` 本机可跑通并常驻（或修复计划任务自启）。验收标准：杀掉服务进程后 60 秒内自行恢复，端口/URL 不变；同时把「起服务+开窗」收成一键（`antinel.cmd` 已有雏形）。

## B2 · 端口漂移静默换端口

**证据**：`_bind_first_free(8790)` 在被占时改用系统临时端口，无提示。用户手输 `127.0.0.1:8790` 打不开，且无从得知实际端口（本轮 before/after 对比时我就同时开过 5 个实例，全靠读 url 文件）。

**建议方案**：落盘 `~/.antinel/console/url.json`（实际端口 + token + pid + 启动时间）；被占时 stderr 明说「8790 被 PID x 占用，已改用 y」；托盘 tip 带实际端口。

## B3 · 口令 token 在 URL query 里

**证据**：`?t=<32位口令>` 每次渲染都带。0.36.2 特意让 run_id 从 token **派生**避免凭据进标题，说明团队在意这个；但 URL 本身仍会进浏览器历史/书签/日志。

**建议方案**（可选，非本轮范围）：`_head` 渲染时种 httpOnly cookie，后续请求不再依赖 `?t=`；判据锁「token 只出现在首次 Set-Cookie，不出现在后续 URL」。

## C1 · 负控变异参数不配 ⇒ TypeError 冒充负控

**证据**：本轮 N-U13（戊1 负控）首跑 💥——我把头部 mp4 形态加回时 args 少给一个 `M.STATE_VAR[st]`，变异渲染抛 `TypeError: not enough arguments for format string`。负控的职责是「证明正判据会红」，结果它自己先崩了——量具故障伪装成产品问题。

**建议方案**：负控模板化为两步——① 前置断言「变异模块能 import + 最小渲染不抛」（不过即判负控自身失效）；② 行为断言（变异可观测 + 真实现不带该形状）。两步都绿才算负控有效。

## C2 · 判据自己 docstring 里的锚点字面被自己的判据扫到

**证据**：D-30 同款本轮又应验至少三次——0490 docstring 复述注入锚点串、CSS 注释复述「本机 · 127.0.0.1」（U-10 误红）、`M.reading_note()` 字面被当调用点（U-01 多数出 4 个调用点）。判据扫渲染产物/源码时，把量具自己的注释也扫了。

**建议方案**：① 扫渲染页的判据统一先剥 `<details>/<style>`（U-03 已有 `_body_without_terms` 先例，推广）；② 源码锚点一律「逐字取自磁盘 + AST 抽取」，不手写进 docstring；③ docstring 扫描范围沿用 D-30 的 `_docstring_corpus()` 白名单机制，别全文扫。

## 环境限制（非产品问题，仅登记）

- 托盘 GUI（`tools/tray.ps1` NotifyIcon）在代理会话起不来（无交互式窗口站，`Application.Run` 直接退出）——帧 7 以托盘图标资产 16×16 + stale 字段取证替代；真实桌面会话可正常起。
- Edge `--app` 窗口只在**后台任务**的进程树里能存活：前台命令结束时其 job 会连 Edge 子进程一起回收。当前这个窗口由后台任务保活（服务同在 `127.0.0.1:8790`）。
