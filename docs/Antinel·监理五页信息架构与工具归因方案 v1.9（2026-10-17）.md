## 2. 页数推演：为什么是五页

**页的立案标准**：一个高频用户问题 ＋ 独立时间窗 ＋ 独立行动集，三者齐备才配一个页。

| 候选问题 | 频率 | 行动集 | 判决 |
|---|---|---|---|
| a. 我有没有中招？谁在偷数据？ | 首次＋每周/月 | 重跑、看裁决、布金丝雀、导出一页纸 | ✅ **独立页（体检）**——独立旅程、独立时间结构（时点快照） |
| b. 现在有什么要我处理？ | 最高 | 知道了/忽略/放行裁决 | ✅ 收件箱 |
| c. 今天/昨天怎么样？ | 每日 | 钻取、导出一页纸 | ✅ 日报 |
| d. 之前每天都发生了什么？ | 低（取证） | 按天/按月翻、认领 | ✅ 账本 |
| e. 监理自己靠谱吗？ | 低（出事时） | 复核、重拉 | ✅ 运行状态 |
| f. 花了多少钱？还能站多久？ | 中 | 设预算、记账 | ❌ 不立案：事件（预算告警）进收件箱，余量进运行状态，明细走 CLI——"钱"与"安全"同属自省，拆页割裂 |
| g. 给领导交差 | 低 | 导出 | ❌ 产出物不是页：日报/体检的"导出一页纸"按钮 |
| h. 跨工具汇总 | 中 | 筛选 | ❌ 日报排行的工具分布即页面版 |

**否决"粮草独立页"的理由（E198 纪律）**：粮草账（积分/元）与审计账（条/次/件）**异质单位**，
绝不能混进账本；而它的高频行动（设预算）已有 CLI 与事件通道，页级行动集不足。

**五页 = 体检、收件箱、日报、账本、运行状态。** 页序即旅程序（首次用户第一眼是体检）。

## 3. 双受众界面原则（为人服务，也为 Agent 服务）

Agent 不读网页；网页不给 Agent 看。但双方必须读**同一份事实底座**：

| 原则 | 内容 | 现状 |
|---|---|---|
| ① 同一底座、两种渲染 | 页面渲染给人；`--json`／MCP 渲染给 Agent。共用 glossary／规则表／宿主表真源，不许第三份实现 | glossary 已是唯一真源 ✅ |
| ② CLI 人话＝Agent 转述底稿 | Agent 替人跑命令后**转述**给人——所以 CLI 文案与页面同一套用词、同一套人话纪律；`--help` 的 Agent 话术表就是用户话术表 | 已具雏形，随 §5 机制统一 |
| ③ 页面能说的，命令都能给 | 可验证性的机器侧：每个页面事实都有 CLI/JSON 出口（反 packed：命令能给的页面都该能看） | host-scan --json 等已有；补缺口 |
| ④ 被监理的 Agent 也是用户 | 钩子拒绝消息是 Agent 的"界面"：必须人话＋可行动（"改用 xx 路径／见规则 AN-012 的大白话"） | post_tool_use 已人话化，纳入同一套判据 |
| ⑤ SKILL.md 是 Agent 的"首页" | Agent 的装机说明书；与控制台同一套术语真源 | 已随包 ✅ |

## 5. 三层机制（先立尺子，再改产品）

### 5.1 机制一 · 同一事实单一出口
- 事实→家映射固定：状态词→顶部条；事由名→标题；为什么→第二行；怎么办→展开区；
  工具→徽标；计数→其独占页（§4.5）。
- 机器检查：**句子指纹**（去数字标点后 ≥8 字片段同页出现两次即红）＋**数字唯一**
  （同值同口径只渲染一次；同值不同口径必须各带限定词）。
- 负控：故意在第二行复述时间 ⇒ 必红（现网活体：L2 条目行首与第二行各写一次时间）。

### 5.2 机制二 · 正确性
1. 数据保真：链→Alert 字段不丢（实锤：链上 107,955 条带 host，Alert 层全丢且无人守）。
2. 口径唯一：工具维度扩进 `M.day_counts`，渲染层禁自算。
3. 声明可验证：页面上的规则号必须存在于规则表、工具名存在于宿主表、数字能追到结构化数据。
4. 失败要说出来：核验没跑成 ≠ 通过。

### 5.3 机制三 · 品质性
1. 鸟语黑名单：环境变量名、内部实现词（口径/归并/徽标/宿主/投影）、无解释英文缩写；
   白名单：规则编号（创始人 2026-10-17"规则编号肯定也保留"）。
2. 长度：条目第二行 ≤90 字（实测现 100+）；单句 ≤40 字。
3. 指代显式（F57）；同屏重复率。
- 全部判据化并入既有套件（A2 常驻 29 已满）：渲染类→0490，文案类→0360 W 族，数据类→0353。

## 11. 用量统计与第一版上线时序（创始人 2026-10-17 追问：时长／问答数／token／积分，监理基础工作）

### 11.1 实查事实（回源文件＋产品实测，三条）

1. **文档记录过**：`AUDIT_SCHEMA.md:315` 自认——「成本/token 消耗（三问三答 A 族）尚未进入账本——`transcript_path` 已随事件到达但 v0.22.0 未使用，属 v0.23.0 范围」。
2. **产品实况比文档更进一步：token 采集已在跑**——`post_tool_use.record_usage_delta`（`hooks/post_tool_use.py:240`）从 transcript 割取 token 事实、追加链式 `usage_delta` 记录（带 `usage_collect` 总开关，fail-open）；`_accumulate_budget_state`（v0.27.0 notice_budget）按会话/项目日累计到 `.psl/state/session_usage.json`——**本机实测 9 个会话、进出 token 均在记**。文档落后于产品。
3. **真正的缺口不是「记」而是「看」**：全库检索，日报/账本/运行状态/CLI **没有任何一处消费** `usage_delta`——数据躺在链上，用户看不见。另两处小缺口：`usage_delta.host` 恒空串（工具归因没接上）；问答数/使用时长可从链上 session 首/末 `ts` 与 transcript 派生但未派生。

### 11.2 归置原则（三条）

1. **用量是账本的「成本轴」，不是新页**——粮草页否决逻辑（E198 异质单位）同款延伸：进日报与运行状态，不立第六页。
2. **两本账纪律不动**：`credits`（宿主积分，手动快照/预测/对账）与 `granary`（哨兵口粮）分开；「Cost is NEVER written」是刻意设计（成本绝不自动写，防口径污染），用量展示只显示 token 事实与手记积分，不自动折算钱。
3. **先记后看**：埋点不可逆（今天不记，历史永远缺）而展示随时可补——所幸「记」已经做到且默认在跑；因此第一版上线**不欠任何埋点债**，只需保证 `usage_collect` 默认开启、不误关。

### 11.3 时序（上线优先，用量展示分期）

| 版本 | 用量相关动作 | 其余 |
|---|---|---|
| **0.53.0（第一版上线）** | **零新增埋点**。唯一要求：`usage_collect` 默认开；判据加一条「usage_delta 在 7 天链内出现（有 AI 编程活动时）」防静默断流 | 五页 IA＋工具归因，按 §10 照旧 |
| **0.54.0（上线后第一迭代）** | ① 日报尾部「用量一行」：今日 token 进/出＋活跃会话数（从 `usage_delta` 唯一实现派生，不新写第二份计数）；② 使用时长/问答数派生（链 session 首/末 ts，不新埋）；③ 运行状态「粮草」块接真数据 | — |

### 11.4 一句校准

用量统计补上的是账本的「成本轴」缺角（文档里确实记过、产品里其实已埋好）；
但监理到位与否的**主判据仍是裁决质量**（拦没拦住、说得清不清白、盲区认不认）。
用量一行上去之后，用户「基础工作做全了」的体感成立，而它不挤占第一版上线——因为最贵的那一步（埋点）已经走完了。

## 15. 粮草（续航）第一版口径裁决（创始人 2026-10-17 追问）

> 问题原文：**"按照你的原型图，第一版就要把粮草信息做进去吗？"**
> 起因：v1.2 的 §4.4 与 §14.6 都写了"运行状态页新增粮草小块"，原型第五张也画了这一块。
> 本节是对这条的**自我证伪**：先查产品事实，再判决。

### 15.1 四条实查（全部本机可复现，不是推演）

| # | 事实 | 证据 |
|---|---|---|
| 1 | **单位根本不统一** | `rules/economics/` 五个画像四种单位：`workbuddy` = **credits**、`claude-code` = **USD**、`qoder`／`generic`／`zcode` = **tokens**。且 `antinel.py:482` 在 `unit≠credits` 的宿主上**直接拒绝服务**："当前宿主经济画像为 tokens——无积分口径，credits 不可用" |
| 2 | **新用户首日必空** | 本机 `~/.antinel/granary/` **目录不存在** ⇒ `granary.state()` 返回 `state="off"`（代码注释：`off` ＝还没记过粮账，不报警，像"未启用"）；`antinel credits forecast` 实测输出"预测需要 ≥2 次快照（现在 0 次）" |
| 3 | **数字是用户手记，不是系统实测** | 积分余额只能靠 `antinel credits snapshot <余额>` **人工口报**；粮是本地按小时扣减的工时账。两者都**不是**从工具侧自动采集的账单 |
| 4 | **页面上本来就没有粮草块** | `inbox_server.py` 全文 `granary` 仅 4 处，全是 `light_explain()`（四态解释句）与 `badges()`（缺粮徽标）——**没有任何独立渲染块**。CLI 已是真话空态：`antinel 粮` 输出"还没有粮账：监理还没开始站岗（没在消耗，也就不缺粮）。" |

三条隐含推论：

- 推论 A：一个"粮草"块要在页面成立，必须**四种单位并存**（积分／美元／token／无口径）。四种单位放进同一块＝**F54／E198 的作案现场**：看上去都是"钱"，其实一个都没法加。
- 推论 B：**手记的数画成仪表盘，就是把"你报的"读成"系统测的"**。这是比缺少功能更重的信任损伤——安全产品最不能欠的就是这一条。
- 推论 C：产品原本的设计是**"粮草在 CLI，异常才上页面"**（缺粮 ⇒ 徽标 ⇒ 一句话）。第一版不做粮草块，是**保持原设计**，不是砍功能。

### 15.2 判决：第一版**不做**（连"条件出现"也推后）

| 理由 | 强度 | 说明 |
|---|---|---|
| 单位不统一，无法有单一正确渲染 | **硬约束** | 不是代码量问题，是口径不可统一；CLI 按宿主画像渲染天然正确，页面做不到 |
| 首日必空，空框比没有更差 | 硬 | 首装第一眼是本产品的信任窗口；一个"还没有数据"的空框会让人怀疑整套系统没在工作 |
| 手记数不能显示成实测 | 硬 | `credits` 是用户口报，`granary` 是本地工时；页面上任何"余额/花了多少"的仪表化呈现都会改变数据性质 |
| 页面正在减负，加概念＝加解释成本 | 中 | 创始人本轮反复要求去"鸟语"、减重复；"粮 ≠ 积分 ≠ 钱"这个概念需要一整句解释，而它答的不是第一版的问题 |
| 告警已有出口，不靠常驻 | 中 | 缺粮走 `badges()` 徽标＋`light_explain()` 解释句，异常驱动已经闭环 |
| 与"尽快上线"一致 | 中 | P5 因此从三块缩到两块，省掉空态设计、跨宿主口径、四条判据 |

**不做的代价（诚实评估）**：用户看不到"还能站几天"的常驻读数。
缓解三条：①缺粮时徽标必亮（已有）；②`antinel 粮` 一条命令给出余额/明细/规则；③§11 的「用量一行」（0.54.0）才是"花了多少"的正解——**粮答的是"还能站多久"，用量答的是"花了多少"，前者是续航、后者是成本，第一版只需要答"安不安全"**。

### 15.3 撤回我自己写错的三处

1. **把新增写成收敛**：原型第五张的"粮草"块是**我新加的**（0.52.0 页面上本来没有），却在 §14.6 写成"只显示不记账"，读起来像在收敛既有内容。事实是新增。
2. **一个词合并两本账**：`granary.py` 头部明写三本账必须分清（`credits`＝宿主烧的积分／`ledger`＝本机事件日摘要／`granary`＝哨兵口粮，单位 1 粮＝在岗 1 小时）。我用"粮草"一个词统称，正是三本账头部警告过的那类混口径。
3. **漏了跨宿主空态**：四种单位里三种在页面上无从显示（tokens 类宿主连 `credits` 命令都会拒绝），我画原型时只按本机 workbuddy 的 credits 想，等于**用一台机器的局部事实当全局设计**——与本批"本机 100% workbuddy 导致徽标永不出现"是同一类错误（局部环境冒充普遍形态）。

### 15.4 第一版实际保留什么

- **缺粮徽标**（`badges()`）与**四态解释句**（`light_explain()`）不动：异常驱动、已有实现、已有判据（0372 S09 六态词条键不可撤）。
- **CLI 全部不动**：`antinel 粮 [余额|明细|规则]`、`antinel credits snapshot|forecast|reconcile|plan`。空态已是真话（15.1 表 #4 实测）。
- **运行状态页该位置留白**：不放占位框、不写"暂无数据"。留白＝这件事还没到页面上，不是"有数据但不给你看"。

### 15.5 什么时候做（0.54.0 的准入条件，四条须同时满足）

1. **单位按宿主画像分渲染**：不同宿主显示各自单位，**永不跨宿主求和、永不折算成统一货币**（折算即违反"不承诺收益／不编口径"）；
2. **每个数字带来源标记**：手记（你报的）／实测（本地计量）／推断（估算），三者视觉可辨，不许把"手记"画成仪表；
3. **两级空态**：本机无账（`off`）／快照不足（`<2`），两级的文案不同——前者"还没开始站岗"，后者"再记一次才能预测"；
4. **判据含负控**：`off` 时页面零粮草字样、零 0 值；若显示必须与 `granary.state()`／`credits` 快照同源（换第二份算法必红）。

与 §11 的「用量一行」同批发布，因为两者合成才回答"我花了多少、还能撑多久"，单独上任何一个都只是半句。

## 17. 两处自造更正（2026-10-17 实查）

写规格时凭空造了两个不存在的东西，均已在代码里核实并更正。**这类错误不改，规格越细越危险**——细到函数名却指错函数，比粗着写更难发现。

### 17.1 `--arm` 不存在

- 原文（v1.2／v1.3 §14.6 P6）："三段全只读，`--arm` 是唯一写动作"；
- 实查：`antinel host-audit` 只有 `--host` 与 `--probe` 两个参数，**没有 `--arm`**；且 `cmd_host_audit()` 本身**全程只读**（列路径、算体量、数工作区），根本没有写动作。
- 更正：体检页**没有任何写动作**；"历次对比"的快照写入由页面侧（服务端）负责，不是命令参数。

### 17.2 体检数据源指错命令

- 原文：体检页"装机盘点"取 `host-audit` 的输出；
- 实查：六档裁决的计数 `counts_by_verdict` 由 `antinel.py:3297-3368` 的 `_host_scan_payload` 产出（属 **`host-scan`**）；`host-audit`（`antinel.py:2313`）打的是**目录体量**（每个宿主几个工作区、占多少 MB），不含裁决。
- 更正：体检页"装机盘点"段取 **`host-scan` 的 payload**；`host-audit` 的体量数据归"装机明细"，两者不是一件事。

### 17.3 由此立一条规格纪律

**方案里出现的每一个命令、参数、字段、函数名，必须带"代码落点"（文件:行或函数名）。写不出落点的，一律不许写进规格。**
这条已写进 §18 的表格要求，成为准入条件而非提醒。

## 19. 「一步到位」的可行性判断（对创始人 2026-10-17 追问的正面回答）

创始人问：细节前置到位后，能否**一步把 0.53.0 修订到可发布**。

### 19.1 结论

**"一次定规格"成立；"一次改完再验"不成立。**
两者不是路线之争，而是同一件事的两面：确定性来自**每个改动点都有落点与判据**，不来自改动被合并在同一次提交里。

### 19.2 三条硬理由

1. **红项必须可归因**。0.53.0 涉及 5 个文件、8 件、10 条以上判据。一次性改完再跑，任何一条红都无法指认是哪件引起的——这正是"绝不全量复跑中途改产品文件"这条纪律要防的事。本轮已有实证：改目标抽取时**顺带**撞出 94 字假绿，若当时还在同一次改动里叠着归因与体检页，这条会淹没在红堆里。
2. **有一个功能在本机不可自证**。链上近 8 天 100% workbuddy、0 个其他工具 ⇒ 工具徽标（≥2 工具才显示）在这台机器上**永远不会出现**。一次改完直接发版＝把一个从未被真实数据验证过的功能推给用户。这条只能靠多工具夹具＋发布前用户路实测来补，不能靠"改得全"。
3. **PyPI 不可回滚**。一次推平 0.35.1→0.53.0，推错了只能发 0.53.1 或 yank。发布动作必须单独成件、单独过门（§14.7 P7 的五段用户路），不能混在功能改动里。

### 19.3 执行形态：0.53.0 内部 8 个门槛

一个发布版本，八个门槛；每个门槛的"过"都是**可执行判据 + 一条命令**，不是"我觉得行"。

| 门槛 | 件 | 过的定义 |
|---|---|---|
| G1 | P1 数据层（Alert.host／usage_delta.host） | 新旧记录分代正确，缺失留空不填 generic；判据 + 负控绿 |
| G2 | P2 收件箱 | 行内无时间双写、无状态复述；徽标仅 ≥2 工具（双工具夹具证明）；`host:` 过滤可用 |
| G3 | P3 日报 | 全页只有一个"今天"口径；排行行尾工具分布；同页无第二份计数 |
| G4 | P4 账本 | 撤四卡；无记录天不给 0；`antinel ledger --json` 与页面同源（换第二份实现必红） |
| G5 | P5 运行状态 | 只答"此刻"；未核验是明确告警句；无粮草块（G1–G3 守卫） |
| G6 | P6 体检页 | 六档顺序与 `VERDICTS` 同源；盲区不并入清白；首装空态不编 diff |
| G7 | P7 发布端到端 | 载荷／自证／通道／**用户路**／同步五段齐（新 venv 装→install→钩子真注册→五页开→uninstall 还原） |
| G8 | P8 发布门 | 阻断清零＋豁免列名＋自愈留前后两次日志 |

### 19.4 "不让模型猜"的量化指标

- 规格里**每个改动点**都有"落点"列 ⇒ 目标 100%；低于 100% 的条目降级为"待定"，不排产；
- 每条判据都有**成对负控** ⇒ 100%（本轮 W-SPK13 即按此做，负控退回旧实现必须红）；
- 每件改动后**当场跑**其判据，不攒到最后（本轮 0514／0380／0490 三次当场复跑即是此形）。

### 19.5 对第一版范围的影响

按上述标准，第一版的范围**不变**（五页＋归因＋用量埋点保障＋发布端到端），只是把"一次改完"拆成八个可停可退的门槛。
新增一件：**P0**（本 §16 已完成）——详情行目标抽取与行预算，作为其余各页的显示地基先落地。

## 24. 「非必要不改不删」的执行守卫（创始人第二次强调）

## 28. 网站体检接入（创始人交办：antinel.com 有体检入口，要考虑周全）

### 28.1 实查：网站的「体检」到底是什么

`https://antinel.com`（首页）与 `/check/`（自查页）逐字取回：

- 首页：`最省事：让你的 AI 助手来跑` → 给 AI 一段提示词：`2. 安装检查工具：python -m pip install --user antinel` → `3. 运行检查：python -m antinel host-audit` → `4. 把原始输出完整贴出来，逐行解释`
- `/check/`：`不注册、不上传、不需要密钥 —— 查的是你自己电脑上已经发生的事`；`命令只读你自己电脑上的文件，不联网、不上传`
- 结果读法只有三种：`路径 … 不存在` ／ `路径 … 存在` 但工作区行没有 `⚠ 已上传接受` ／ **出现 `⚠ 已上传接受`（★ 要看的就是这一行）**

### 28.2 三个必须承认的事实（决定接入方案）

1. **网站没有服务端体检。** 它不接收任何数据、不产出任何自己的结果。所谓「网页体检」＝**引导用户在自己机器上跑同一个包**。
2. **跑的那个包，就是监理的包。** 第 2 步就是 `pip install --user antinel` ⇒ 所谓「装前体检」，**包已经在机器上了**，只是还没跑 `antinel install`（没注册钩子）。这是本方案最重要的一次重新框定。
3. **`host-audit` 目前不落任何文件。** 实测：`antinel host-audit` 纯 stdout，`~/.antinel/` 下没有对应记录文件；`findings.json` 只在 `host-scan --arm` 才写（`antinel.py:3271`），本机至今没有该文件。

⇒ 所以「网站端体检结果展示在系统里」**不可能靠服务器对接**，只能靠**本机留痕**。

### 28.3 三种桥（含成本与风险）

| 桥 | 做法 | 能否覆盖「装前已体检」 | 代价 | 风险 |
|---|---|---|---|---|
| **桥一（推荐）** | 让 `host-audit` **存一份体检报告**到 `~/.antinel/health/audit-<ts>.json` | ✅ 能（装前跑的就是这个包） | 改一处写文件；网站提示词同步加一句 | 违反「只读」字面 → 需一句措辞澄清 |

### 30.2 根因

- `_INDEX_SUBDIRS = ()`（`antinel.py:2523`，注释明写「目前故意为空，本机 0 实证」）；

### 34.1 为什么第一步是它，而不是先做体检页

### 35.2 七处必须拍板（T-1…T-7）

#### T-1　B 组的「文件条目数」与「打包大小」不是同一个轴（照旧实现＝写出错话）

- **§27.5 原文**（五行表）把这两个数排在同一行：
  `| 文件条目数 | host-audit 同源字段 条目 | 11,132 |` 与
  `| 原来的大小 | lastCompressedSize.workspaceSizeBytes | 143,378,975 B ≈ 136.7 MB |`。
- **实测**：11,132 是 `host-audit` 现在对 `D:\psl\poc` **实时 walk** 出来的条目数；
  143,378,975 是 `state.json` 里**上次打包那一刻**记下的工作区大小。两者时间点不同、来源不同、
  甚至可能指向不同内容（打包后你又加了文件）。
- **为什么这属于 §27.1 第一类蠢**：读者会把它读成「136.7 MB 由 11,132 个文件组成，平均每个 12 KB」
  ——这个推理在本机**没有任何证据支撑**。
- **处置（推荐 A）**：B 组**不放条目数**。B 组每条只给四个数：
  项目目录 ／ 上次打包时多大 ／ 加密后多大（＋倍数）／ 服务器收下了吗（＋打包时间）。
  条目数、`.git` 条目、密钥类文件留在 **A 组与存档**（那是 `host-audit` 的视角，答的是「这个目录现在什么样」）。
- **代价**：B 组少一个元素；换来的是这一组**单源、单时点、可复算**。
- **反选 B**：显示条目数但加「现在」二字并单独一行 ⇒ 仍是一行两个时点，只是说得更啰嗦。
- **反选 C**：让 `host-scan` 也去 walk 项目目录 ⇒ 违反「非必要不改」且扫描时长翻倍。

#### T-2　体检页到底是「两折叠」还是「四组」（§20.4 与 §27.3／§27.8 互相矛盾）

| 出处 | 说法 |
|---|---|
| §20.4 版面图（v1.5） | `③ 两个折叠（默认收起）`：▸逐个看 ／ ▸往外发与诱饵 |
| §27.3 四层钻取（v1.6） | L1 = **四组**标题，`常显，组内折叠` |
| §27.8 折叠纪律 | `L1 四组默认全展开（组内前 5 条常显，其余「展开其余 N 条」）` |

三处给了三种状态。**§27 是后来者**（v1.6 > v1.5）且创始人明确要「四组明细」，故以 §27 为准；
但 §27 内部「组内折叠」与「默认全展开」还要选一个。
- **处置（推荐）**：**四组默认展开，组内前 5 条常显，其余折叠在「还有 N 条」里；L3 原始证据默认收起。**
  理由：① 默认收起等于让用户先点两下才知道有四组，与「第一次就要看得懂」冲突；
  ② 每组只摊 5 条 ⇒ 常显内容约 20 条 ＋ 六格 ＋ 结论行，约 3 屏，不失控；
  ③ 折叠的责任从「整组」下移到「组内超出部分」，一处折叠层级，不多不少。
- **§20.4 的两折叠就此退役**（已在原文处加指路）。

#### T-3　`print_spool` 的 `null` 不是「0 条」（照旧渲染＝把「没找到」写成「是空的」）

- **§27.7 原文**：`| print_spool | 打印后台 | 0 条 | 空 = 正常（这一处允许显示 0）|`
- **实测**：payload 里是 `"print_spool": null`。根因在 `antinel.py:3050` → `_obs_dir()`：
  **目录不存在返回 `None`**；目录存在但 0 文件才返回 `(q, 0, 0, False)`。
- ⇒ 本机 `null` 的真实含义是「这台机器上**没找到**打印后台目录」（`%SystemRoot%\System32\spool\PRINTERS`
  通常需管理员权限或本就不存在），**不是**「打印队列此刻是空的」。
- **处置（推荐）**：`null` 一律渲染为 E6 同族的话：`这一项在你这台机器上没找到 —— 不是「查过、是空的」。`
  「0 条＝正常」这句话**留到真的读到 0 条文件时**才用（那时 payload 是 `{"entries":0,…}`）。
- **代价**：本机永远看不到「打印后台空着正常」这句安慰话——但那句话本来就不是事实。

#### T-4　§27.2 说 B 维度「现有页面 ❌ 无」，说得过重

- **实测**：`ui_server.py:400-410` 的 `_evidence_html` **已经在渲染** `workspaceSizeBytes`／
  `workspacePath`／`lastAcceptedManifestHash`（页面上是「打了多大／打包的是这个目录／服务器收下了吗」）。
- **准确说法**：数据在，但**埋在 59 个工具各自的折叠证据里，以「落点」为单位**。
  要回答「我的哪些项目被打包过」，用户得挨个点开 59 个工具才能拼出 4 行。
  ⇒ 缺的不是数据，是**以项目目录为单位的独立成组**。
- **处置**：改说法，不改设计。B 组依然要做，理由从「没数据」改为「数据在但不可读」。
- **附带**：B 组**不必新增采集**（仍在 `details` 里），故不影响「非必要不改」。

#### T-5　L0 结论行的第三个数不能是「没布门闸 K 个」
