## 一、两处缺陷的事实与修订

### 1.1 账本出现「防护缺口」与「缺口」

**事实**：六态是封闭集合（`inbox_model.STATE_LABEL`）：

| 代号 | 标准名 |
|---|---|
| R0 | **失守** |
| L2 | 拦截 |
| L1 | 注意 |
| Ls | 缺粮 |
| L0 | 值守中 |
| dev | 研发中 |

**「防护缺口」不在这个集合里。** 它在五页可见文本里共 9 处（账本 4 处、收件箱与
remediation 5 处），词源是 0.48 时代旧称；0.51.0 六态定名（commit `f6fc49a`）
把 R0 定为「失守」，账本这一份没有跟着改。

**修订**：九处一律改为六态标准名「失守」或平实描述（"有东西没被挡住"／"有问题"），
并且**账本格子的词改为从 `M.STATE_LABEL` 派生**——不再有第二份命名源。

### 1.2 看不到是哪个 AI 编程工具

**事实**：运行状态页「工具识别」行括号里放的是**置信度**（"有直接证据 104 条"），
不是工具名。句子承诺"认得出是哪个工具"，却永不给出那个名字。

**修订后**：`近 7 天 477 条记录里，103 条认得出是哪个工具——全是 WorkBuddy（有直接证据 103 条），374 条说不清（78%）；……`
工具名走 `M.host_distribution`（唯一实现），显示名走 `_host_label`（宿主表 `name`）。

> 另有一处**不是缺陷**：日报排行行尾与收件箱徽标对单工具机器（`host_count=1`）
> 按设计不显示分布 —— 设计文件 §19.2 已自认"此机不可自证"，本机正是这种机器。

## 三、根因：为什么机器一条都没发现

### 3.1 问题一：判据替旧词背书（最危险的一层）

不是"某个人忘了改一个词"，而是**判据把旧词抄成了期望值**：

```python
# 0.53.0 的 ci/inbox_guards_0490.py（T-04）
for word, key, lv in (("拦截", "blocked", "L2"), ("注意", "noticed", "L1"),
                      ("防护缺口", "breached", "R0")):
```

产品渲染「防护缺口」，判据断言页面必须有「防护缺口」⇒ **两边一致、全绿**。
**抄写把错误固化成了标准。**

三层原因：① 命名源分裂（态名的权威是 `STATE_LABEL`，账本格子里却是硬编码字面量）；
② 判据从实现派生、而非从权威派生；③ 没有词表闭包检查。

### 3.2 问题二：判据照"句子"写，不照"问题"写

U22 原有五条腿（分母／成功数／置信度／说不清占比／空态）**全是这句话的组成部分，
没有一条是"这一块要回答的问题"**。于是出现最荒唐的形状：一个专门回答"是哪个工具"
的块，判据不检查工具名。

三层原因：① 尺子照抄实现结构，误以为"字段都对"＝"块被守住"；② **设计要求分散且
没有承接检查**（§4.4 与 §6 对同一块的要求不一致）；③ 句式陷阱（"认得出是哪个工具"
读起来像答案在句中，实际括号里是置信度）。

## 四、四道机器防线（根治，不是 happy path）

### 防线 A · 派生（已落地）

账本格子的态名从 `M.STATE_LABEL` 派生，产品与判据**同一个源**。改六态名 ⇒ 两边同时变，
物理上不存在"改一边忘一边"。不是"加一条不许写旧词的检查"，而是让旧词**没有地方可写**。

### 防线 B · 闭包闸（已落地）

`T-04e`／`N-T04e`：扫五页可见文本（`PC.body`，S48 口径），命中退休态名即红。
退休词表 `_RETIRED_STATE_WORDS` 登记即永久。
**它上线当刻就抓到 5 处我此前漏掉的地方**（`remediation.py` 4 处 ＋ 收件箱「不做的后果」1 处）。

### 防线 C · 问题-答案闸（已落地）

`U22` ①b 腿（句子必须出现夹具里每个工具的显示名，期望名从 `_host_label` 派生）＋
③ 腿（单工具也必须点名）＋ `N-U22c`（把工具名摘掉 ⇒ 必须红，且红因必须含「点名」）。
它守的不是"某个数"，而是"这一块的问题有没有被回答"。

### 防线 D · 设计要求→判据映射（**本版已落地**）

#### D.1 三样东西

| 件 | 落点 | 作用 |
|---|---|---|
| 章号派生 | `S57._design_chapters()` | 从设计文件里解析出全部 `## N.` —— **不在表里列清单**，清单会跟丢 |
| 账 | `docs/设计条款-判据映射.json` | 每章一条：`guarded`（由谁守）／`uncovered`（没人守，写 why＋next）／`record`（无验收面，写 why） |
| 尺子 | `S57` ＋ `N-S57`（并入 `guard_instrument_selfaudit.py`，**未新增套件**：A2 常驻 29 已满） | 六条腿，见下 |

**六条腿**：

1. 设计文件里每个一级章号必须在表里有登记 —— 未登记即红，并**点名缺哪几章**；
2. 表里的章号必须在设计文件里真实存在 —— 防幻觉条款号；
3. `guarded` 的 `guarded_by` 非空，且每个 id 都是**真实存在的判据 id**（从 32 个判据
   文件的 AST 里提取，实测 649 个）；
4. `quote` 必须**逐字落在该章正文里**（空白归一后比对）—— 引不出原文＝没读那一条；
   把别章的话搬过来也会红；
5. `uncovered` 必须写 `why` ＋ `next`（谁来关这条），`record` 必须写 `why`，且
   `record` 条数受 `record_cap` 约束；
6. `design_doc` 必须是该族**最高版本** —— 设计升版而映射表没跟，当场红。

#### D.2 首跑实测：38 章，7 条 uncovered

**16 条 guarded、7 条 uncovered、15 条 record（cap = 15）**。uncovered 的七条：

| 章 | 要求 | 实测缺口 |
|---|---|---|
| §7 | 同页句子指纹不重复 | 全仓无此判据（`delivery_gate` 的"指纹"是闸门自身快照，不是页面句子） |
| §11 | 用量要"看得见" | 五页渲染零用量（`inbox_report.py` 0 处；`inbox_server.py` 的 token 全是登录口令） |
| §15 | off 时页面零粮草字样、零 0 值 | 无判据（G 族守的是"粮不卖／不可转让／不可兑换／两本账"） |
| §18 | 每件必须五列填满 | 无施工单登记表，也就无判据 |
| §22 | 五道闸 | **只落了闸五**：闸一无判据、闸二的"负控没红升红"仍是 `print [WARN]`、闸三闸四仍是流程纪律 |
| §24 | 四条规矩（白名单／签字／留账／判据不降级） | 无机器，与 §22 闸一闸二同源 |
| §28 | 网站体检接入 | 站点在另一仓，本仓零判据 |

> **这七条就是这道防线的价值证明**：不是"我读了设计文件所以知道"，而是"机器逼我把
> 每一章表态，表一填就露出来"。与 T-04e 首跑抓 5 处旧词同型 —— 负数项自证有效。

#### D.3 真账上八条腿的实测（不是标本）

| 改什么 | 结果 |
|---|---|
| 真账原样 | 绿 |
| 删掉 §6 那一条 | 红：设计文件有、映射表没有的章：§6 |
| §6 的 `guarded_by` 改成 `U99` | 红：§6 指向不存在的判据 'U99' |
| §6 的 `quote` 换成 §14 的句子 | 红：不逐字落在本章正文里 |
| 把 record 全改 uncovered 且不写 quote | 红：缺 quote（引不出原文＝没读那一条） |
| `design_doc` 指回 v1.11 | 红：设计文件已到 v1.12，映射表还指着 v1.11 |
| `record_cap` 压到 3 | 红：record 条数 15 超过 record_cap 3 |
| 空表 | 红：空表也能全绿的话，这条尺子就是摆设 |

这八条同时是 `N-S57` 的负控内容（内存态，零写盘），并且在真账上独立复跑过一遍。

#### D.4 为什么这不是 happy path

happy path 的形状是"就着这次的错加一条刚好抓住这次的检查"。D 的五条反例：

- ❌ 在表里**列一份章号清单** —— 清单不会自己长，新增一章照样溜过去；正解是**派生**。
- ❌ `guarded_by` 只要求非空 —— 写个 `"U99"` 就能骗过；正解是**对上真实判据 id**。
- ❌ `quote` 只要"在文件里出现过" —— 抄一句别章的也算读了；正解是**限定在本章正文区间**。
- ❌ 允许全标 `record` —— 那是把"没查"写成"不用查"；正解是 `record_cap` ＋ 必须写 why。
- ❌ 表里写死 `v1.12` 而不管新版 —— 升版那一刻表就过期了；正解是**版本锁**。

#### D.5 已知边界（诚实写在这里，不装完整）

1. **分类靠人**：`guarded`／`uncovered`／`record` 的判断是人做的，机器只保证"不许沉默"。
   它防的是"整章没人读"，不防"这一章读错了"。
2. **`record_cap` 可以一行改高**：这是"可见"机制不是"禁止"机制 —— 所以每次跑都把
   `record` 条数打印出来（`章 38｜guarded 16｜uncovered 7｜record 15（cap 15）`）。
   想放开就必须在 diff 里留下那一次抬高。
3. **`guarded_by` 只证明"有这条判据"，不证明"这条判据够强"**。强度由负控与防线 C
   （问题-答案闸）承担 —— 三个字的名字骗得过登记，骗不过 `N-U22c`。
4. **判据 id 的提取口径自己踩过一次**：首版把 id 长度下限写成 3，`H3`／`H7`／`H8`／`H9`
   四条真判据被判成"不存在"。已改为 2 并写进注释 —— 量具先量自己这条纪律，这次是
   我自己撞的。
5. **起判据名也踩过一次**：本条初号 `S56`，而 0430 早就有一条 `S56`（入口真跑）。
   `UID15-b`（跨套件重名折叠检测）当场报红 ⇒ 改为 `S57`。**"我知道自己这套里没重名"
   不等于没重名**——查重是跨套件的事，必须由机器查。另外 0481 的 `L1`（SPDX 头）
   也当场抓到我这份文档缺头。

## 五、五条反 happy path（A/B/C 三条 ＋ D 两条）

happy path 的形状是：**就着这次的错，加一条刚好能抓住这次的检查**。例如：

- ❌ 写一条 `assert "失守" in page`——抓得住这次，抓不住"下次改成别的词"。
- ❌ 把「WorkBuddy」硬编码进判据——品牌一换，判据要么误红、要么被改成新品牌名。
- ❌ 只在账本页扫旧词——收件箱那 5 处正是这么漏掉的。
- ❌ 在映射表里列章号清单——新增一章照样溜过去。
- ❌ 只要求 `guarded_by` 非空——写个不存在的 id 就骗过了。

四道防线的共同形状：**期望值从权威源派生，尺子不复制实现的字面量**。

- 态名 ← `STATE_LABEL`（唯一命名源）
- 工具名 ← `host_distribution` ＋ 宿主表 `name`（唯一归因源）
- 旧词 ← 退休词表（登记即永久，堵住所有渲染路径）
- 章号 ← 设计文件的标题本身（**连"要守哪几章"都不许手抄**）

判据不再"抄实现"，而是"验权威"。

## 八、为什么这道防线拖到今天（反思，不是辩白）

三条原因，按可复用的程度排序：

1. **没有"账"这个东西**。前一轮做的是"每条判据守什么"（§7 的索引），方向恰好相反：
   索引回答"这条判据守什么"，缺的那半是"这条要求由谁守"。**反向索引不存在，
   漏一章就没有任何痕迹** —— 这与 F41（删了后文依赖的前文）同族：错误在**没写出来**的地方。
2. **判据是按"我知道什么"写的，不是按"它该回答什么"写的**。我知道工具识别有四个数，
   就检查四个数；我不知道"读者要的是名字"，就没检查名字。机器能补的只有覆盖关系，
   "该回答什么"要靠读原始需求 —— 所以 D 的入库条件是 `quote`：**引不出原文，就不算读过**。
3. **设计要求分散，且默认"读者会读完"**。§4.4 与 §6 各写一半，两份都是真话，合起来才
   是完整要求。人读漏一节，机器一声不响。**D 的落点不是"要求写在一处"（那要靠改设计），
   而是"每一章都必须有人认领"** —— 认领不了就写 uncovered，写不出来就是红。

一条纪律补记：**"我读过设计文件"不是证据，"每一章都有承接"才是证据**。以后凡是
"对照设计文件"的任务，先跑 S57，再谈逐条对照。
