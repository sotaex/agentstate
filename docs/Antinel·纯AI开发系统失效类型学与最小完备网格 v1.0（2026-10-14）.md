# Antinel·纯 AI 开发系统失效类型学与最小完备网格 v1.0（2026-10-14）

**成文时点**：2026-10-14 21:45（GMT+8），由本轮迭代会话执笔，待创始人终审。
**触发问题**（创始人原话要旨）：要让纯 AI 开发的系统能高效开发、高效迭代升级、高效解决错误、提升功能与体验——包括但不限于「废除的功能死灰复燃」「排错时引入新错误」「越修错误越多」「各种低级问题 AI 看不见」——把所有维度上可能出现的问题想全，列成清单，如有可能做到最小完备。
**证据纪律**：每条类型标注本项目实例（可复核）或【提案·未观测】；数字由脚本计数，不心算；百分比一律带分母。

## 0. 结论先行

**主张 S1（生成式网格）**：纯 AI 开发系统的全部可观测失效，都是三个正交轴上的坐标点——

| 轴 | 名称 | 回答的问题 | 取值（闭集） |
|---|---|---|---|
| A | 环节 | 错误在哪一环被放行？ | 8 个（§1） |
| B | 形态 | 错误以什么物理机制存在？ | 10 种（§1） |
| C | 盲区 | 为什么验证当时没抓住它？ | 8 种（§1） |

实例无限，类型有限：任一失效必须能同时回答「在哪一环放行的（A）＋以何形态存在（B）＋为何不可见（C）」，三问都有闭集答案，故类型空间由网格生成而非凭记忆罗列。

**判据 S2（可证伪的最小完备）**：拿本项目已登记的全部历史失效（F40–F58 家族、X-046–049 等实例、0515/0516/0517 判据所针对的缺陷）做主格映射——

- 全部落进网格 ⇒ 网格对本项目成立；
- 有落不进者 ⇒ 该条即维度缺口的实证（元问题 M1 的自反探针，见 §6）。

即：**最小完备的不是「类型清单」，而是「生成网格」；类型是格子的填充物，可增补；网格漏格才会漏类型。**

**数学式 S3（收敛条件）**：问题总量 N(t) 的变化率

  dN/dt ＝ 新类型产生率 − 判据固化率

总量收敛 ⇔ 判据固化率持续高于新类型产生率。**同族复发不是新 bug，是「判据固化失败」的信号**——所以一等指标是「复发间隔」，不是 bug 数。本项目实证：cmd 编码问题同族第三次复发才建机制（X-047），即一次固化迟滞。

## 1. 三维生成网格

### 轴 A·环节（何时失守／放行）

| 编号 | 环节 | 典型放行方式 |
|---|---|---|
| A1 | 输入与需求理解 | 需求读偏、约束漏读、摘要沿袭 |

| A3 | 实现与修改 | 漏登记、漏消费者、顺手扩大改动 |
| A4 | 自检与验证 | 验证边界画小、量具失真、假绿 |
| A5 | 交付与发布 | 清单 fallback、版本混装、metadata 不验收 |

| A7 | 反馈与复盘 | 用户 direct read 被当抱怨、复发不归类 |
| A8 | 版本与演进 | 旧版未退役、废除件复活、口径随版本漂移 |

### 轴 B·形态（以何机制失守）——共 10 种

| 编号 | 形态 | 一句话物理定义 |

| B3 | 冒充 | A 充当 B（旧的充新的、内部的充外部的、推演充决议） |

## 4. 盲区详单：AI 为什么看不见（轴 C 展开）

### C1 跨边界
- **进程边界**：CLI 短命、msedge 挂其进程树下，命令结束被连带清理（X-049 四路实证：Popen／DETACHED／cmd start 全死，唯 daemon 长命存活）。
- **时间边界**：daemon 活 4 小时＋，命令活 2 秒——「起得来」与「活得久」是两个问题。
- **会话边界**：记忆断层、摘要带错进入下一轮。
- **用户边界**：真机复核（tooltip 三点）非 AI 可代验；「看不到」是最高优先级 direct read。
- **机器边界**：CI 无桌面、显示器数量不同、构建机≠开发机。

### C2 跨层
- 代码态≠运行态（修了源码，旧实例还在跑——换代＋回读才闭环）。
- 仓根态≠装配包态≠wheel 态≠安装态（清单哈希算于 merge 之前即失配）。
- 文档态≠代码态（文档说废除、代码还在）。
- 清单态≠载荷态（128 项 vs 131 件双向错配）。

### C3 跨口径
- 百分比分母（331 vs 全量）、复用率三重口径、版本号三处、pass/fail 分母（wall-clock 必须剔除）、「76%≈全量／七成＝331 内」式同句双分母。

### C4 隐性环境（「低级问题」主战场——逐项列全）
| 子类 | 已实证／已知坑 |
|---|---|
| 编码 | CRLF vs LF；CP936 vs CP437（UTF-8 中文注释即使 CRLF 也误执行）；BOM；全角空格；中文引号；文件无编码声明 |
| 显示 | 多显示器坐标；DPI 缩放；任务栏位置；Z-order；最小化到托盘；窗口落在屏幕外 |
| 进程 | 进程树／job object 清理；句柄继承；CREATE_NO_WINDOW≠DETACHED；cmd start 语义 |
| 时序 | 兜底落位覆盖手搬；tick 周期（2s）vs 建窗时长；启动顺序竞态 |
| 文件 | 文件锁；长路径；大小写；只读位；.gitattributes（* -text 使 CRLF 对照失效） |
| 权限 | 沙箱白名单（DST-02）外写失败；UAC；防火墙首弹 |
| 解释器 | PATH 解析；多版本 python；venv 与系统混用 |
| 外部世界 | PyPI 名被占（agentstate）；网络可达性；第三方仓库变更 |

### C5 语言层放过
「说得通」比写错数字更危险：任何语义／逻辑检查都放它过关，只有「回源文件检索」能抓到。且**合理性与数量级检查在 F40／F54 场景双双失效**（两个数都极端、都接近某个真值）——这两个明星检查有明确的失效区，失效区内只信脚本逐口径重算。

### C6 量具失真
mock 打在副本；夹具不成立（不含真信号）；断言名说谎；探针被环境污染；判据自身没有判据。**量具失准比没有量具更危险（假绿）。**

### C7 概率性
flaky（同输入多次结论不一致）；单次采样当稳定；竞态；偶发环境（代码页时红时干净）。

### C8 权威压制
创始人原话（「这是创始人说的」压制核对）；高频熟词（检索冲动由陌生感触发，熟词不触发）；源内命中即用（命中≠可用，先问是推演还是决议）；摘要沿袭。

## 8. 边界规则与反重叠

1. 一个实例一个主格；连带格不计入密度统计（防重复计数）。
2. 主格判定顺序：先形态（B）后盲区（C）——盲区是「为什么没抓住」，形态是「它是什么」。
3. 【提案·未观测】的类型不享同等信任：要么补第二个实例，要么补可复现判据，否则降级为「风险提示」。
4. 清单自身按 M1–M7 每轮自检一次；扩维必须显式记录（轴 D 预留，见 §9）。

## 9. 残留风险与可证伪声明

1. **对抗性／供应链未设专轴**：恶意 skill、投毒依赖、名字抢占（agentstate 实证）目前并入 B2×C4。若项目进入 skill 审计与全球分发深水区，应扩轴 D（外部性与对抗），否则该域类型会挤爆 B2。
2. **多 Agent 协作轴未建**：当前单 agent。若引入同事 agent，主体间失效（承诺不一致、消息丢失、责任稀释、互相假确认）需扩轴。
3. **BT 总数与提案数均由脚本计数**（本节成文时 BT 共 56 条，编号 1–56 连续、无重号、无缺口；其中【提案·未观测】3 条：BT-16、BT-44、BT-47），复扫以脚本为准，不心算——本节自身就是 BT-27 的第一个实例。
4. **本清单的可证伪点**：任一历史失效落不进网格 ⇒ S1 被削弱；任一【提案】类型第二个实例始终不出现 ⇒ 按 M4 降级。两者都是清单变强的方式，不是失败。
