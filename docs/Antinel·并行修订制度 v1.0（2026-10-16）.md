# Antinel·并行修订制度 v1.0（2026-10-16）

> 适用范围：多路 AI 同时在 Antinel 仓上修订（主树一路 ＋ worktree 流）。
> 本文是两路共享的宪法：**先读本文，再动手**。与铁律冲突时，铁律优先
> （铁律是产品的根，本文只是工作方式）。

---

## §0 为什么需要这份制度

此前所有修订都是串行的：一路修、验、合，下一路再动。慢，且把「机器级
共享状态」的冲突风险藏在了「反正只有一路」的前提里。

现在要开第二路。串行前提消失后，两路同时触达同一台机器上的**闸门
套件、哨兵进程、console 真单例**，会出现三类新问题：

1. **跨树污染**：闸门/哨兵的运行时状态若按机器绝对路径存，两路互踩；
2. **量具失真**：并行负载把时序敏感的量具变成「时红时绿」——比恒红更坏
   （铁律 2 的并行放大）；
3. **假绿/假红**：单树全绿不代表合起来绿；集成红时无法归因。

本制度把「哪些能并行、哪些必须串行、绿怎么算、出事怎么登记」写成
**可执行的程序**，而不是口号。

## §3 规则

### A · 并行单位是「流」，不是「缺陷」

**流 = 一个 git worktree ＋ 一条分支 ＋ 一组不相交所有权的文件 ＋
一段专属 ID 号段 ＋ 自带负控。**

- 不以缺陷为并行单位（一个缺陷拆给两路＝打架预定）；
- 文件所有权在**开流时**登记（流简报 §5），流内只动自己名下的文件；
- ID 号段分派：X-053..X-060 归流 B（本轮），流 A 继续用既有号段；
- 跨流要动对方文件 ⇒ 先协商，协商结果写入流简报，不允许静默改。

### B · 量具不得依赖环境（铁律 2 的并行放大）

并行负载会把时序敏感的量具变成「时红时绿」——**比恒红更坏**。

- 任何量具/判据**不得**依赖：挂钟、机器负载、并发流数、其他流的进度；
- 依赖即禁：发现依赖，先改判据（或申报盲区），再谈并行；
- 两路各自跑闸门前，先确认本套件在 B 档清单里没有它（B 档套件
  到串行窗口再跑）。

### C · 分派纪律

- 每个缺陷实例登记时注明归属流；**X-051 本轮归流 B 专属**；
- 流 A 不得动 `ci/inbox_guards_0516.py`（流 B 试点目标），流 B 不得动
  流 A 在修文件——以各自流简报「本批在修文件」清单为准；
- 登记簿（`ci/defect_types.py`）三纪律不变：每类有人守或申报盲区／
  实例不许借判据充数／未闭合实例必须暴露。

### D · 单树绿 ≠ 本批绿

单树全量闸门全绿是**必要非充分**条件。它只证明「这棵树自己说得通」。

### E · 合并裁判（集成树才判本批绿）

本批绿的判定，只在**集成树**上做，且要全过：

1. 全量闸门：`python ci/delivery_gate.py`（34 套全跑）；
2. 全部负控**双境**：产品变异必红 ＋ 正常必绿（缺一境即量具失效，
   按铁律 1 报「夹具失效/SKIP」，绝不报 PASS）；
3. 版本系判据：S70 / JDG-06 / D-23 按当前态解读（出包在途豁免语义
   见 MEMORY §24/27）。

**集成红 ＋ 单树全绿 ⇒ 这是 T-09 跨流交互的新实例**（并行制新增的
失败类别），登记入 `ci/defect_types.py`，归因到「两树合起来的才有的
行为」，不许拆回单流糊弄。

### F · 串行清单（B 档）

§2 B 档四件（0514 / 0490 w05 / 0363 / j2_pypi_e2e）**全局串行**：

- 开跑前在群里（或向用户）喊一声「我要跑 B 档」；
- 跑完喊「B 档结束」；
- 两路同时想跑 ⇒ 后到者等。宁可慢，不许假红。

新套件若写真 url.json / 真端口 / 真进程，**开跑前先审计进 B 档**，
审计结论写进本文 §2。

### G · 披露与诚实

- 流简报（§5）是流对外的唯一凭据：没有流简报的流不许合并；
- 简报里必须写「没验什么」——没跑全套、环境限制、夹具自证缺境，
  全部明说。隐瞒的诚实缺口在集成时暴露，代价大十倍；
- 本制度的诚实边界见 §8，改制度先改边界。

## §4 开流程序（已实测通过，照抄即可）

```
# 0. 开工基线（动手前打，钩子提醒会随之消失）
cd /d/psl/poc/antinel-security
git tag pre-<批次名>-YYYYMMDD

# 1. 建流
git worktree add -b stream-b .worktrees/b

# 2. 树内自检（必须 True / []）
cd .worktrees/b
python -c "import host_shield; print(host_shield.self_check())"

# 3. 冒烟一套（绿了再开工）
python ci/delivery_gate.py --only 0372

# 4. 开工：只动流简报登记过的文件
#    （闸门常用姿势：--only <键,键> 子集验证；--affected 让机器推套件）

# 5. 收工拆流（DST-01 不拦，安全）
cd ..
git worktree remove .worktrees/b      # 合并后再拆，别急着拆
```

实测记录（2026-10-16，流 B）：基线 `pre-parallel-20261016`（52ca423）
⇒ worktree 建 ⇒ 自检 `(True, [])` ⇒ 0372 冒烟 22 绿/0 红 ⇒
主树闸门状态零污染。


## §6 合并裁决程序

1. 流提交到自己的分支（`stream-b`），贴流简报；
2. 集成者（主树那路，或用户指定）把分支合入 main **之前**，在集成树上：
   - `python ci/delivery_gate.py` 全量；
   - 负控双境逐项核；
   - 版本系判据按当前态解读；
3. 全绿 ⇒ 合入；合入后打版本/出包按既有五步（bump_version →
   workspace_facts 5 字段 → release.py → tag → 提交，见 MEMORY §26）；
4. 集成红 ⇒ 按 §3-E 分类归因：单流复发（回该流修）／跨流交互
   （T-09 新实例，登记后两路协同）；
5. 合并后才拆 worktree（§4 步骤 5）。

## §7 本轮分区与试点（2026-10-16）

| 流 | 载体 | 在修 | ID 号段 |
|----|------|------|---------|
| 流 A | 主树 main（对端 AI） | 对端自有清单（不干涉） | 既有号段 |
| 流 B | `.worktrees/b`（分支 stream-b） | **X-051 试点** | X-053..X-060 |

**试点 X-051（T-10 静默降级）**：0516 判据内层 `subprocess` timeout
(600s) ≥ 外层单套 timeout (900s)，环境慢被读成 `CRASH 超时 >900s`
（闸门实测单跑 15-16s 正常）。修复方向：**内层/外层超时分层**——
内层须显著小于外层（留足余量），内层超时走「环境问题 ⇒ raise Skip」
路径而不是 FAIL。

试点判据的并发安全性已审计：`ci/inbox_guards_0516.py` 夹具为
`tempfile.mkdtemp(prefix="g0516_fix_")`（:335），每进程唯一 ⇒ 两路
同跑不互踩。**修完必须自证负控会红**（产品变异下），D 类 fixture
换值同批自证（MEMORY §9 教训）。

渐进三级路线（不急）：
- **L1（现在）**：并行修 ＋ `--only` 子集验证 ＋ 串行集成全闸；
- **L2**：B 档串行调度固化（跑前喊话约定进工具）；
- **L3**：批量合并（多流积压后统一裁决窗口）。

## §8 诚实边界（本文没做到的）

1. **机器级审计未穷尽**：B 档清单靠读证识别，可能存在漏网套件。
   缓解：新套件开跑前先审计（F 规则）；真漏了，假红会告诉我们；
2. **两树全量对打未实测**：今天实测的是「流 B 单跑 0372＋自检」，
   **没有**「两路同时各跑全套 34 套」的实测记录。L1 阶段两路各跑
   子集、集成时全量，正好规避这一点；L3 之前必须先补这个实测；
3. **集成树全量闸门本身是单点**：不能并行化，全量 ~20-25 min 是
   本批节奏的下限；
4. **版本四件套天然串行**：两路都升版必打架，走 C 档纪律；
5. 本文是程序不是产品：它不进 psl/manifest，不参与哨兵签名——
   改它不需要重签，但也意味着它没有机器强制力，靠两路自觉。
