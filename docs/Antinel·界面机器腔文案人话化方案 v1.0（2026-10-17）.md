## §3 人话化映射表（单一真源，写侧＋读侧共用）

> **设计要点**：建立**一张映射表＋一个渲染函数**，写侧生成与读侧兜底**同取一份**
> ⇒ 不存在第二份口径（本仓最恨的漂移形状）。

### 3.1 术语映射（裸术语 → 人话）

| 机器串 | 人话 | 备注 |
|---|---|---|
| `manifest` | 「出厂登记」（首次出现）／「登记」 | 不带引号，不加英文 |
| `登记表` | 「登记」 | 与上同义合并 |
| `哈希` | 「指纹」 | 「文件指纹对不上」 |
| `state 文件` | 「防护设置文件」 | |
| `链记录` / `链上` | 「安全记录」 | append-only 链对用户＝不可改的账 |
| `基线` | 「布防时记下的样子」 | |
| `rollup` | 「汇总」 | 主要不渲染 |
| `net_mode` | （删，或写「出网闸」） | |
| `（#6）` | （删） | 内部编号 |
| `链 8位哈希` | **保留原名改称「核对号」＋不截断** | ★ 2026-10-17 创始人裁定追加（见 §3.4）：**链哈希必须保留**（「体现监理的严谨性」），并补一句大白话说明「核对号」干什么用；旧实现截成 10 位是**信息损失**，改为完整。 |
| `规则编号`（如 `AN-001`） | **保留 ＋ 加一句大白话** | ★ 同批裁定：编号保留（可追溯）、但在旁边补一句人话说明它是什么（「哪条防护规则拦下它的」）。 |
| `时间` | **保留** | ★ 同批裁定：「事件发生的时间等关键要肯定也要保留」。 |
| `subkind` | （不渲染） | 代码键 |

### 3.2 键值对 → 人话（写侧 reason 新式）

| 旧 | 新 |
|---|---|
| `监理不在（旧 pid=%s），由 %s 重新拉起（mode=%s）` | `监理刚才不在（进程号 %s 已结束），已由 %s 重新拉起（拉起方式：%s）。` |
| `监理死亡（旧 pid=%s）且拉起失败（cause=%s，mode=%s）——门闸无人值守` | `监理已停止（进程号 %s），重新拉起也没成功（触发方式：%s，失败环节：%s）——现在没人值守。` |
| `监理 pid=%s 的进程号已被复用…` | `旧监理的进程号 %s 被系统分给了别的程序——旧监理已停止，判定不在岗并重启。` |
| `state 文件 enabled=%s 与审计链最近状态（%s）不一致——以链为准。…` | `防护开关的实际值（%s）与安全记录里最后一次的值（%s）对不上——以记录为准。如非本人操作请检查；要改请走正规入口。` |
| `登记表与 manifest 不符（疑似运行期投毒）——按启动缓存执法：` | `登记的清单与出厂登记对不上（疑似运行期被投毒）——按启动时缓存的那份执行：` |
| `研发态：代码与登记表不符（改动未重建清单）——…` | `研发迭代中：运行代码与出厂登记对不上（改了代码还没重新登记）——这一版还没发出去，不是防线失守；监理照常在岗。` |

（其余逐条见 §5 落地清单）

### 3.3 `mode=` / `cause=` 的**值**也要人话

`mode=detached` / `cause=hook-parametric` / `self-check-failed: …` 的**值**是内部枚举 ⇒
加一张 `_MODE_TEXT` / `_CAUSE_TEXT` 映射：`detached`→「后台独立拉起」、
`hook-parametric`→「由钩子机制自动拉起」…… **未知值原样显示并括注**（fail-loud，
不编）。

### 3.4 ★ 创始人裁定：三样"技术指纹"必须保留（2026-10-17）

> 原方案倾向「精简掉技术细节」，创始人**明确否掉了这一倾向**，原话：
> 「**链哈希应该保留吧？体现监理的严谨性。规则编号肯定也保留，不过要加上一句
> 大白话说明。另外，事件发生的时间等关键要肯定也要保留，是吧？**」

| 项 | 裁定 | 落地口径 |
|---|---|---|
| **链哈希**（核对号） | **保留** | 不删、不截位（旧实现截 10 位 ＝ 信息损失，改为完整）；改称「核对号」并补一句人话说明它干什么用（事后核对这条记录没被改过）。 |
| **规则编号**（如 `AN-001`） | **保留 ＋ 加一句大白话** | 编号保留可追溯；旁边补「哪条防护规则拦下它的」，让不懂内部编号的人也知道这是什么。 |
| **事件时间** | **保留** | 时间戳原样保留（「等关键要肯定也要保留」）。 |

**这条裁定的方法论意义**：人话化**不是删信息**，是**把机器语言换成人的语言**。
「严谨性」与「可读性」不是取舍关系 —— 指纹／编号／时间**照旧全给**，
只是每个都给一句人话说明它是什么、干什么用。

**同一条纪律用在 FZ-004 上**：版本差从顶栏主行移走，但**版本号一个都没丢**
（挪到徽标悬停提示 ＋ 问号点开），见 §7 的 FZ-004 兑现说明。

## §6 诚实边界（不许装知道）

- **读侧免疫不是万能**：旧链记录里的 `detail` 是**整串**，`humanize` 只能做**词级替换**
  （`pid=123` → 「进程号 123」）；若旧记录整句结构都不同，只能做到「不刺眼」，做不到
  「像新写的一样顺」。**这一点必须如实说，不许承诺「旧记录也全新」**。
- **本方案不新增术语**：`manifest`→「出厂登记」是**替换**不是新增词条；若创始人希望
  「出厂登记」可点击解释，那是**新增术语＋新落点**（另一批，需单独确认）。
- **`_p_speak_audit.py` 是审计快照**：103 处里约 60 处是**代码键名/注释**（不渲染），
  真正上屏的约 40 处；本方案只治那 40 处。
- **词级替换会留接缝**：`mode=detached` 这类被术语表翻译后，句子里可能出现
  「由钩子机制自动触发重新拉起（方式后台独立拉起）」这种**语义准确但略重复**的
  读法 —— 比原来的 `hook-paramedic` 好读，但不是最优文笔。**不为此再加工**：
  再改就要动写侧句式，动写侧就要重签 manifest 并重跑全部判据，收益不抵风险。
