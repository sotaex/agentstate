## 1. 机制层：文案必须派生自结构（不是靠判据事后检查）

### 1.1 根因是结构，不是疏忽

旧写法（本批之前的账本页）：

```python
_lead = "下列四个数只数今天；……"          # ← 字面量，硬编码「四」
m = ('<div class="metrics">'
     '<div class="metric">…</div>'        # ← 四张卡，**手写 4 组** `%s`
     '<div class="metric">…</div>'
     '<div class="metric">…</div>'
     '<div class="metric">…</div>')
```

两者之间**没有任何引用关系** ⇒ 「改了卡片数忘改文案」不是疏忽，是**必然**。
事后判据（0490 的 T-04d）只能守账本页这一个点——日报页同样 4 张卡 +
口径文案，却没有对应判据。

### 1.2 修法：数量词从结构派生

```python
_cards = [("ledger_blocked", _v("ledger_blocked", 0)), …]     # 列表生成
m = '<div class="metrics">' + "".join(… for k, v in _cards) + "</div>"
_lead = "下列%s个数只数<b>今天</b>…" % _zh_num(len(_cards))     # 派生
```

新增 `_zh_num()`（数字 → 中文小写）——中文文案写「四个」比「4 个」自然，
派生需要这个转换。**结构一变，文案自动跟。**

### 1.3 升级为常驻判据 **S55 / N-S55**（全站，不只看账本页）

落在既有的量具自检套件（不占 A2 的常驻预算）。两条断言，扫**所有**定义了
`_view_*` 的顶层模块：

| 断言 | 卡什么 |
|---|---|
| ① | 渲染函数里不许出现**字面量形式的指向性数量词**（下列/以下/这 N 个·数·项·条·张·类）——必须带格式化占位符（即派生） |
| ② | 同一渲染函数内不许并存**两份**计数来源（`day_counts` / `load_days` / `summary`）——三问之三「头部 11 天 vs 月行 8 天」就是两份来源并存 |

### 1.4 ★ 「全站通用**正则**判据」此路不通——实测连翻三次车

这是本轮最值钱的教训。我先试的是写一条正则扫全站渲染产物，**三次都栽**：

| 尝试 | 翻车方式 |
|---|---|
| v1 宽扫 | 把 `<style>` 里的 CSS 注释和术语悬停文本当成页面正文 ⇒ **满屏假阳性** |
| v1 单位表 | 漏了「**数**」这个单位 ⇒ 正好漏掉本批那个 bug 的形态「下列四个**数**」 |
| v2 剥术语层 | 正则 `.*?</span>` 贪心跨区，把整段正文吃掉 ⇒ **连目标串都扫不到** |

另有**本质性假阳性，正则消不掉**：页面上有「以下 1 项」这类合法数量词，
它指向的不是卡片区。要判断「以下 N 项指向哪个结构」需要 DOM 位置关系。

⇒ 结论：**只做 AST 结构判据（窄而准），不做文本正则**。S55 因此扫源码结构，
不扫渲染产物。

### 1.5 分辨力实测（同尺换输入，纯内存变异，零文件改动）

| 喂入 | 期望 | 实得 |
|---|---|---|
| 原样产品文件 | 绿 | ✅ 绿 |
| 数量词改回字面量 | 红 | ✅ 红（点名 `_view_ledger:2133`） |
| 同一函数注入第二个计数来源 | 红 | ✅ 红（点名 `day_counts/load_days`） |

## 2. 无窗口自启：黑窗口的两个源头与根治

### 2.1 两个源头（不是一个）

| 窗口 | 源头 | 为什么有窗 |
|---|---|---|
| **常驻大黑窗** | 启动文件夹里的 `antinel-shield.cmd`（开机自启） | `.cmd` 由 cmd.exe/conhost 执行 ⇒ **必然**建控制台；且它**前台**跑常驻哨兵 ⇒ 窗口一直开着 |
| **一闪而过** | 桌面 `Antinel Antinel 监理.cmd`（双击入口） | 同样前台调 `python.exe`，一闪 |

用户机器实测：`schtasks` 被本机策略拦死 ⇒ `antinel enable` 走了**启动文件夹
回退**（`state.autostart == "startup-folder"`），所以 Startup 里是 `.cmd`。

### 2.2 三个候选方案与裁决

| 候选 | 裁决 | 理由 |
|---|---|---|
| `.cmd` 里改 `start /b` | **不够** | 能消掉"常驻"，**消不掉启动那一闪**——用户明确说「甚至不一闪而过」 |
| `.vbs` + `WScript.Shell.Run(…, 0, False)` | **弃用** | 实测宿主安全策略直接拦 `wscript.exe`（Windows LOLBin）；且一个**安全产品**拿被安全策略重点关照的脚本宿主当启动器，调性不合 |
| **`.lnk` → `pythonw.exe`** | **采纳** | explorer 直接 CreateProcess，**全程没有 conhost**；pythonw 是 GUI 子系统，**不创建控制台** ⇒ 真·零窗口 |

### 2.3 代价与兜底：pythonw 下 `sys.stdout` 是 `None`

换 pythonw 的第一个坑：它**没有控制台** ⇒ `sys.stdout`/`sys.stderr` 为 `None`
⇒ 产品里所有 `print(..., flush=True)` 会 `AttributeError` **崩掉常驻哨兵**。

**那比黑窗口严重得多**——用户以为有保护，实际没有。

⇒ 两个入口各加一个**无控制台守卫**（`host_shield._no_console_streams` /
`inbox_cli._no_console_streams`）：缺流时接到 `~/.antinel/logs/*.log`，
print 照旧可用（落到日志）。**只在缺流时才动手**，有控制台时行为完全不变。

实测（脱离控制台环境）：跑前 `console.log` 不存在 → 跑后有了输出
⇒ 守卫确实触发、且**没有窗口**。

### 2.4 产品改动清单（根因在仓库里，所以改代码而不手改用户环境）

| 文件 | 改动 |
|---|---|
| `host_shield.py` | ① `_no_console_streams()`；② `task_installed()` **同时认 `.lnk` 与 `.cmd`** |
| `inbox_cli.py` | `_no_console_streams()` |
| `antinel.py` | ① `_startup_folder_lnk()`；② `_pythonw_exe()`；③ `_create_startup_lnk()`（PowerShell + WScript.Shell COM 建快捷方式）；④ `_retire_old_startup_cmd()`（旧 `.cmd` **改名归档**）；⑤ enable 回退分支**优先 `.lnk`**，`.cmd` 降为 PowerShell 不可用时的兜底 |

**为什么 `task_installed()` 必须一起改**：它原先只认 `antinel-shield.cmd`
⇒ 换成 `.lnk` 后每次巡视都会记一条「自启缺失」——**而启动项明明就在**
（与本族 P12「文件系统事实优先」是同一个坑换了张脸）。

**为什么旧 `.cmd` 必须归档**：换了 `.lnk` 而旧 `.cmd` 还在 ⇒ 下次登录**两个
都跑**，多一个窗口（正是要消掉的那个）；哨兵 singleton 会拒掉第二个进程，
但**窗口已经闪过了**。归档＝改名（`.away-<时间戳>`），零删除纪律。

### 2.5 判据（+2 条，0353）

| 判据 | 断言 | 负控 |
|---|---|---|
| P12 自启在岗也认得无窗口快捷方式 | 启动项是 `.lnk` 时 `task_installed()` 必须说"在" | 两种自启物都不在 ⇒ 不许说"在" |
| P12 登录自启首选无窗口形式 | AST：`.lnk` 分支排在 `.cmd` **之前**；`_create_startup_lnk` 经 `_pythonw_exe()` 取解释器 | 把两分支顺序颠倒 ⇒ 必须红 |

### 2.6 实测（临时 APPDATA，不碰真启动文件夹）

```
① 建 .lnk            = True | 存在 = True
② 旧 .cmd 归档       = True | 原位置还在 = False | 归档物存在 = True
③ task_installed()   = True （True=认出来了）
结论：自启链路正确（.lnk 优先 + 旧 .cmd 已归档 + 认得在）
```

读回 `.lnk` 内容核对：

```
TARGET = C:\Users\…\.workbuddy-ai\binaries\python\versions\3.13.12\pythonw.exe
ARGS   = -I -S "…\host_shield.py" sentinel "…\antinel-security"
WORKDIR= D:\psl\poc\antinel-security
```

## 3. 需要创始人本人执行的一步（Agent 不许代做）

**产品自己的守卫 DST-04 会拦 Agent 写启动项**（「建立持久化机制……必须由你
本人确认后手动操作」）——这是**正确的安全设计**，本批**没有绕过它**。

所以换成无窗口自启的最后一步，需要你在终端跑一次（它是幂等的）：

```
python antinel.py host-shield enable
```

它会：把自启物从 `.cmd` 换成 `.lnk`（→ pythonw，无窗口），并把旧 `.cmd`
改名归档。跑完重启，那个常驻黑窗就没有了。

> 兜底说明：万一 PowerShell 在这台机器上不可用，它会**如实退回 `.cmd`**
> （有窗口，但哨兵照跑）——宁可看得见，不可没有保护。

桌面那个「一闪而过」的入口（`Antinel Antinel 监理.cmd`）是**手工创建**的、不在
产品逻辑里，需要另外换成一个指向 `pythonw.exe` 的快捷方式；等本条自启生效、
你确认效果后我再给具体做法（同样需要你本人操作）。

## 4. 顺带发现

- **负控的变异锚点不许依赖会被重构掉的字面量**：N-T04d 原先靠替换文案
  「下列四个数」造变异；产品改成派生后该字面量不存在 ⇒ 负控**静默失效**
  （它自己报了「负控自身失效，不算通过」，护栏起作用）。已把锚点移到
  **派生表达式**上。教训：锚在结构性表达式上更稳。
- 本批测试脚本两次被**产品自己的守卫**拦下（DST-01 拦删除、DST-04 拦启动项）
  —— 守卫是活的，这也反过来证明了它有效。
