## 1. 命名裁定

### 1.1 「值守台」：降级，逐出产品名

「值守台」描述的是一块屏幕——窗口标题、页面名、界面层。它是**功能描述**，不是**角色**；
用户听完不知道这是什么。处理方式：保留作界面名（控制台窗口标题照用），不再作为产品名。

### 1.2 「哨兵」：三处不合身

1. **语义只覆盖一半能力**。哨兵＝站岗、警戒、拦下；而产品的真实能力是「按口径把关、
   验收、留痕、责令整改」。只覆盖「拦下」，丢了最值钱的「按口径裁量＋留痕」；
2. **海外撞名**。Microsoft Sentinel 是云原生的 SIEM 爆品，同一个词在安全域已被占用；
3. **隐喻违和**。军事化哨兵意象与 B 端交付验收语境不匹配——买方要的是独立第三方把关，
   不是对抗性守卫。

### 1.3 「监理」：国内产品名（推荐形态 **Antinel 监理**）

三条理由：

1. **语义同构**：监理的核心动作（按口径把关、验收、留痕、有权叫停）与产品能力
   （闸门＝验收、账本＝台账、登记簿＝闭环）逐一对上；
2. **法域现成**：「信息系统监理师」是国家软考中级资格，社会认知就是
   「工程质量的第三方把关人」——买方不需要教育，且天然带 B 端信任；
3. **商标结构干净**：Antinel 是商标，「监理」是描述词，组合使用，各司其职。

### 1.4 海外：没有对应词，只能搬内核

调研结论：**「监理」是中国建设监理制度独创的职业角色，海外没有对等词根。**
同一职能靠合同定义，各法域叫法不同——

| 法域／体系 | 叫法 | 备注 |
|---|---|---|
| 英联邦 | Clerk of Works | 文化上最贴近，ICWCI 职业团体 |
| FIDIC／世行项目 | the Engineer | 代表雇主，裁定时保持中立 |
| 美国 | Owner's Engineer／Resident Engineer／Commissioning Agent | 甲方代表 |

四者共同内核只有四条：**独立第三方 · 代表业主 · 监督过程 · 验收留痕。**
所以海外命名不译「监理」，只搬内核。按此筛选：

| 候选 | 判断 |
|---|---|
| **Steward**（受托照管的人） | **推荐**：无头衔冲突、无军事隐喻、无撞名 |
| Custodian | 备选：偏「存」，监督过程的气味不足 |
| Auditor | 偏窄：只覆盖验收，不覆盖过程监督 |
| Supervisor | 禁用：与 HR 头衔撞车 |
| Engineer | 禁用：多法域受保护职业头衔 |
| Sentinel | 禁用：微软 SIEM 同名爆品 |
| Overseer | 禁用：英语圈负面历史联想 |

### 1.5 B 端还是 C 端的回答：不是二选一，是分层

产品线名 **Antinel 监理** 通吃；叙事按买家分层（见 §7）。
C 端用户不需要理解「监理」的制度全貌，只需要三个直觉——独立、按规矩、留痕——
而这三个直觉恰好是「监理」在中文里的日常词义。

## 2. AI 交付现场为什么天生需要监理（三方同构）

### 2.1 建筑工程为什么必须是三方

三方结构不是谁设计的，是三个条件逼出来的：① 业主不一定懂行、不可能全程在场；
② 承包方握有信息优势（业主看不见钢筋笼里到底几根）；③ 质量事故后果由业主乃至公众
承担。信息不对称 ＋ 后果外部化 ⇒ 制度必然长出第三方。且监理制度有三个精巧设计，
后文全部要用：**谁付薪**（拿业主的钱却必须履职中立）；**谁定标准**（不创造成套规范，
只执行与裁量）；**谁施工**（绝不碰施工——既当运动员又当裁判者不可能中立）。

### 2.2 AI 现场：三条件逐条复活，还多一条

| 工程条件 | AI 交付现场 |
|---|---|
| 业主读不动 | AI 产出体量超出人的审阅带宽——554 条判据、29 套件的仓，人肉 review 物理不可能 |
| 承包方握有信息优势 | 知道「怎么来的」的是模型；模型可以非常自信地说错——文本流畅度与事实正确度脱钩 |
| 后果外部化 | AI 写的代码、报告直接进生产；署名的是使用者，砸的是使用者 |
| **（新增第四条）** | **承包方不是人**：没有职业操守约束、没有饭碗风险、不会被行业禁入——传统靠「信誉」的制衡整个失效 |

⇒ 人（业主）、AI（承包方）都齐了，缺的就是第三方。**中立监理不是「可以有的功能」，
是三方结构成立后的刚性需求。**

### 2.3 软件的「独立」不靠薪资结构，靠机制

工程监理的独立性靠资质与法规；软件的独立性靠**防篡改机制**：守护链文件被
manifest 钉死、判定记录进防篡改账本、audit 留痕。法官不能被被告篡改——
这是同一句话的两种语言。

## 3. 中立三铁律（本产品的立身之本）

> 中立 ≠ 不站边。监理拿业主的薪水，永远站业主边。中立精确指两件事：
> 按既定口径裁量，不因任何压力晃动；以及绝不亲自施工。

落到产品上是三条红线：

1. **不生成内容**：不写报告、不改代码、不产出被监管对象。只判、记、叫停——
   既生产又验收的角色，在逻辑上不可能是中立的；
2. **判定只按既有口径**：同一套判据对免费用户与付费用户完全一致；
   不因付费与否改变判据、阈值、规则集或报告口径；
3. **判定与收费彻底解耦**：不按结果计费、不收通过费、不出售已验证标识；
   钱只从「写权威记录」与「聚合治理」两处来，且来路与判定结果无关
   （收入边界见 §8 与《A6 收入边界声明》）。

## 4. 最强反驳与三回应

**反驳**：「SLSA、来源证明、密码学 attestation 已经很中立了，还要角色干什么？」

回应：机制是监理的工具，不是监理本身。工具保证「规则被执行」，
保证不了三件事——三件都有本仓实测为证：

1. **口径会腐化，需要裁量主体**。判据会过期、会盲区、会「红得对但指错路」：
   实测某闸门判据给出的修复路径是空操作（跑完红项依旧）。发现问题的是人，不是规则；
2. **谁守守门的人**。守护必须分层自证：产品／量具／钩子／登记簿四层各有人守、
   或申报盲区。这就是「监理的监理」的制度化；
3. **责任要落在某处**。红灯亮起时需要一个不闪烁的口径对业主说「这条我没测出来」，
   而不是把不确定性翻译成绿色——本产品铁律第一条：测不出报夹具失效，绝不报 PASS。

## 5. 从 2B 到全民：三个结构变化

传统监理锁死在 2B，是因为它的成立条件只在工程项目里凑得齐（客单价撑得起持证工程师，
stakes 高到值得旁站留痕；C 端纠纷靠品牌、平台、消法解决，无三方结构）。
AI 领域三个结构变化，把监理的需求面从「项目数」变成「用户数」：

1. **承包方默认化**：每个写邮件、写报告、写代码的人都在使唤 AI。需求量 ≈ AI 用户数；
2. **信息不对称反而更深**：工程里业主至少能验收「墙平不平」；AI 产出里 C 端几乎验不了
   任何一层。工程质量问题看得见，AI 的质量问题看不见——**看不见的那个更需要监理**；
3. **署名责任外部化到每个人**：AI 代笔的信、报告、commit 都署使用者的名，
   出错砸的是使用者自己。

一条冷事实：C 端历史上**不为「安全」付钱**（杀毒免费化、密码管理器低渗透），
只为具体伤痛与即时确定感付钱。这决定 C 端叙事语言（见 §7、§10）。
C 端没有「基建部」可依赖，监督只能外化成产品——所以 C 端不是「变小了的 B 端」，
是形态被逼着变成产品。

## 6. 「AI 也需要监理」的改写与委托链

「AI 自身也需要监理」是拟人化，且是制度坑：AI 没有可被侵害的利益，
就没有可被监理保护的东西；一旦坐实「AI 可以是业主」，中立性的锚点
（对「人」负责）就松了。

准确表述两句：

1. **AI×AI 现场要求监理机器可读**——口径是代码，不是文件。两个 AI 各说各话是
   最大风险，所以监理的口径必须唯一且机器可执行（本产品「一个事实两套口径」禁令、
   术语唯一真源、机数调用点，本质上就是 AI×AI 时代的监理语言纪律）；
2. **委托人永远是人**——agent「雇」的监理，雇佣关系最终追溯到人。AI 是中间承包人，
   不是终极业主；所有验收责任，最终追溯到人。越强的 AI，越可能是被监理对象，
   而不是监理的客户。

对外禁用句：「AI 是业主」「AI 也需要监理」；可用句：
「AI 的每一次托付，都应当有据可查。」

## 7. 三种买家，一层内核

同一内核（独立 · 按口径 · 留痕），三种包装。**名字分层与买家分层同构。**

| 买家 | 付钱买什么 | 产品形态 | 对外语言 |
|---|---|---|---|
| **B 端机构** | 流程合规、问责链（等保／ISO／甲方验收） | 嵌交付流水线、台账、审计报告、权限到人 | 完整制度语言（监理全套） |
| **C 端个人** | 署名兜底、确定感（被 AI 翻过车的人） | 常驻、轻量、红灯即时报 | **伤痛叙事，不说三方制度** |
| **AI 协作链** | 可机读的验收凭据（SLA 化结论） | API、凭据签发、机读口径 | 不说「AI 是业主」，锚点是人 |

产品线名 **Antinel 监理** 通吃三个买家：B 端听到制度，C 端听到「按规矩、留痕」，
AI 链拿到机读凭据。

## 8. 收费结构与增长飞轮

### 8.1 C 端免费不是善意，是宪法义务

两个独立推导，任一成立结论不变：

1. **认识论**：向被引用方收费 ⇒ 裁判变当事人 ⇒ 裁决不再构成证据
   （ISO/IEC 17020「费用不得依赖检测结果」同款纪律）；
2. **经济学**：判定是**非竞争性**商品——被引用一万次也不减少 ⇒ 有效价格＝边际成本＝0，
   任何正价格都人为制造稀缺、缩小引用疆域。

⇒ 用户侧（C 端与被引用方）永久免费；可定价的只有**写权威记录**的无裁量执行
（登记／出证／对账，按笔，同价不问结果）与**聚合层**（跨机汇总、合规报告、SSO/RBAC、
私有化）。

### 8.2 三层结构

```
┌─────────────────────────────────────────────┐
│ C 端触角层 · Antinel 个人版                    │
│ ¥0 永不收费 · 功能不阉割 · 本地零网络           │
│ 产出：引用基数 · 回执传播 · 长尾验证劳动入口     │
└──────────────────┬──────────────────────────┘
                   │ 免费放量
┌──────────────────▼──────────────────────────┐
│ 判定核 · PSL 协议层                          │
│ 引用免费 · 口径开源 · 判定权独立               │
│ 产出：权威疆域（被引用一万次也不减少）          │
└──────────────────┬──────────────────────────┘
                   │ 认证收费（只此两处）
┌──────────────────▼──────────────────────────┐
│ 收费门：写操作（出证/登记/对账）＋ 聚合层        │
│ （团队/企业/私有化）                          │
│ 铁律：与判定结果无关 —— 现金流在此，养活慢壁垒   │
└─────────────────────────────────────────────┘
```

### 8.3 谷歌类比：只复制结构，不复制租位

- **可复制**：用户侧免费、回执即传播单元（引用一次＝扩散一次）、
  权威的放大器结构（零门槛引用 ⇒ 引用基数 ∝ 权威疆域）；
- **不可复制**：谷歌的租位是广告货架——那是**竞争性**注意力、移动时代的旧稀缺，
  正被 LLM 入口分食。**收租位必须收在新稀缺上：写权威记录。**
  用旧租位养活新层，是把命交给正在死的那一层。

### 8.4 C 端是放大器，是期权；现金流在 B 端

状态层对「写」收费比对「查」收费深一层 ⇒ C 端规模**不是**生存前提，
是权威疆域的放大器与赌注期权。按台收费的团队版／企业版／私有化是现金牛，
养活口径共识这个慢壁垒；C 端免费放量，买的是判定层终局的入场券。

### 8.5 增长指标

C 端的 KPI **不是注册用户数，是回执流通量／引用数**。
引用基数＝市场份额＝抵押品。用 DAU 逻辑做这一层，就是把层伪装成应用——
已有前车之鉴（应用伪装层的产品以入口优势硬切场景，无「凭什么是层」可答，终局关闭）。

## 9. 证伪信号（出现任一，本章重画）

1. **免费版靠数据／广告变现的压力测试失守一次** ⇒ 认识论支柱腐蚀开始，§8.1 结论撤回；
2. **C 端引用基数涨，但回执流通量不涨** ⇒ 放大器叙事失效：C 端只是用户、不是引用者，
   应退回行业俱乐部路线，收缩 B 端；
3. **C 端规模起量，但认证门长期没有 B 端客户接盘** ⇒ 形态赌对、胜负赌注仍未下注，
   现金流策略重估；
4. **主要厂商把判定位收进自家围墙且市场接受** ⇒ 中立层需求从墙缝退回墙内，
   §2 的三方结构在 C 端部分弱化（B 端问责链仍在）。

## 10. 对外话术（分买家，签发后启用）

### 10.1 通用三句（命名与定位）

- 一句话：**Antinel 监理——在 AI 替你干活的现场，替你按口径把关、留痕、叫停的独立第三方。**
- 对「这和哨兵／守护类工具有什么区别」：它们管「拦没拦」，我们管「**以谁为准、
  留没留痕、谁担责**」——这是监理和保安的区别。
- 对海外：**Antinel Steward — the independent party that judges your delivery
  by your own rules, and keeps the record.**

### 10.2 B 端（制度语言）

- 「等保／ISO／甲方验收要的不是又一个扫描器，是**问责链**：谁按什么口径判的、
  判据是什么版本、记录能不能重算、出事后谁签字。这四件我们全留痕。」
- 「我们不出具鉴定报告，不是检验检测机构；我们交付的是**可复算的证据链与判定台账**，
  结论与责任由你掌握——正因为不碰你的结论，我们的判定才敢给你当证据用。」

### 10.3 C 端（伤痛叙事，不说制度）

- 「AI 替你写的东西，署的是**你的名字**。代码合进主干之前、报告发出去之前、
  数据引用之前——它过没过口径，你看不见。Antinel 监理就是替你看的这一层：
  过了才放行，没过就拦下，每一笔都留痕可查。」
- 「免费版功能一样不少，判据全部开源可复算；**收费的是团队跨机汇总与私有化**，
  跟判定宽严无关——我们不可能因为谁付了钱就把红灯改成绿灯，那等于自己拆自己的台。」

### 10.4 AI 协作链（机读接口）

- 「给 agent 的验收结论是机读凭据：口径唯一、可重放、可对账；
  **委托人永远是人**——每一张凭据都能追溯到一个署名的人。」
