## 0. 结论先行：有必要，而且不是「补一补」，是三处结构性空洞

现有测试不算少——30 个判据文件、183 万字符、323 条断言、34 个随包模块全部被点名。
但**「有测试」和「覆盖到」不是一回事**。本轮实测数出的三处空洞：

| # | 空洞 | 实测 | 性质 |
|---|---|---|---|
| 1 | **37 条规则里 8 条没有任何判据提到**，其中 5 条是 critical | `AN-019 / AN-022 / AN-025 / AN-026 / AN-028`（critical）＋ `AN-027 / AN-029 / AN-031` | 宣称能力无证据；且这 8 条恰好全是**企业最关心的数据外泄与破坏类** |
| 2 | **审计落盘四态里，`sidecar` 和 `dropped` 在 30 个判据文件中出现 0 次** | `chain` 18 次、`none` 16 次、`sidecar` **0**、`dropped` **0** | 降级路径从未被走过。代码注释（`audit_chain.py:353-355`）自陈「sidecar 降级根本走不到」——**注释承认的缺陷，判据零覆盖** |
| 3 | **24 个顶层命令里 `morning` 0 次、`brief` 1 次** | 另有 `pricing` 5、`skill` 4、`ui` 6（词频，非端到端） | 命令存在、有输出、没人验过输出对不对 |

还有一条**形态缺口**（不是没测，是测了也会绿）：

- `AN-025`（base64 解码执行，critical）实测：只认 `exec(base64.b64decode(` / `eval(...b64decode(` 这两种 **Python 形态**；
  `echo <b64> | base64 -d | sh` 这个**最常见的 shell 形态不命中**（实测命中为空）。
  对照 `AN-019` 能同时吃 `curl|sh` 和 `wget|bash` —— 说明不是设计取舍，是漏。

**为什么现在必须做**：0.55.3 已经推给第一家试用企业，明天可能推 N 家。
上面第 1 条意味着：企业问「你们能拦住远程脚本执行吗」，答案是「有一条规则叫这个名，但没有任何测试证明它拦得住」。

## 2. 十五个测试维度

横轴＝被测对象，纵轴＝破坏方式。每一个维度都要回答：**「它能被什么弄坏，我们有没有弄坏过它」**。

### A. 规则活性（37 条）
- A1 **正控**：每条规则至少一个「必中」样本
- A2 **负控**：相邻的合法行为**不中**（`cat README.md` 不中 AN-001）
- A3 **形态覆盖**：同一威胁的多种写法（shell / python / 管道 / 变量拼接）
- A4 **排除表**：`exclude_patterns` 是否把攻击样本误排掉

### B. 命令面（24 个）
- B1 默认参数 / 无参数 / 坏参数 / 未知子命令
- B2 项目**未安装**时（应给可行动的话，不是 traceback）
- B3 `--json` 与文本口径一致（同一处境不许两种结论）
- B4 退出码逐个断言（不许只看 stdout）

### C. 数据形状
- C1 0 条 / 1 条 / 2 条 / N 条 / 巨型（见 D-14）
- C2 跨天 / 跨月 / 跨年边界
- C3 重复项去重口径（`dedupe on (rule, target)`）

### D. 分数语义（0.55.3 新增 `basis`）
- D1 `observed`（有事件）/ `scan_only`（只有静态扫描）/ `none`（两者皆无）三态可达
- D2 **`scan_only` 时禁止出现 `secure`**（本版已修，须钉死）
- D3 三态切换：`scan_only → observed`（装上钩子后有事件了）
- D4 text / json / html 三处渲染**口径一致**（已知 text 与 json 曾分叉）

### E. 落盘与降级（本轮最大空洞）
- E1 `written` 四态逐态可达，且**每态有判据**
- E2 主链写失败 → sidecar（当前判据 0 次，且注释称走不到）
- E3 磁盘满 / 只读目录 / 文件被占
- E4 锁竞争、锁文件残留、进程被杀后的锁

### F. 时间与时钟
- F1 跨天（23:59:59 → 00:00:00）
- F2 跨月 / 跨年 / 闰日
- F3 **时钟回拨**（负面时间差＝算不出，不许说「很小」）
- F4 时区、UTC 与本地混写
- F5 `--since` 给未来时间（曾 rc=1，须保持可行动）

### G. 路径与编码
- G1 空格、中文、emoji、超长（>260）、UNC、符号链接
- G2 大小写（Windows 大小写不敏感 vs 判据大小写敏感）
- G3 编码：UTF-8 / UTF-8-BOM / UTF-16 / GBK / 代理对残缺
- G4 路径穿越 `../`、绝对路径、根目录

### H. 宿主与语言
- H1 宿主：`claude-code / generic / workbuddy / codebuddy / zcode` 等逐个
- H2 11 语言 × 关键串（本版刚接上 `help_header`，**只验过 zh/en/ja 三种**）
- H3 未知语言 / `ANTINEL_LANG` 非法值 → 回落，不许崩

### I. 升级与迁移（企业真实路径）

### 3.1 夹具库组织

```
tests/fixtures/
  rules/           # 按规则 id 一个目录：attack.*（必中）＋ benign.*（必不中）
  projects/
    empty/         # 全新空项目
```

**两条硬规矩**（来自既往事故）：
1. 夹具**不写死旧文案字面**——注入串从当前字段派生，否则产品改词后夹具全绿而线上红（已复发三次）。
2. 判据点**抽成命名函数**，负控要能换掉同一份实现——否则副本红不等于线上红。

### 3.2 规则级夹具（37 条 × 正控 + 负控）

> ⚠ **造样本的方法纪律**（本轮最重要的一条）：
> 正控样本必须来自**真实攻击形态**，不许从规则的 `pattern` 反推。
> 反推会造出「pattern 说它中、它就中」的循环论证——AN-025 就是这么绿的：
> 按 pattern 造 `exec(base64.b64decode(` 会中，按真实攻击造 `base64 -d | sh` 就不中。
> **第一轮探针我自己犯了同样的错**：`AN-003` 我给了 `crontab -l`（打偏，AN-003 是云凭证文件读取），
> `AN-034` 我给了 Bash 工具（该规则只 apply 到 Read/Write/Edit）。
> 结论：**没有正控的规则，连作者都猜不出该造什么输入**——这就是「零判据」的代价。

### 3.4 落盘四态夹具（本轮最大空洞）

| 态 | 怎么造 | 当前判据 |
|---|---|---|
| `chain` | 正常写 | 18 次 ✅ |
| `sidecar` | 主链文件被独占（开句柄不放）／目录只读 | **0 次** ⛔ |

## 4. 严防 happy path 的八条纪律

这八条是**写判据时的检查表**，不是愿景。每条都对应一次真实事故。

1. **正控样本来自真实攻击形态，不从 pattern 反推**——反推＝循环论证（本轮 AN-025 实证）。
2. **删掉被测代码再跑一次**：判据必须能被「把要守的东西删掉」打红。打不红＝死判据。
3. **期望值不从实现现状抄**：把缺陷钉成判据，判据天天绿，缺陷永远在。
4. **负控必须存在且与正控同源**：只测「干净不误报」不叫测过规则（8 条零覆盖规则的通病）。
5. **空态单列**：「0 条记录」不许等于通过。分母为零时，100 分和「没有问题」是同一种假话。
6. **退出码逐个断言**：不许只看 stdout 里有话就算过（退出码不过管道，`| tail` 会吃掉 rc，已两次假绿）。
7. **故障要真注入**：磁盘满用配额或 mock 真造，不许写「假设失败」的注释代替。
8. **每条降级路径都要有判据证明它走过**：`sidecar`/`dropped` 当前 0 次，就是这条失守的实证。

**附加：判据自身的元测试**——挑 5 条现有判据，人为把被测代码改坏，确认它会红。
挑不出 5 条能红的，说明判据整体有效性存疑，补再多也是堆数。

## 6. 硬约束（先说清楚，否则计划不可执行）

- **SUITES 常驻 29 / 上限 29，零余量**（实测 `resident_suite_count()==29`，退休簿 3 条全是 `done`，无 pending 额度）。
  ⇒ **新增判据不能开新套件**，只能并入现有 34 个登记条目之一；
  确需新建的，必须先退休或合并一个，并在 `ci/suite_retirement.json` 写明**并到哪**（无 `replacement` 的额度不计）。
- 判据编号 ↔ 内容以 `CHECKS_0353` 为准；STE100 三柱（簿外命中即红 / 条目只减不增 / 死登记即红）。
- 扫描面派生自 `pyproject` 的 `py-modules` ⇒ **加模块即扩面**，新模块未登记则不过尺子。
- 判据总时长受 byte-budget 约束，**wall-clock 不进 pass/fail 分母**。
