# Antinel 收敛台账

> 2026-10-13 建立（创始人拍板）。**把「错误量在收敛」从感觉变成数字。**
> 在此之前，"有没有在收敛"只能靠翻交接件与提交历史去回忆 —— 那是散文，不是账。

## 三条纪律

1. **append-only**：只追加行，不改旧行（唯一的例外是把本批"待测"格子回填成实测值）。
2. **数字必须来自闸门实测**，不许估。每一项都要能在 `.psl/gate/last_run.json`、
   `ci/defect_types.py --report` 或某个提交的 `--stat` 里对上。
3. **"本轮新增红"必须写出来**。只记"修了几条"而不记"新长出几条"的账，
   天然会显得在收敛 —— 那是自欺（本仓铁律：查不出来 ≠ 查出来是好的）。

### 本轮实测（2026-10-13 · 效率升级）

**修的三处真缺陷**（都不是"顺手优化"，都是本轮实测撞出来的）：

1. **运行锁的判活被静默降级**（T-08）：`delivery_gate._pid_alive` 写成
   `except: return False`，而 `import audit_chain` 因 `sys.path` 没有仓根而**必然失败**
   ⇒ 判活恒为"死" ⇒ **活锁被判成陈旧锁**。
   在 Windows 上侥幸没偷成（占用方句柄没关、`os.replace` 撞共享冲突），
   **POSIX 上会真被偷走**。修法：仓根进 `sys.path` ＋ 判活改三态 ＋ 拿不准一律按占用。
2. **提交钩子部署漂移 6 天**（T-09）：`.git/hooks/pre-commit` 是 09-28 拷的
   （跑 `regression_gate`），仓内源 10-07 已升级为 `delivery_gate --quick`
   ⇒ 那个"一处入口"的强制点**实际是断的**，28 套快档判据这 6 天**一次没在提交时跑过**。
   修法：源改快道 ＋ 重新部署 ＋ **D-33 正面守**「部署件与仓内源逐字一致」。
3. **闸门自身文件不在任何 import 图里**：改 `ci/delivery_gate.py` ⇒ 影响面 **0 套**
   ⇒ 快道会认为"这次改动不需要复验任何东西"。修法：`_GATE_SELF_FILES`
   强制复验 `selfcheck`（且**不参与预算**）；`_touch_files` 不再把钩子脚本当非产品文件丢掉。

### 本轮实测（2026-10-13 · B3 口令不进 URL）

**缺陷**：主 URL `/?t=<口令>`、每个页签链接 `/?v=…&t=<口令>`、favicon/logo 的
`?t=<口令>` —— 口令进了浏览器历史、Referer、地址栏与截图；点一次按钮（303 重定向）
还会把它写回地址栏。

**修法（`inbox_server.py`）**：首字节带 `?t=` 的那次下发一枚
`HttpOnly; SameSite=Strict; Path=/` 的 cookie（`_COOKIE`），此后**所有**站内导航与
子资源都靠它；**14 处 href/src 摘掉 `t=`**（表单 hidden `t` 与 JS 的 POST body
保持不动 —— 它们不是 URL）。**旧 URL `/?t=…` 继续可用**（维八）。

**判据（`ci/inbox_guards_0490.py`）：W-06 ＋ N-W06（34 绿）**
- 四现场：① 四个视图渲染页里 `href`/`src` **零 `t=`**；② 旧 URL 仍 200；
  ③ cookie 能过守卫（真发 HTTP）；④ `Set-Cookie` 含 `HttpOnly`/`SameSite=Strict`/`Path=/`，
  且**无凭证请求 403 且出声**。
- 负控三变异（链接放回 `&t=` ／ `_guard` 不认 cookie ／ 去掉 `HttpOnly`）全部被抓到，
  且**逐条断言红的落点**。

**连带对照（改 URL 形状会打破既有判据 —— 实测撞出 5 处）**：
`0353:2399`／`0353:2462`（正则断言 pill 链接含 `&t=T`）、
`0490` 的 `N-W02`／`N-U08`／`N-U05`（变异锚点逐字取自被改的源码行）
⇒ 同步更新锚点/正则。**0353 复跑 62 绿 / 0 红**。

**全量交付闸门**：首跑 **29 绿 / 1 红** —— 红项是 `0460 S80 ★ 两票并且`，报
`build→None//`。单独复跑 0460 **17 绿 / 0 红**、直调 `deletion_permission` 得
`allow=True/vote1=ignored/vote2=regenerable` ⇒ **判据逻辑正确**，红只出现在**机器高负载**时
（`git rev-parse` 耗时 1.70s vs 正常 0.1s，子进程取不到信号）。**重跑全量闸门 30/30 全绿（rc=0）**。
⇒ 这是一条**机器天气型 flake**（判据依赖 git 子进程返回），已记入下方「未闭合实例」待办。

> ⚠️ **环境备注的后续（2026-10-13 晚）**：上一条"整机层面（进程创建／杀软实时扫描）"
> 已**定位并解决** —— 真凶是 **Windows Defender 实时保护**（`MsMpEng` 常驻 518 MB）。

### 本轮实测（2026-10-13 · C1 负控模板化两步）

**缺陷（T-03 量具自身有缺陷）**：负控（量具）**自己的**故障冒充产品红 ——
N-U13 把头部 mp4 形态加回时变异 args 少给一个 `M.STATE_VAR[st]`，变异渲染抛
`TypeError: not enough arguments for format string`。负控的职责是「证明**正判据**会红」，
结果它**自己先崩了** ⇒ 量具故障伪装成产品问题，人得读 traceback 才分辨得出。

**修法（`ci/inbox_guards_0490.py`）**：
- 新增 `_mut_render(src, tag, rel, **kw)` —— **两步法第一步**：「变异模块**能 import
  ＋ 最小渲染不抛**」；不过 ⇒ 返回「负控自身失效：…（量具故障，不是产品问题）」。
- **12 处**渲染型负控（N-U01/U03a/U03b/U04/U05/U06/U08/U10/U11/U13/U15、N-W02）
  从「`mut = _load(...)` ＋ `page = mut.render_page(...)`」合并成
  「`page, _why = _mut_render(...)` ＋ `if _why: return _why`」。

**判据（C-01 ＋ N-C-01，36 绿）**：
- **C-01**：用 **`ast`** 扫「负控块里还有没有**裸的** `.render_page(`」。
  ★ 为什么不用正则：正则会把**字符串字面量里**的 `mut.render_page(`（N-C-01 的变异
  文本里正有这一句）当成真调用 —— **首跑真咬到自己人**（2 红）。`ast` 只看真 Call 节点。

  再怀疑判据变慢；否则会把"机器慢"误读成"闸门坏了"。
