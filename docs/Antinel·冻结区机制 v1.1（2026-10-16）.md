## §1 定型如何发生（发动机）

**定型不是创始人宣告的，是机制捕捉的。** 这是本机制与「人手一份冻结
清单」的根本区别。

### 1.1 AI 主动问（四个时机）

| 时机 | 场景 |
|------|------|
| 批收尾 | 本批修订完成、闸门绿了，问「哪些改动值得定型」 |
| 正面评审后 | 创始人给出正面评价（「这样对了」等）后，问「这条定型吗」 |
| 流简报 | 流对外简报里附「建议定型清单」 |
| pre-touch | 动手前发现目标区域是近期刚改的，问「这段刚定过吗」 |

### 1.2 批准语言词表

创始人说以下任一句 ⇒ 该条定型：**通过／同意／就这样／定型／定了／
可以／OK／行**（口语即批准，不需要正式仪式）。

### 1.3 回报确认回路

AI 收到批准语言后必须回报：「收到，FZ-00x 记入冻结区（单元/契约）」
——**不许静默定型**：没有回报确认的批准不算定型，下次还要问。

### 1.4 铁律

- 未经问就冻结 ⇒ 冻结失效（未经确认的「定型」是 AI 自作主张，与病灶
  同源）；
- 批准词表只作**定型触发**，不作任何其他裁决依据。

## §2 登记簿 schema（ci/freeze_zones.json）

条目字段（簿内 note 字段即口径，随簿维护）：

| 字段 | 含义 |
|------|------|
| id | FZ-00x，簿内唯一（D-38 查重） |
| status | candidate（候选，不执法）／frozen（生效冻结，执法） |
| unit | source 类：`file.py` 或 `file.py::func`；output 类：契约说明串 |
| kind | source（源码哈希）／output（输出契约断言） |
| contract | 契约人话（是什么、为什么定、原话＋日期） |
| check | output 类：检查函数名（须在 `_FREEZE_OUTPUT_CHECKS` 已实现） |
| hash | source 类：冻结时的 sha256（AST 取函数段，不按行号） |
| frozen_at / decision | 冻结日期／定型原话＋批准日期 |
| retire_log | 退休记录 [{by, date, reason}] |
| blocked_on | 候选的卡点（待确认／待修复） |

## §3 两种粒度与选型规则

| kind | 适用 | 执法方式 | 选型规则 |
|------|------|----------|----------|
| source | 自包含渲染器/计算逻辑（函数字节即契约） | sha256 重算比对 | 单元自包含 ⇒ source（粒度到函数，**不整文件**） |
| output | 布局/文案/视觉契约（跨多函数） | 跑登记的 check 函数 | 契约跨函数或跨渲染 ⇒ output（check 名登记；**未实现的契约不许冻结**） |

★ source 取段用 AST（行号会随无关编辑位移——T-06 同型病）；取不到 ⇒
结构契约破坏，红（铁律 1）；
★ output 的 check 是实现函数的登记名；`_FREEZE_OUTPUT_CHECKS` 为空时
该 output 条目不可冻结（冻结未实现的契约＝让闸门守一条做不到的事，
只会假红或假绿）。
★ output 粒度的代价与补偿：契约从「函数字节」改为「输出关系」⇒ 常量
值不在冻结面（FZ-001 的 `#E8A33D` 可随规格调整），但 check 必须**有牙**
——常驻负控（§4.3 灯色探针）每次闸门运行验「回耦/回灰确被抓住」。

## §4 执法与退休

**执法（D-38）**：frozen 条目逐条执法，触碰即红（detail 附退休指引）；
candidate **不执法**——它们是「待修复/待确认」的管线，违例只登记不
阻断。登记簿缺失 ⇒ SKIP（判据未生效如实报，铁律 1）；frozen 缺
hash/check ⇒ 红（登记簿自身不一致，不静默放过）。

### 4.1 退休顺序（解禁回路）

```
① 登记新契约（怎么变、为什么变，写进新 FZ 条目或原条目新段）
② 退休旧条目（retire_log 追加 {by, date, reason}）
③ 改代码
④ 重新冻结（新契约生效，hash/check 填新值）
```

顺序反了（先改代码再退休）⇒ 闸门先红。**退休纪律是命门**：没有退休
通道的冻结是死锁（要么永远不能改，要么被绕过）；退休成本＝填一行
理由，这是合法演化的门票。

### 4.2 退休通道不变式（机器守，Phase B3）

顺序只是纪律，机器守的是它的两个**可判定面**
（`regression_gate._registry_invariant_problems`，纯函数、entries 由
调用方给 ⇒ 合成夹具可驱动）：

1. **retire_log 三字段齐全**：每条记录 by/date/reason 非空，缺一 ⇒ 红
   （半拉子退休不许蒙过——「填了日期忘了理由」与「没退休」同样
   是绕过）；
2. **不许裸降级**：曾冻结（frozen_at 在位）而今 status != "frozen"
   且 retire_log 为空 ⇒ 红。有 retire_log 记录＝合法退休，不红。

两条挡的是 D-38 逐条执法挡不住的那一半：**伪造一条完整退休记录**
（三字段齐全）后翻状态改代码——语义自洽、不变式全过。那条路由
§4.4 的字节级保护兜。

### 4.3 机械自证（常驻负控，每次闸门运行都跑）

- `_freeze_machinery_probe`：合成一条 frozen 条目两步验——① 哈希填
  **真值** ⇒ 执法必须**放过**；② 哈希填全零 ⇒ 执法必须**抓住**。
  任何一步不对 ⇒ 负控自身失效（红，铁律 4：不会红的闸门不是闸门）；
- `_freeze_invariants_probe`（Phase B3）：全合成夹具三步验退休通道
  不变式的两条腿都有牙——① 合法退休（三字段齐全）必须**无问题**
  （反方向：堵死合法通道同样是闸门失效）；② 缺 reason 必须红
  （方向断言 retire_log）；③ frozen_at＋candidate＋空 retire_log
  必须红（方向断言裸降级）。纯进程内字典、无外部输入面 ⇒ 无 SKIP
  通路（不存在「测不出」的输入）；
- `_lamp_color_machinery_probe`（Phase B2）：output 类 candidate 的
  check 有牙自证——FZ-001 违例只登记，但探针照跑：未变异必须过
  （不过⇒产品违例照红）、状态机回耦 `css(V.beamC)` 必须红、静态
  骨架回灰必须红。锚点未打中 ⇒「量具故障」诚实红。

### 4.4 登记簿自身的字节级保护（研发树专属名单，Phase B3）

登记簿自己也是可被改的文件（改它就能伪造退休）。外层守卫：
`host_shield._DEV_GUARDED_CHAIN_FILES = ("ci/freeze_zones.json",)`
——self_check 里**在场才校验**（fail-closed 同 0.36.4 纪律）：

- 研发树里它在（git 跟踪）⇒ 必须登记进 manifest 且字节相符；
  没登记 ⇒ 红；字节不符 ⇒ 红（§4.2 挡不住的伪造退休，这层哈希兜）；
- 出包产品里它**不在场**（`ci/` 不进 wheel——MANIFEST.in 无 ci/
  规则）⇒ 跳过，不误报。

★ 为什么必须「在场才校验」而不是直接进 `_GUARDED_CHAIN_FILES`：那份
随包发、在出包产品里被 self_check 遍历 ⇒ 清单里永远不会有 ci/ 条目
⇒ 恒红 ⇒ `spawn_sentinel()` 硬拦 ⇒ 监理在产品里拉不起来。
★ 已知时点（诚实边界）：发布构建会把主树 manifest 刷成纯 wheel 清单
⇒ 本条目被抹掉 ⇒ 发布后主树 self_check 红一条「没登记」——与 S70
同族的出包后已知态。修法：`python _tools_034/_resign_manifest.py
--adopt-dev`（补登名单从 host_shield import 不另抄；构建器永远不收
ci/ ⇒ 这是唯一出路）。下一轮开工时跑一次即恢复。

## §5 接法

### 5.1 与并行修订制度

冻结区＝**跨流共同契约层**：文件所有权（规则 A/C）管「别改别人的
文件」，冻结区管「谁的都不能动」——两层正交叠加。已立为并行修订
制度**规则 H**。

### 5.2 与 manifest

`psl/manifest.json` 哈希 129 个在册文件（含三大核心）⇒「发现变了」
有；但重签是例行 ⇒「这次改动该不该发生」无。冻结区补这个缺口：
manifest 回答「是不是这棵树的文件」，冻结区回答「该不该动」。
v1.1 起两层有了**交集**：登记簿自身进研发树专属保护名单（§4.4）
⇒ 登记簿的字节也被 manifest 钉住——manifest 钉「文件没变」，
冻结区钉「变了也不许（除非走退休）」+ 登记簿自身字节不许悄悄变。

### 5.3 不替代负控

负控（缺陷注入验证判据会红）与冻结区（已定型代码防擅改）互补：负控
证量具活着，冻结区证契约没被悄悄改。冻结区失效不会让负控失效，
反之亦然——两条独立防线。冻结区自己的量具（§4.3 三个探针）也按
此纪律自证。

## §7 诚实边界（本机制没做到的）

1. **粒度不能整文件**：冻结单位是函数段或输出契约；整文件冻结会把
   正常演进也判死（退休成本失控）⇒ 清单必须短；
2. **清单必须短**：冻结区是「已定型的少数」，不是「全部代码」——
   什么都能冻等于什么都不能冻（分辨力归零）；
3. **退休纪律是命门**：没有退休通道的冻结要么死锁要么被绕过；退休
   记录必须原话级（by/date/reason）——机器只守「齐全」与「不裸
   降级」（§4.2），**不守理由的真假**（伪造一条看似合理的完整记录
   仍能过不变式；那条路由 §4.4 字节哈希兜，再上是 git 审查层）；
4. **不替代负控**（§5.3）；
5. **output 类 check 依赖产品加载**：window_title_format／
   lamp_color_contract 都要加载 inbox_server 等产品模块 ⇒ 产品
   模块读不到时走 SKIP 通路（铁律 1，如实出声，不当绿）；
6. **出包后主树会红一条**（§4.4 已知态）：登记簿 manifest 登记被
   构建刷掉 ⇒ 下一轮开工跑 `--adopt-dev` 恢复。这是 manifest 作为
   「发布时快照」与研发态治理件的固有张力（T-02 同族），诚实
   记录而非隐藏；
7. **定型捕捉靠 AI 自觉执行**：主动问是机制要求，但不是机器强制
   （与并行制 §8.1 同调——创始人单裁判前提下，机器力用在确定性
   判据上；定型捕捉是对话层的事，回报回路是它的自证）。
