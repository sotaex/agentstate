## 第二件　`0372` N-S20（S13）

### S13.1　根因（实测，不是"负控失效"这么简单）

红因：`💥 N-S20 … NameError("name 'os' is not defined")` ——
注意是 **`💥`＋`%r`**（`main()` 1071–1072 的**非 AssertionError** 分支），
说明异常是**冒泡出 `n_s20()`** 的，不是判据主动 `_raise` 的。

**逐层实测**：

| 项 | 实测 |
|---|---|
| `inbox_cli.py` 行尾 | `git ls-files --eol` ⇒ **`i/lf w/lf`**（**纯 LF**，CRLF 假设**已证伪**） |
| anchor `"import os\nimport sys"` | **存在**（24/25 行连续） |
| 模块级使用 `os` | **第 33 行** `sys.path.insert(0, os.path.dirname(os.path.abspath(__file__)))` —— AST 实测，是唯一的模块级 `os` 使用 |
| `n_s20()` 里的 `exec(...)` | 在 **`try` 之外**（1033 行 vs 1035 行 try） |

⇒ 去掉 `import os` 后，模块在 **exec（导入）阶段第 33 行就崩**，
异常**没被 `_s20_run` 兜住**（它在 try 外）⇒ 冒泡 ⇒ 💥。

**★ 比"锚点失效"更硬的一层**：今天的 `inbox_cli.py` **模块级必须 import os**
（第 33 行），所以「整个模块拿掉 `import os`」这个变异形态**已经不可能存在**——
它一导入就死，跟 `cmd_daemon` 那条分支**毫无关系**。
⇒ 原负控**测的从来不是它声称测的东西**：它测的是「模块导入依赖 os」
（这对任何模块都平凡成立），**分辨力为零**。属「死判据」族的新变体：
**负控活着，但测错了对象。**

### S13.2　修法（保留原意、恢复分辨力）

变异形态改为**在函数作用域内屏蔽 `os`**：

```python
exec(compile(src, p, "exec"), mut.__dict__)     # ★ 用**原样**源码导入（不再去掉 import os）
mut.__dict__.pop("os", None)                    # ← MUTANT：把模块全局里的 os 拿掉
```

- 导入成功（第 33 行的 `os` 已用过）
- `cmd_daemon` 里 `os.getpid()`（309 行）⇒ 全局查找不到 ⇒ **NameError** ✓
- 精确模拟「C6 原貌」＝ 分支用了 `os` 但**该分支看不到** `os`
- **分辨力回来了**：若 309 行不再用 `os`（比如改用别的实现），变异后就不崩
  ⇒ 负控会报「负控失效」⇒ 尺子真的在守这条分支

**附带修**：`exec` 包进 `try/finally`，保证 `sys.modules["inbox_cli_ns20"]` 一定被清
（原代码 `sys.modules.pop` 在 `finally`，但 `exec` 在 try 外 ⇒ **exec 一崩就滞留**；
记忆里已有同族教训：「坏品种滞留比空判据更险」）。

**不动**：`S20` 正判据（它已绿，且是真跑真身分支）、`_s20_run` 的补丁与还原链。

**预期**：`0372` 由 **21 绿 / 1 红** → **22 绿 / 0 红**。

## 第三件　`glossary` 立「落点」词条（S14）—— **实测证伪，本件不做编码**

**背景**：v1.1 §S4 的 T-7′（A″）只改了**体检可见面**（页面 4 ＋ `host-scan` 8 ＝ 12 处），
门闸／brief／help 侧的「落点」**故意没动**（那裡是「待裁决的外传目标」，与体检侧不同义）。
v1.1 §10.5 把「在 glossary 立『落点』词条作桥梁」登记为遗留 —— **本件就是来处理它的**。

### S14.1　两条实测（不写盘，2026-10-18 01:0x）

| 实测 | 结果 |
|---|---|
| `ui_server.py` 里的 `chip(` 出现次数 | **0** —— 体检页**完全不用 glossary** |
| `GL.TERMS` 的键在 `ui_server.py` 里以字面量出现的 | **[]**（24 个键零命中） |
| 注入一个新词条后 `0353` 的 P13（`c_glossary_pages_are_clickable`） | **True → False** ⇒ **P13 当场红** |

⇒ **glossary 是监理页（`inbox_server` 四栏目 inbox/report/health/ledger）的术语表**，
体检页是**另一个渲染器**，与它零交集。
把体检侧的词「落点」加进去，**天然不对位**；而 P13 要求它必须在**那四个栏目**里出现落点。

### S14.2　为什么不做（三条，逐条可核对）

1. **落点不自然**：`落点` 在四个 inbox 栏目里**没有任何语境** ——
   它是体检页／`host-scan` 的词。要加，就只能在一个没提过它的页面**硬塞一个 chip**，
   这正是本项目反对的形状：**为了让判据绿而做产品妥协**
   （与「不许为了让 P13 绿而少加字段」是同一条纪律的两面）。
2. **要解决的问题实际不存在**：A″ 立桥梁的前提是「用户会在同一处撞见两个词」。
   实测：体检面已**全用「地方」**，门闸面仍用「落点」——
   它们是**不同的页面、不同的命令**，用户不会在同一处同时看到。
   而且改词之后反而**消除了同词异义**（原本「落点」在两处指两种东西）。
3. **替代方案更轻**：真要说明，写进体检页自己的文案即可
   （体检页不在 P13 范围内，改它不触动 `0353`），不必动术语表。

### S14.3　留给创始人拍板的三个选项

| 选项 | 做什么 | 代价 |
|---|---|---|
| **A（推荐，即现状）** | 什么都不做 | 无。两个词分处两个面，且已消除同词异义 |
| B | 加词条 ＋ 在 health 栏目硬塞 `chip("落点")` | 产品妥协：栏目里出现一个没有语境的词条 |
| C | 改 P13 口径，把体检页也纳入 `seen` | 要改判据 ＋ 体检页得先引入 `GL.chip`（现为 0） |

**本件结论**：**不做编码**，维持 A。上面三条实测与理由是交付物的一部分。
