## 3. 第一处：误拦

### 3.1 四层导览

| 层 | 干什么 | 状态 |
|---|---|---|
| 命令结构化 | 把命令认成结构体：哪些段是命令、哪些段只是赋值 | **今天就能做**（补丁已在内存中验证） |
| 目标提取 | 拿到真正要操作的目标路径 | 工具箱已有，接线即可 |
| 删除许可（记作 VCT） | 「能不能删」的两票裁决 | 需新增一次版本查询调用 |
| 兜底名单 | 删除许可取不到信号时的退路 | 现有名单降级而成 |

**顺序不能颠倒**：当天那条被拦的命令，目标是一个变量引用，字面路径不存在。没有结构化就拿不到目标，目标提取无从下手。

### 3.2 结构化：改动只有两处，且在内存中已验证

| # | 位置（以函数名为锚） | 改什么 |
|---|---|---|
| 1 | 命令钩子里的首词函数 | 前缀剥离正则的尾部由「必须有空白」扩展为「空白**或到行尾**」，并且**引号感知** |
| 2 | 命令钩子里的只读辨析函数，其逐段循环 | 某段剥完前缀后**没有剩余命令**（纯赋值段）⇒ 视为中性、跳过该段，不参与否决 |

必须引号感知：这是上一版第一版补丁被正例当场抓出来的地方。最终正则是值部分允许三种形态之一：**双引号串、单引号串、无空白串**。

**实测结果（5 正例加 7 反向对照，0 失败，2026-10-10）**

```
正例（修复后不再误拦）：当天被拦的那条、赋值加检索、赋带空格的值加查看、多变量加管道、基线纯检索
对照（修复后必须仍然拦）：赋值后接删除、命令替换里藏删除、检索结果转给删除动词、
                        前缀赋值加真删除、赋值后接连接符再加删除、查找命令自带删除参数、反引号里藏删除
```

**为什么不会被坏人利用**：命令替换、反引号这类「提及转成执行」的通道，早已被命令扫描阶段的危险标志挡住；真删除一旦出现在某一段，该段的动词仍不是只读动词，仍会否决整条。

**关于「能解掉多少」这句**（审 9 的产物）：上一版写「一处边界条件就能解掉绝大多数」，没给分母。本件的准确表述是：**在取证所用的 6 条日常命令样本里，命中此边界的有 2 条（2/6）**；这个数不能外推到「绝大多数」，它只证明这一类写法确实存在，且频繁出现在日常工作里。

### 3.3 一处行为变化（必须提前讲）

只读辨析也被「豁免逐段判定」用到。修复后，形如「变量赋值加分号再接删除」的写法会由「拦」变成「走豁免放行」。

这是**消除不一致**，不是放坏人：规则本就写明那个删除目标在豁免内，之前只是被那句赋值连带否掉了；且这次放行照常被记为豁免放行事件（该记录的写入位置核验时落在第 3168 行），**留痕不失**。

**硬纪律（不许被绕过）**

> 赋值建起来的变量表，只许用于「看得更清楚」（展示、提示、目标提取），**不许用于匹配豁免名单**。
> 否则等于把豁免名单的选择权交还给调用方。所以「赋值成构建目录再删它」这类写法仍然必须拦（实测确为拦）。

### 3.4 删除许可（创始人指定要补的那一条）

**允许删除，必须两票都同意。**

| 票 | 问的问题 | 怎么问（本机已实测） |
|---|---|---|
| 第一票 | 用户自己声明过「这是产物」吗 | 版本工具的忽略查询，带忽略索引参数，返回 0 表示是 |
| 第二票 | 它真的能再来一份吗 | 向上查找构建描述文件（多种生态各有一种） |

三处强化（上一版立的，本件保留，并补齐对照）：

1. **用忽略规则的反向语义，不用「追踪清单」**。追踪清单只覆盖已入库文件；最容易丢的是刚写完还没提交的新代码。改成「工作树内且未被声明为产物即受保护」，两者一起兜住。
2. **忽略声明优先于已追踪**。本仓实测：构建目录明明在忽略规则第 5 行，而索引里却返回 **61 个**被追踪文件。若反过来以已追踪优先，「清理构建目录」这个最日常的动作会立刻变成新的误拦。**用户手写的产物声明，语义强于一次手滑入库的历史事实。**
3. **与「可再生」做并且运算，不是或者运算**。配置文件之类常被写进忽略规则，但删了就真没了。第二票正是补这个洞。

### 3.5 判定顺序与四个退出口（审 7 的产物，新增）

```
命令进来
 一、命令结构化（分不出段，走出口甲：按现有保守口径处理）
 二、目标提取（取不到字面目标，走出口乙：变量展开后只用于展示，不用于豁免）
 三、是否删除类操作？（否，到此结束，不进入删除许可）
 四、删除许可两票（版本查询不可用、超时、路径在工作树外，走出口丙：交给兜底名单）
 五、兜底名单（也无信号，走出口丁：按现有默认拦，且留痕）
```

四个出口的**共同要求**：不许静默。走到哪一个出口，都要在记录里写明「为什么走到这里」。

### 3.6 落地时三个必踩的坑（已替你踩过）

| 坑 | 实测现象 | 必须这么做 |
|---|---|---|
| 已追踪路径不算被忽略 | 不带参数时返回 1，看着像「没被忽略」 | **必须带忽略索引参数** |
| 路径在工作树外 | 返回 **128** | 先定位工作树根；根外走出口丙，**不许把 128 当成「未被忽略」继续判** |
| 中文路径 | 默认输出把中文转成转义 | 关闭路径转义，且**不要靠输出里的路径串做比对**，只看返回码与有无输出行 |

**性能直接决定架构**：本机单次忽略查询约 **403.7 毫秒**、索引查询约 **323.0 毫秒**、批量 8 条约 **335.7 毫秒**。结论是**绝不能进热路径**；必须是「已判定为删除操作且已拿到目标」之后才调用，并带 **2 秒超时**，超时走出口丙且留痕。

### 3.7 兜底名单：降级，不删除

不再担任主判据，于是**它的长度不再是攻击面的增长点**；只在删除许可两票都取不到时才走它；走它兜底放行也必须留痕。

## 4. 第二处：状态写入（本轮重写的部分）

### 4.1 新证据：节流其实早就失效了

| 观测 | 读数 | 口径 |
|---|---|---|
| 状态文件里「上次复活尝试」的时效 | **停在 17.28 小时前**（等于哨兵启动时刻） | 单点读取，当天 08:0x |
| 同一时段内的实际拉起次数 | **当天 03:23 至 05:38 拉起 13 次** | 生产仓当日记录 |
| 同文件相邻间隔短于节流窗（300 秒） | **46.9%（68 / 145）** | 145 个间隔 |
| 其中落在节流边界（290 至 310 秒） | **1.4%（2/145）** | 同上 |
| 间隔中位数 | **341 秒** | 同上 |
| 同一秒的并发簇 | **1.2%（2 / 160）** | 160 条生产仓复活记录 |

**关键推论（标为「强证据，未终判」）**：节流失效**不是计时抖动**（落在边界的只有 1.4%（2 / 145）），也不是**严格并发**（同秒簇只有 1.2%（2 / 160））；它与「上次复活尝试的写入迟迟没有更新」同时出现，最可能是**这条记账根本没写进去，或被写回了旧值**。

两个候选机制，代码位置上都是真的，本轮没能把它俩分开（诚实登记见 §9）：

- **候选一，拒写**：唯一按字段更新的入口有三处调用点，**全部忽略返回值**。而该函数在「文件存在但读不到」时会返回假并拒绝写入 —— 这正是为了堵住历史上那次「状态被抹空」而加的保护。**一个保护在生效时，会让另一个保护（节流）静默失效。这是审 5 抓到的连带。**
- **候选二，被覆盖**：哨兵主循环在启动时读一次状态到内存，之后有 6 处整份写回，会把读到的旧值覆盖回去。

分开它需要一次连机观测（读状态文件的修改时间序列，并在拒写分支加一次留痕），本轮没做，不冒充结论。

### 4.2 因此定性要改一半

| v2.0 的定性 | v3.0 的更正 |
|---|---|
| 状态写入丢更新 | 丢更新是真的，但**主因不是多个进程同一瞬间抢**，而是**两种写法并存下的错开覆盖或静默拒写** |
| 主要靠锁解决 | **只靠锁不够**：锁解决同一瞬间，而这里的竞争窗口是**秒到分钟级错开**，5 至 60 秒这一档占 23.4%（34 / 145） |
| 无 | **必须先把 6 处整份写回收编进唯一入口，再谈锁** |

一句话：**上一版想的是给屋子加锁，而真正发生的是有人拿着一份旧蓝图把图纸抽屉塞回去了。**

### 4.3 重排后的三层

**甲，单一入口收编（新增，优先级最高）**

- 把哨兵主循环里那 **6 处**整份写回全部改为按字段更新；实在不能改的，必须在写前重新读一次再写；
- **按字段更新入口的返回值不再允许被忽略**：拒写就是拒写，必须留痕并让调用方知道 —— 这一步把静默变成出声；
- 配套：**给状态文件加一个版本号字段**，写前读到的版本号与写时不一致就重试一次，仍不一致就留痕退出（乐观锁）。这一步同时盖住两种候选：拒写会出声，覆盖会撞版本号。

**乙，接线既有锁（新增，成本最低）**

- 仓库里**已经有一套成熟的锁协议**：审计链的锁获取函数，**它的入参是任意路径**，不是写死给链文件用的。自带独占创建、身份牌、30 秒死锁回收、存活探测、令牌匹配释放、失败退化到旁路记录。
- 结论是**不要在哨兵路径上另写一份申请文件**，应当在「检查、记账、拉起」这一段外面把它接上，让**检查与记账合成一个临界区**。
- 收益：把「检查完了还没记账就去拉起」这条路径直接关掉。

**丙，名片租约（上一版已设计，本件保留并加两条）**

- 哨兵自写在岗名片，路径带自己的进程号，**不共享就不需要保护**；
- 判死亡必须**同时比对启动时刻**（防进程号复用的既有纪律）；
- 扫描时顺手把已死且陈旧的名片**改名让开**（零删除纪律），否则长期运行会无限累积；
- 敏感字段低频写：**写临时文件、原子替换、读回比对**（前者保读者，后者保写者，缺一不可）。

### 4.4 与上一版的一处裁定差异（要不要验进程号）

上一版的立场是「不要验进程号，只看修改时间」，理由是**进程号是对进程的描述，不是进程本身**。

**本件保留这个结论的判据部分**，但要写出它现在的具体含义：

- **如果要新建一套申请文件**，按上一版：只看修改时间，不验进程号；
- **本件推荐的是乙层接线既有锁**，那就**继承现有锁的语义**（含其超时后的回收作为最后一招）。理由有三：它已经跑了好几个版本并被实测过；它只在超时且持有者确实消失时才接管，属于兜底而非常规路径；为一个今天才写的新组件重新设计一套可靠性语义，收益为负。

**一句话裁定：不另写新锁就不必重拟语义；只有另写，才需要上一版那条纪律。**

## 5. 第三处：告警疲劳（本轮新增，从数据里长出来的）

上一版没有这一处。这轮的读数逼出它：

| 观测 | 读数（带分母） |
|---|---|
| 提醒与拦截之比 | **16,797 比 2,403，约七比一** |
| 单条路径疑似规则在提醒中的占比 | **73.5%（12,350 / 16,797）** |
| 篡改类记录里疑似真投毒的占比 | **7.5%（12 / 160）**；其余为自研自检不符 59 条、布防位不一致 73 条、其它 16 条 |

三条结论：

1. **每拦 1 次就撒 7 次提醒**，而其中近四分之三来自**一条规则**。疲劳不是人手不够，是**结构性的**。
2. **「篡改」这个词把自家迭代和疑似投毒记成了同一种东西**（百分之五对百分之九十五），真信号被稀释成二十分之一。
3. 于是**治理对象是告警的配额与分级，不是规则的增减**。

做法（三步，都不需要动规则表）：

| 步 | 内容 |
|---|---|
| 一 | 给**单条规则**设提醒预算（滚动窗口内的配额），超预算自动合并成一条汇总、**保留原始条数**，并在窗口结束时补记；不静默丢弃 |
| 二 | 篡改类分通道：自研迭代导致的与疑似投毒导致的走不同类型与不同级别，界面上不共用一盏灯 |
| 三 | 界面不许出现无分母的告警数 —— 凡显示告警，必同时给出窗口与分母 |

## 6. 从三十六万余条数据里总结的教训（八条）

| 教 | 数据 | 教训与可落地改进 |
|---|---|---|
| 1 | 46.9%（68 / 145）间隔短于节流窗，而落在节流边界的只有 1.4%（2/145） | **不是抖动，是失效**。凡限额类保护，必须自己能报告「我今天生效了吗」—— 否则失效时看起来跟正常一样 |
| 2 | 复活由自家钩子触发占 89.4%（143 / 160），人工触发仅 15 条 | 排除了外部攻击与有人反复折腾两种叙事。**自触发的维护动作必须自限**：连续若干次自愈后改为报警，而不是继续自愈 |
| 3 | 复活理由里写旧进程号为空占 56.9%（91 / 160） | 共享槽被清空或被覆盖是**事实**，不是推理，支持甲乙丙三层改造的必要性 |
| 4 | 同秒并发簇 1.2%（2 / 160），五到六十秒错开 23.4%（34 / 145） | **竞争窗口跨时间，不跨瞬间**，只做互斥锁不够，要有租约有效期 |
| 5 | 提醒与拦截约七比一，单条规则独占 73.5%（12,350 / 16,797） | 见 §5：按规则设预算，不全局放松 |
| 6 | 篡改类中疑似真投毒仅 7.5%（12 / 160） | 自家迭代与攻击必须分通道记名，否则等级体系被稀释 |
| 7 | 注释里已三次记录修好一处弄坏另一处，本轮是第四次（拒写打了节流） | 这是系统性风险不是运气，每次改动必须配「它没弄坏别的」的反向对照才算改完 |
| 8 | 自家硬化套件的实验数据与生产数据同池 | **两类数据必须可分**，否则任何跨目录的时间序列统计都是假的（本轮第一版就踩了，改同文件口径重算） |

## 7. 验收矩阵（每条必须配会红的反向对照）

| 层 | 正判据 | 反向对照 |
|---|---|---|
| 结构化 | 赋值加只读命令，不再因结构丢资格 | 摘掉纯赋值段视为中性的处理，至少两条正例必须重新变红（上一版实际发生过） |
| 结构化安全性 | 无 | 赋值后接删除、命令替换里藏删除、检索结果转给删除动词，必须仍然拦 |
| 变量表纪律 | 展开后只用于展示 | 把展开值拿去匹配豁免，必须红 |
| 删除许可第一票 | 构建输出目录，声明成立 | 去掉忽略索引参数必须红（本仓构建目录当场翻面） |
| 删除许可第二票 | 有构建描述文件即可再生 | 临时目录里没有构建描述，必须判不可再生 |
| 删除许可边界 | 工作树外路径走出口丙 | 把返回 128 当成未被忽略，必须红 |
| 删除许可中文路径 | 能得出正确返回码 | 依赖输出字符串做比对，必须红 |
| 甲，单一入口 | 6 处整份写回全部改为按字段更新 | 恢复任一处，并发下必须能观测到字段被回滚 |
| 甲，拒写出声 | 按字段更新返回假，必须有留痕 | 忽略返回值（现状）必须红，现在这里是绿的，那正是缺陷 |
| 乙，接线既有锁 | 多进程并发只有一个赢家 | 改回先读后写两步，必须重新出现多个赢家 |
| 丙，原子替换 | 并发读永远读不到半截内容 | 去掉原子替换直接写，并发读必须能抓到残缺 |
| 丙，名片 | 一张活着且新鲜的名片判在岗 | 伪造进程号已死但心跳新鲜，必须判不在岗 |
| 告警预算 | 超预算合并且保留原始条数 | 超预算就静默丢弃，必须红 |

**并发部分不许用协程模拟**，必须起真进程去抢 —— 本机这 46.9%（68 / 145）的短间隔就是现成实绩，这类缺陷用模拟并发测不出来。
