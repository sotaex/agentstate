## 0. 总结论

规格 v1.0 的**事实层基本可靠**：全部代码声明（PRIORITY／base_state 七姿态／`_window_open`／
`TAMPER_CHANNEL_KINDS`／`_tamper_channel_light`／`_GRANARY_ON_DUTY`／`AUTO_HANDLED_KINDS` 6 成员／
`LEVEL_OF_KIND` 唯一 L2 kind／`level_of_record` 降档）、两条创始人裁定引文（0.35.3／0.39.0）、
S10/S15/S16/S17 的判据内容与行号引用，**逐字核对无误**；探针逻辑行两次重跑零抖动、
与原日志逐字一致。

**但它的「修法决策层」有 2 条 Sev-0**：规格给创始人的影响面表（§6.2）与「独立小修」
判断（§6.3-3）**各漏了一条会当场转红的判据**，且漏的恰好是两条「守已修缺陷」的回归守卫
（0490 W-03 守托盘/Web 两套口径；0470 S93 守篡改分通道）。若照 v1.0 直接执行修法，
执行轮会连撞红灯，而红灯的原因（判据钉的正是要改的行为）规格里一个字都没写。

另有 **4 条 Sev-1**（真值表有洞、Ls 的 credits 路径整个缺失、kind 枚举不全、术语表锚点漏引）、
**8 条 Sev-2**（自撰引文、light() 描述不精确、探针缺阴性对照、时点性未注等）。
全部 14 条扣分点带证据列于 §2；5 条「疑似缺口经反证不成立」列于 §3（证明审核确实在找反例）；
v1.1 的修订逐条对应列于 §4。

## 2. 扣分点清单（14 条，按 Sev 分级；每条带证据）

### Sev-0（照文档动手会当场出错）—— 2 条

#### S-01 口径 B 的影响面漏了 0490 W-03：规格说只动 0353/0380，实测还红一条回归守卫

- **规格原文**（§6.2 三策边界影响对照表）：只列 `0353 c_light_only_owner_actions`、`0380 S10/S15/S11` 三档。
- **实测**（`_p_caliberb_impact.py`，日志 `output/_p_caliberb_impact.log`）：
  把 `M.current_state` 换为口径 B 语义后真跑 0490 的 `_w03_assert()`——
  **「账内 L2：页面状态词应 '拦截'，实得 '值守中' —— current_state 口径变了」**；
  还原后回绿（探针本身坏的可能已排除）。
- **为什么是 Sev-0**：W-03 不是普通断言，它是 **A2「托盘与 Web 两套口径」这个已修缺陷的回归守卫**
  （0490:1170-1176 注释原文可查），用例②钉的正是「guarding + 未读 tool_call_blocked ⇒ 拦截」。
  规格让人以为改灯态只需重签 S15，实际还要动一条守已修缺陷的闸门——
  **而重签它等于削弱一条回归守卫，这个代价规格没告诉创始人**。
- **缺的到底是什么**：§6.2 缺一行「0490 W-03（托盘/Web 同源守卫）」；§7 拍板项缺一个
  「W-03 用例②是否随口径 B 同批重签」的显式决策。

#### S-02 「B3 修法是独立小修」判断错误：0470 S93 与 N-S93b 实测当场转红

- **规格原文**（§6.3-3）：「`_tamper_channel_light` 抬 dev 增加『姿态为 dev』条件……
  这是独立小修，可与任一策同批。」
- **实测**（`_p_b3_impact.py`）：变异为该语义后——
  `s93` 转红：「自研迭代与未自愈投毒共用一盏灯（都是 L0）」（0470:343-344 的第三断言）；
  `n_s93b` 转红：「夹具不成立：真实现下自研迭代就没走 dev 灯（L0）」（0470:400-404）。
  修法前／还原后两条全绿。
- **机理**：S93 与其负控的夹具**全部用 `posture="guarding"`**（0470:337、375-384、400-402），
  即它们钉死的正是规格称作「缺陷」的 B3 行为。加姿态条件后 guarding+dev_drift 从 dev 变 L0，
  与 guarding+未自愈投毒（R0 级不抬灯 ⇒ L0）同灯 ⇒ 第三断言失败。
- **缺的到底是什么**：§6.3-3 缺「S93 的 dev 夹具须同批改 posture=dev、N-S93b 夹具前提同步」；
  §7 缺对应拍板项。**注意这与口径 B 是两个独立影响**（Z-04 已证：口径 B 单独跑 S93 仍绿），
  必须分开记账、分开签字。

### Sev-1（实现者必须自选，或可追溯到停发路径）—— 4 条

#### S-03 真值表有洞：「界限 100% 清晰」的操作定义没被自己的表满足

- 规格 §0 定义「对**每一种**输入组合有且只有一个灯态」，§4 却只列 13+7 行。
- **实测补测**（`_p_truth_gaps.py`，日志 `output/_p_truth_gaps.log`）：姿态×粮 16 个基础组合里
  **缺 6 行**：`warn+低⇒R0`、`interrupted+低⇒L1`、`unknown+低⇒L1`、`dev+低⇒Ls`、
  `集合外+低⇒L1`、`off+低⇒L0`；事件×粮交叉**缺**：`guarding+L2+低粮⇒Ls`（PRIORITY 4>3）、
  `guarding+L1+低粮⇒Ls`。
- 其中 `off+低粮⇒L0` **判据层早就钉着**（0380 S13:229-231「没在岗不该报缺粮」）——
  规格的表既没抄它也没引它，「每一行可被负控证伪」的声明因此不实。
- **缺的到底是什么**：16 行基础真值表＋事件维规则层＋**输入签名与完备性论证**
  （`current_state` 实际只读 `posture`、`granary["state"]`、逐记录的 `(state, ts, level, kind)`——
  只要把表按这些维度组织，「完备」才是可证言的，否则只是「我想到的组合」）。

#### S-04 Ls 的 credits 路径整个缺失：第二个「桶灯分裂」无记载

- 规格 §1 把 Ls 定义成单一来源（「粮快见底，低于一周口粮」），全文不提 `credits_low`。
- **事实**：`LEVEL_OF_KIND["credits_low"]="Ls"`（inbox_model.py:99）、
  `TITLE_OF_KIND["credits_low"]="缺粮：积分余额偏低"`（:126）、
  `STATE_Ls` 注释写「额度/预算阈值告警」（:922）——而 `granary.py` 实测是**哨兵口粮**
  （1 粮＝在岗 1 小时、阈值 168＝7 天，granary.py:17/60-69），且其 docstring 明说
  「不是『我花了多少钱』」。**「积分余额偏低」这个标题与口粮口径存在张力**，三者口径不一。
- **实测**（`_p_truth_gaps.py` T3）：构造一条 credits_low ⇒ `level=Ls`、`needs_owner=True`、
  `has_consequence=True`、**桶＝action**、**灯＝L0**、而 `light()` 合并读＝**Ls**。
  即：若该 kind 投产，收件箱「要处理 1 条」与灯「值守中」并列——与 B5（zone 失败）
  **同型的第二例**，规格只记了第一例。
- 附带：`credits_low` 当前**无生产者**（全仓仅两张表登记，grep 实证）——是前向登记，
  但规格作为「切换逻辑」必须写「投产时会怎样」。
- **缺的到底是什么**：§1 Ls 行的第二来源、§5 的 P6 同型第二条、以及一条给产品的问题登记
  （「缺粮：积分余额偏低」标题与口粮口径是否要分词）。

#### S-05 `AUTO_HANDLED_KINDS` 枚举不全（6 成员列 4）＋ frozenset 未注

- 规格 §5 P1 写「L1 的四个 kind（revived / changed / dev_drift / zone_locked 成功）」，
  实际黑名单 **6 个成员**（inbox_model.py:189-199）：漏 `host_shield_lock_held`
  （门闸持锁留痕——它在黑名单但**不在** `LEVEL_OF_KIND`，属未投影 kind 的前向登记；
  若投产会走 `level_of()` 的响亮抛错，不会静默降级）。
- §6.3-2 的 monkeypatch 方案没说 `AUTO_HANDLED_KINDS` 是 **frozenset**（不可原地增删）；
  已实测 `needs_owner` 调用时读模块全局（inbox_model.py:251）⇒ **整体替换模块属性可行**，
  但规格应写明这一点，否则执行轮可能写出 `M.AUTO_HANDLED_KINDS.discard(...)` 直接抛异常。

#### S-06 术语表锚点漏引 S17/S18：照 §9 改词条可能当场打红

- 规格 §9 说修复轮要同批改「术语表 light 词条」，但没引 **0380 S17**
  （钉 `_GL_MUST = ("失守、缺粮只认此刻", "拦截／注意")`、禁 `_GL_FORBID = ("两个读数", …)`，
  0380:416-417）与 **S18**（`guard_posture()` docstring 口径，禁「存疑/查不到」）。
- 现词条（glossary.py:158-167）恰好含两个必含短语 ⇒ 现在绿；任何「顺手改写」
  都可能摘掉它们。规格作为修法指令，必须把这两条判据写进影响面。
